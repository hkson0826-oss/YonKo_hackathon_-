# 깃발 대항전: 규칙과 제출 절차

확인일: 2026-09-27. 저장소의 규칙서 PDF, 공개 규칙 Markdown, 배포 엔진, 밸런스 설정, 실행 제한을 대조했다. 게임 코드의 원본 커밋은 `88a77d888a1562e52ca2b21b2363d52bb8ce307c`로 배포 문서에 기재되어 있다. 실제 대회 사이트에서 이후 공지가 바뀌면 그 내용을 다시 확인해야 한다.

**같은 날 22시대 추가 확인:** 로그인된 공식 사이트에서 최종 대진·순위·마감·보고서·실행 제한을 확인했다. 최신 운영 정보는 [사이트 운영과 보정 점수](10-사이트운영과보정점수.md)를 따른다. 아래의 로컬 문서 출처와 웹 확인 범위를 구분한다.

## 1. 먼저 읽을 결론

- 이 게임의 목적은 **160턴 종료 시 건물 점수에서 앞서는 것**이다. 병력 수나 누적 점수는 우선 목표가 아니다.
- 양 팀이 동시에 명령을 낸다. 적이 현재 있는 칸과 다음 턴 도착하는 칸은 다를 수 있다.
- 상대의 모든 병력과 자원이 공개된다. 정찰병이 없어도 적의 위치는 보인다.
- 깃발병이 떠나도 건물 소유권은 유지된다. 모든 건물에 깃발병을 상주시킬 필요가 없다.
- 일반 턴 300ms, 첫 턴 3초. 제출은 소스 ZIP이고 실행 환경은 CPU 전용이다.
- **임의 데이터·학습 가중치·실행 파일 제출은 금지**되어 있다. GPU 사용 가능 여부와 별개로 최종 제출 설계에 적용되는 제약이다.

근거: [공개 규칙서](../yk-development-tools/docs/rulebook.md), [실행 제한](../yk-development-tools/bots/dist/starter/limits.json), [플랫폼 운영](../yk-development-tools/docs/PLATFORM_OPERATIONS.md).

## 2. 대회 운영과 확인되지 않은 사항

대학 공식 공지에는 대회 기간이 **9월 27일~10월 1일**, 발표·시상이 10월 6일로 안내되어 있다. 팀은 2~3명이며 대상을 포함해 총 7개 팀을 시상한다. 이 공지는 참가 안내이고 회차별 최종 제출 시각이나 리더보드 계산식 전체를 제공하지 않는다. [연세대학교 공식 공지](https://computing.yonsei.ac.kr/bbs/board.php?bo_table=sub4_4&wr_id=266)

로컬 배포 문서에서 확인한 운영 규칙:

| 항목 | 내용 |
|---|---|
| 회차에 사용되는 코드 | 마감까지 업로드를 끝내고 선택한 코드 |
| 검사 중 코드 선택 | 가능하지만 검사 실패 시 다른 코드로 자동 대체하지 않음 |
| 연습 | 하·중·상 중 하나, 공개 시드 0~9, 소속 진영 고정, 10경기 |
| 사전교육 수료 | 중 난도 6승 이상, 무승부는 승리에 포함하지 않음 |
| 작업 요청 | 진행 중인 제출·연습 작업을 끝낸 뒤 같은 종류의 다음 작업 요청 |
| 문의 | 대회 사이트 채널톡 |

사용자는 제출 횟수가 무제한이고 사이트에서 테스트할 수 있다고 확인했다. 업로드와 제출 선택은 사용자가 직접 한다.

**후속 확인:** 회차별 마감, 최종 대진·순위 기준, 보고서와 운영 안내는 [공식 사이트 조사](10-사이트운영과보정점수.md)에서 확인했다. 개발 리더보드의 정확한 보정 산식과 공식 맵 시드는 확인하지 못했다. 위 공개 시드 0~9는 로컬 배포 문서의 안내이며 서버의 실제 시드와 동일하다고 검증한 값은 아니다. 로컬 `example_lv2.py`와 서버 “중” 난도 봇의 동일성도 미확인이다.

## 3. 맵

| 항목 | 규칙 |
|---|---|
| 크기 | 15×15 |
| 좌표 | x는 오른쪽으로 증가, y는 아래로 증가, 모두 0~14 |
| 방향 | U=(0,-1), D=(0,+1), L=(-1,0), R=(+1,0) |
| 지형 | `.` 평지, `#` 장애물, `B` 건물, `H` 본진 |
| 통행 | 장애물만 통행 불가. 건물·본진은 통행 가능 |
| 본진 | Y는 신촌, K는 안암. 점령·파괴 불가 |
| 대칭 | `(x,y) ↔ (14-x,14-y)`의 180도 점대칭 |
| 본진 간 거리 | 맨해튼 거리 최소 12 |
| 장애물 | 점대칭 10쌍, 20칸. 모든 건물과 본진은 서로 도달 가능 |
| 재현성 | 같은 시드에서 같은 맵 |

건물은 본진을 제외하고 17개다.

- 중앙광장 1개: `(7,7)`, 항상 3점.
- 신촌·안암 각각 5개: 학생회관, 도서관, 공학관, 병원, 역. 각 1~2점.
- 중앙 6개: 역 2개, 방송국 2개, 보급소 2개. 각 2~4점. 중앙 건물의 y는 2~12.
- 대칭인 건물 두 개의 종류와 점수는 같다.

총점은 `3 + 2×(8개 대칭쌍의 점수 합)`이므로 항상 홀수다. 하지만 중립 건물이 남을 수 있으므로 **최종 동점은 가능**하다. 총점 범위는 25~47점이다.

## 4. 병종과 전투

| 병종 | 코드 | 생산 비용 | 이동 | 역할 |
|---|---|---:|---|---|
| 깃발병 | F | 5 | 1칸 | 유일하게 점령 가능, 전투력 0 |
| 전투병 | W | 3, 공학관 보유 시 2 | 1칸 | 전투력 1, 점령 불가 |
| 정찰병 | S | 2 | 1칸 또는 MOVE2로 2칸 | 점수 공개, 전투력 0, 점령 불가 |

유닛은 개별 ID나 체력이 없다. `(좌표, 팀, 병종)`별 인원 수로만 표현된다. 아군끼리는 같은 칸에 제한 없이 겹치며 분할 이동할 수 있다.

전투는 **이동이 모두 끝난 뒤 최종 도착 칸**에서만 일어난다.

1. 양 팀 W를 `min(W_Y,W_K)`명씩 제거한다.
2. W가 남은 쪽이 상대의 F와 S를 모두 제거한다.
3. 양쪽 W가 0이면 양측 F/S는 함께 살아남는다.

W 10 대 W 9에서는 양측 9명씩 죽고 1명만 남는다. 큰 군대가 손실 없이 작은 군대를 지우는 구조가 아니며, 스타크래프트의 사거리·체력·연속 공격 공식을 가져오면 틀린다.

**생존과 적 제거의 문턱이 다르다.** 적 도착 W가 4명이면 아군 W 4명으로 F를 살릴 수 있다. 적 F까지 제거하려면 W 5명이 필요하다. 양측 F가 남으면 점령은 경합으로 멈춘다.

내 소유 건물에서 내 F가 전투로 죽으면 건물이 즉시 중립이 된다. F가 없는 빈 내 건물에 적 W만 들어오면 소유권은 그대로다. 적 W는 혼자서 빈 건물을 점령하거나 중립화할 수 없다.

## 5. 자원

| 항목 | 값 |
|---|---:|
| 시작 자원 | 10 |
| 시작 병력 | 0 |
| 기본 수입 | 매 턴 10 |
| 학생회관 수입 | 소유한 회관 1개당 +2/턴 |
| 자원 상한 | 40 |
| 보급소 | 팀별 최초 점령 시 +15 |

상한은 수입과 보급소 등 모든 획득에 적용된다. 40을 넘어가는 자원은 사라진다. 상대 자원도 매 턴 입력에 나온다.

생산은 턴 초 자원으로만 한다. 점령은 그 턴 수입을 받은 다음 처리하므로, 생산으로 자원을 0까지 써도 기본 수입 10으로 점령할 수 있다. 단 여러 건물의 총 점령 비용이 10을 넘거나 회관 상실 등으로 예측이 달라질 수 있으므로 합계 기준으로 예약한다.

## 6. 한 턴의 정확한 순서

`명령 수신 → 생산 → 동시 이동 → 전투 → 건물 효과 갱신 → 수입 → 점령 → 정보 공개 → 승리 판정`

| 효과 | 실제 적용 시점과 결과 |
|---|---|
| 새 유닛 이동 | 생산이 먼저이므로 같은 턴에 바로 이동 가능 |
| 병원 생산·공학관 할인 | 생산 단계의 소유권 사용. 이후 잃어도 이미 처리한 생산 유지 |
| 순간이동 | 이동 단계에 소유한 역만 사용. 이번 턴 점령 예정인 역은 사용 불가 |
| 학생회관 수입 | 전투 이후, 점령 이전 소유권 사용 |
| 회관을 전투로 잃음 | 이번 턴 수입부터 감소 |
| 회관을 점령 단계에서 새로 얻음 | 다음 턴 수입부터 증가 |
| 도서관 할인 | 점령 단계 진입 때 소유 여부를 고정 |
| 도서관을 점령 단계에서 잃음 | 해당 단계 할인은 유지 |
| 도서관을 점령 단계에서 얻음 | 다음 턴부터 할인 |
| 도서관을 전투 단계에서 잃음 | 해당 턴 점령 할인도 사라짐 |
| 보급소 보너스 | 모든 건물의 점령 처리 후 지급. 같은 턴 다른 건물 점령 재원으로 사용 불가 |
| 방송국 | 점령 후 정보 공개 단계에서 바로 공개 효과 적용 |

이동 직전 병력 풀과 도착 병력을 구분한다. A→B로 온 유닛에게 같은 턴 B→C 명령을 줘도 다시 움직이지 않는다. 기존 B의 유닛은 움직일 수 있다. 서로 위치를 교환하는 적 유닛은 중간에서 충돌하지 않는다.

## 7. 점령

점령 명령은 없다. 전투 이후 해당 건물에 자기 F가 있고 상대 F가 없으면 자원을 써서 자동 진행한다.

| 현재 소유 | 이번 턴 처리 |
|---|---|
| 중립 | 비용 2 지불 후 즉시 내 소유 |
| 상대 | 비용 2 지불 후 중립. 다음 턴 이후 다시 비용 2로 점령 |
| 내 소유 | 유지, 추가 점령 비용 없음 |
| 양 팀 F 공존 | 경합, 양 팀 모두 점령 진행 없음 |

- 중앙광장은 단계당 4, 도서관이 있으면 일반 건물 1·광장 3.
- F가 여러 명 있어도 건물당 한 단계만 진행하고 비용도 한 번만 낸다.
- 자원이 부족한 건물은 건너뛰고 뒤의 처리 가능한 건물을 계속 확인한다.
- 중립화는 공격자를 기억하지 않는다. 다음 턴 상대도 다시 점령할 수 있다.
- 점령한 F가 떠나도 소유는 유지된다.

**중요한 비대칭:** 적 건물에 수비 F가 있고 내 W가 이를 제거하면 전투 단계에서 중립이 되므로, 내 F는 같은 턴에 점령할 수 있다. 수비 F가 없는 빈 적 건물은 일반 점령으로 두 턴이 걸린다. 약한 F를 상주시켰다가 죽는 것이 빈 건물로 두는 것보다 불리할 수 있다.

점령 처리 순서는 다음과 같다.

1. 마지막 `PRIORITY`의 좌표 순서.
2. 나머지는 공개된 점수 내림차순. 미공개 점수는 정렬에서 0.
3. 같으면 본진 기준 정규화된 `(y,x)` 오름차순. Y는 그대로, K는 `(14-y,14-x)`.

대칭으로 추론한 점수는 봇이 아는 정보일 뿐 엔진의 “공개 여부”를 자동으로 바꾸지 않는다. 중요한 순서는 `PRIORITY`로 직접 지정한다.

## 8. 건물 기능

| 건물 | 코드 | 기능 | 전략상 해석 |
|---|---|---|---|
| 중앙광장 | PLAZA | 3점, 단계당 점령비 4 | 중앙의 고정 점수. 무조건 첫 목표일 필요 없음 |
| 학생회관 | HALL | +2 자원/턴 | 일찍 확보할수록 경제 효과 큼 |
| 공학관 | ENG | W 비용 3→2 | 같은 예산에서 W 생산량 약 50% 증가 |
| 병원 | HOSPITAL | 그 칸에서 생산 | 생산량 증가가 아니라 이동 거리·증원 시간 절약 |
| 역 | STATION | 아군 역 사이 TELE | 2개 이상 필요, 한 턴 병종 하나 최대 5명 |
| 도서관 | LIBRARY | 단계당 점령비 -1 | 확장·재점령이 많을수록 유용 |
| 방송국 | WATCH | 체비쇼프 3 이내 건물 점수 공개 | 적 병력 탐지용이 아님 |
| 보급소 | DEPOT | 팀별 건물별 최초 +15 | 단기 병력 공급, 자원 상한으로 보너스 유실 가능 |

공학관과 도서관의 할인은 두 개를 가져도 추가 중첩되지 않는다. 두 번째 건물의 가치는 점수·백업·상대 효과 차단에서 나온다. 공학관의 표시명 “공학원/정보관”과 관계없이 코드는 ENG다.

## 9. 명령 문법과 흔한 실수

```text
SPAWN F 2
SPAWN W 3 4 7
MOVE 0 7 F 1 R
MOVE2 2 5 S 1 U R
TELE 3 4 W 5 8 9
PRIORITY 7 7 5 6
END
```

| 명령 | 필수 제약 |
|---|---|
| SPAWN | 토큰 3개 또는 5개, 양의 인원. 좌표 생략=본진. 좌표 지정=소유 병원만 |
| MOVE | 토큰 6개, 양의 인원, F/W/S, U/D/L/R, 유효 도착 칸 |
| MOVE2 | 토큰 7개, S 전용. 경유·도착 칸 모두 통행 가능 |
| TELE | 토큰 7개. 서로 다른 소유 역, 처음 실제로 1명 이상 이동한 유효 명령만 적용, 최대 5명 |
| PRIORITY | 좌표가 짝을 이뤄야 함. 여러 줄이면 마지막 것만 유효 |
| END | 매 턴 필수. 출력 후 flush |

- **본진 좌표를 명시한 SPAWN은 무효**다.
- 생산 자원이나 이동 인원이 모자라면 가능한 만큼만 처리한다.
- 같은 단계의 명령은 출력 순서대로 처리한다. 단계 자체의 순서는 바뀌지 않는다.
- TELE가 무효이거나 이동 가능한 해당 병종이 0명이면 횟수를 소모하지 않는다.
- MOVE2 경유지는 전투도 점수 공개도 하지 않는다. 도착 후 생존 상태 기준으로 처리한다.
- PRIORITY 중복 좌표는 첫 번째만 사용하고, 건물이 아니거나 이번 턴 대상이 아닌 좌표는 무시한다.
- 명령 오류는 해당 줄만 무시한다. 시간 초과·프로세스 종료·END 누락은 몰수다.

## 10. 공개·비공개 정보와 메모리

항상 공개: 전체 지형, 모든 병력의 좌표·병종·인원, 양측 자원, 건물 종류·소유권·단계.

유일한 숨은 게임 상태 값은 아직 공개되지 않은 건물 점수다. 동시 선택 중인 상대 행동 역시 결정 순간에는 알 수 없다. 입력의 `-1`은 낮은 점수가 아니라 “미공개”다.

점수는 내 유닛이 건물 위에 생존하거나 내 S의 체비쇼프 2 안에 있거나 내 방송국의 체비쇼프 3 안에 있으면 영구 공개된다. 상대와 공개 목록을 공유하지 않는다.

모든 비중앙광장 건물은 8개의 점대칭 쌍이다. 가능한 점수 조합의 상한은 `2^5 × 3^3 = 864`개다. 이는 독립적인 조합의 상한이며 실제 생성기에서 모든 지형에 모든 조합이 나타난다는 뜻은 아니다. 양 끝 건물을 따로 샘플링하면 규칙을 위반한 가상 맵을 만들게 된다.

프로그램은 경기 내내 살아 있으므로 다음을 보관할 수 있다.

- 건물별 과거 소유 턴 수: 나중에 점수가 공개돼도 누적 점령-턴을 재계산 가능.
- 팀별 보급소 최초 점령 여부: 재점령 보너스를 잘못 기대하지 않기 위해 필요.
- 이전 병력 배치·생산 추정·목표: 상대 행동 패턴과 경로 변경을 분석.
- 이미 공개되었거나 대칭으로 추론한 점수.

`N 1`은 직전 턴 중립화되었다는 표시이며 `N 0`과 점령 규칙이 같다. 누가 다음 점령의 권리를 가진다는 뜻이 아니다.

## 11. 승리 판정

즉시 승리: **상대 점수=0 AND 내 점수>맵 총점/2**.

160턴 종료 후 다음 항목을 사전식으로 비교한다.

1. 현재 소유 건물의 실제 점수 합.
2. 매 턴 점령 단계 직후 점수 합을 누적한 값.
3. 생존 병력 환산 `5F + 3W + 2S`.
4. 전부 같으면 무승부.

현재 점수 1점 차이는 누적 점수나 병력 수로 뒤집을 수 없다. 전투병 할인으로 2에 생산했어도 마지막 환산 가치는 3이다. 자원 잔량 자체는 타이브레이커가 아니다.

## 12. 실행 환경·제출

| 항목 | 배포된 실행 제한 |
|---|---|
| Python | 3.12.14 |
| NumPy | 2.3.3 |
| C++ | C++20, GCC 12.2.0 |
| 장치 | CPU |
| 메모리 | 384 MiB |
| 프로세스 | 최대 32 |

| 첫 턴 | 3000ms, 프로세스 기동·INIT·초기화·첫 응답 모두 포함 |
| stdout/턴 | 64 KiB, 4096줄 |
| stdout/줄 | 1 KiB |
| stderr/경기 | 1 MiB |

일반 턴 측정은 입력 전송 시작부터 END 수신까지다. END를 썼더라도 프로세스가 이미 종료했다면 몰수될 수 있으므로 EOF까지 입력을 기다리는 루프를 유지한다. 양측 동시 오류는 무승부, 각 0.5점이다.

C++ 제출 ZIP 루트:

```text
submission.json  # {"schemaVersion":1,"language":"cpp"}
main.cpp
protocol.hpp
generated.hpp
```

바깥 폴더를 한 번 더 감싸지 않는다. C++ 보조 파일은 `.cpp/.h/.hh/.hpp`, Python은 `.py`가 허용된다. 절대·상위 경로, 심볼릭링크, 바이너리·데이터·학습 가중치를 넣지 않는다.

프로젝트 루트에서 실행:

```bash
g++ -std=c++20 -O2 submissions/first/main.cpp -o artifacts/first_bot
python3 yk-development-tools/bots/dist/starter/make_submission.py \
  --source submissions/first --output artifacts/submission-v1.zip
python3 yk-development-tools/bots/dist/starter/run_tests.py \
  --zip artifacts/submission-v1.zip
```

실제 1차 제출 파일은 [submission-v1.zip](../artifacts/submission-v1.zip)이다. 업로드 후 검사 통과와 해당 코드의 선택 상태를 확인하고 서버 연습을 실행한다.

로컬 검사에서 출력 초과는 경고지만 서버에서는 몰수다. 로컬 머신은 Python 3.14.7/GCC 16.2.1이므로 서버와 버전·CPU가 다르다. 코드에서는 C++20과 표준 라이브러리만 사용했다. 서버에서의 컴파일·성능 확인은 별도로 필요하다.

## 13. 강의 자료를 읽을 때 주의할 점

강의는 01:25~01:33에 실제 대회 환경이 아니라 설명용 가정이라고 명시한다. 강의의 200턴, 예시 전투력, 휴리스틱 가중치를 최종 규칙으로 쓰지 않는다. 강의의 핵심은 BFS, 평가 함수, 여러 상대를 통한 개선, 특정 봇 과적합 방지다. 실제 경기 수치와 판정은 규칙서 및 엔진을 따른다. [강의 전사](../해커톤_안내자료/한국어_자막_전사.txt)
