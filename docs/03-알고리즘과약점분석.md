# 알고리즘 제안, 반례, 1차 구현과 다음 버전

## 1. 최종 제안

추천하는 우승 도전 방향은 **경제·병력 임무를 배분하는 정책 + 정확한 동시 턴 시뮬레이션 + 중요한 전투에 집중하는 탐색 + 다양한 상대를 유지하는 검증**이다. 실행은 C++20으로 하고, 실제 행동 선택은 제한된 후보들의 동시 행동 행렬에서 혼합 전략을 구하는 방식으로 한다.

이는 승리가 보장된 알고리즘이라는 뜻이 아니다. 이미 1차 구현에서 재현 가능한 패배를 찾았다. 1차 ZIP은 빠르게 리더보드에 올리고 서버 결과를 얻기 위한 기준 버전이며, 아래 보완 설계 전체가 구현된 최종 우승 봇은 아니다.

1차 파일: [제출 ZIP](../artifacts/submission-v1.zip), [소스](../submissions/first/main.cpp). 연구 근거와 원문은 [Firecrawl 조사](02-Firecrawl조사.md), 수치와 규칙은 [대회 규칙](01-대회규칙과제출.md)에 분리했다.

## 2. 제안 전에 폐기·보류한 접근

| 후보 | 장점 | 치명적 약점과 반례 | 결정 |
|---|---|---|---|
| 가장 가까운 건물 BFS | 빠르고 구현 쉬움 | 여러 F가 몰림, 적 W에 무방비, 경제 거점 가치 무시 | 최종 전략으로 폐기. 거리 계산 부품으로 사용 |
| 고정 가중치 하나로 탐욕 선택 | 예제보다 강하게 만들기 쉬움 | 같은 패턴이 반복되어 공략당함. 순서·호위·종반 효과가 누락 | 안전한 기본 행동 생성기로만 사용 |
| F를 모든 건물에 상주시킴 | 직관적인 수비 | 약한 F가 죽는 순간 소유권을 잃고, 적 F+W에게 한 턴 탈환 허용 | 폐기 |
| W 최대 생산·한 덩어리 공격 | 국지 수적 우세 | W 혼자 빈 적 건물을 바꿀 수 없음. 반대편의 여러 F를 놓침 | 독립적인 공격 후보로만 유지 |
| 매번 공학관→회관→병원 고정 순서 | 경제 효과 큼 | 지형·거리·상대 공격에 따라 비용이 달라짐. 가까운 보급소를 놓칠 수 있음 | 고정 빌드 폐기, 도착 시간과 기회비용 반영 |
| 일반 순차 미니맥스/Alpha-Beta | 잘 알려진 탐색 | 동시 행동을 상대가 내 행동을 본 뒤 대응하는 게임으로 잘못 바꿈 | 직접 적용하지 않음 |
| 원시 행동 전체에 MCTS | 구현 틀이 간단 | 병력 분할·공동 생산·TELE 조합이 폭증, 300ms에 유용한 탐색 부족 | 행동 추상화 후 국소 탐색에 한정 |
| 한 상대를 예측해 깊게 탐색 | 예측이 맞으면 강함 | 예측이 틀리면 모든 롤아웃이 같은 방향으로 틀림 | 여러 적 정책과 안전 후보 유지 |
| PPO/AlphaZero 모델 직접 제출 | GPU를 활용할 수 있음 | 현재 규칙의 학습 가중치 제출 금지와 충돌 | 제출 주력으로 보류 |

가중치를 몇 개 바꾸는 것만으로 모든 문제를 해결하려 하지 않는다. 경제·장거리 임무, 이번 턴 전투, 최종 승리 판정을 별도의 계층으로 나누고 정확한 전이 모델로 묶는 구조를 선택한다.

## 3. 게임 구조에서 직접 도출되는 전략

### 3.1 공학관의 효과는 크지만 거리가 먼저다

전투병에 예산 10을 계속 쓴다고 가정하면 할인 전 평균 생산량은 `10/3≈3.33`, 할인 후는 `10/2=5`명/턴이다. 학생회관까지 있으면 `12/2=6`이다. 할인도 회관도 없는 상태와 비교한 6/3.33은 약 1.8배다.

이 수치는 오직 W 생산에 쓰는 예산의 비교다. 실제로는 F·점령 비용·전선 이동이 있으므로 그대로 전투 승률이나 병력 비율이 되지는 않는다. 공학관 확보가 10턴 늦어진 비용과 그동안 다른 건물을 얻는 이익을 함께 계산한다.

### 3.2 병원의 가치는 증원 도착 시각이다

본진에서 전선까지 10칸, 병원에서 3칸이면 새 병력의 도착을 7턴 앞당긴다. 단 병원은 소유한 다음 턴부터 생산에 쓸 수 있고, 이동 중 손실·경로·공동 예산을 고려해야 한다. 병원 수가 늘어도 자동 생산이나 추가 수입이 생기지는 않는다.

병원 후보 b의 위치 가치는 다음 형태로 추정한다.

`V_spawn(b) = 앞으로의 생산량 × Σ(목표 중요도 × 기존 생산지 대비 거리 절감)`

가까운 병원만 찾지 말고 상대 병원을 잠시 중립화했을 때 적 증원이 얼마나 늦어지는지도 본다.

### 3.3 깃발병은 점령 임무에 필요한 만큼 생산한다

같은 건물의 F 1명과 10명은 점령 속도가 같다. 추가 F는 별도의 안전한 목표, 양동, 손실 보충, 종반 동시 중립화에 쓰일 때 가치가 있다. 반대로 F가 너무 적으면 W로 지배하는 공간을 점수로 전환하지 못한다.

고정된 “F는 항상 7명”은 출발점에 불과하다. 최종 설계에서는 안전하게 완료 가능한 임무 수와 도착 시간을 기준으로 생산한다.

### 3.4 건물을 지킨다는 것은 적 F의 도착을 통제하는 것이다

빈 아군 건물은 적 W가 들어와도 유지된다. 따라서 모든 건물 위에 병력을 두기보다 적 F가 도달할 경로·목표를 차단하는 편이 유리할 수 있다. 다만 적 F가 들어와 중립화하고 다음 턴 점령하는 것을 방치해서는 안 된다.

동일 칸의 F를 지키려면 도착 W가 적 W 이상, 적 F를 제거하려면 더 많아야 한다. 각 목표에 필요한 인원 문턱을 구하고 불필요한 과잉 병력을 줄인다. 여러 아군 부대가 같은 칸으로 합류하는 효과도 공동 계산한다.

### 3.5 자원 상한과 같은 턴 수입을 함께 반영한다

이번 턴 예측 점령비 C, 현재 자원 R, 보수적으로 계산한 수입 I라면 생산 후 남겨야 할 양의 출발점은 `max(0,C-I)`다. 단 C는 전투 후 생존·경합·점령 우선순위에 따라 변하므로 최종 판단은 시뮬레이터로 한다. 보급소 +15는 C를 내는 데 포함하지 않는다.

### 3.6 마지막 턴에는 중립화만 해도 가치가 있다

4점짜리 적 건물을 마지막 턴에 중립화하면 적에게서 4점을 뺀다. 점령까지 끝내면 점수 차가 8점 바뀐다. 빈 적 건물은 두 단계가 필요하므로 159~160턴의 도착 계획이 중요하다. 약한 적 수비 F를 전투로 제거한 뒤 내 F로 같은 턴 점령하는 경우는 별도 후보로 생성한다.

### 3.7 정찰의 목적은 점수 불확실성 감소다

적 군대는 이미 보인다. S를 생산하는 이유는 두 경쟁 목표의 실제 점수가 행동 결정을 바꿀 가능성이 있을 때다. 이동만으로 자연스럽게 공개될 점수, 대칭으로 이미 아는 점수에 돈을 쓰지 않는다. 1차 버전은 S 생산을 구현하지 않았다.

## 4. 1차 버전에 실제 구현한 알고리즘

### 입력·메모리

- 최초에 통행 가능한 칸 사이의 BFS 거리를 계산한다. 경로는 장애물만 피하는 기본 거리를 사용한다.
- 현재 병력·자원·건물 소유를 배열로 저장한다.
- 보급소 보너스 수령 이력과 건물별 소유 턴 수를 저장한다.
- 공개된 점수와 대칭 점수를 반영하고, 남은 미공개 값에는 1.5 또는 3의 중간값을 사용한다.

### 후보 정책 3종

1. 방어를 상대적으로 중시하는 균형형.
2. 공학관·학생회관의 가치를 더 높이는 경제형.
3. F 목표 수와 위험 패널티를 줄이는 공격형.

각 정책은 다음을 하나의 명령 묶음으로 만든다.

- 본진 또는 병원에서 F/W 생산. 생산한 병력도 바로 이동 대상으로 포함.
- 미소유 건물에 F 임무를 하나씩 배정해 중복 목표를 줄임.
- 적의 한 턴 도달 가능 W와 생산 가능 W를 위험으로 계산.
- 수비·점령·적 F 차단·호위 목표에 W를 분할 배분.
- 역 사이 TELE를 한 번, 최대 5명으로 배정.
- W 도착 계획을 반영해 F의 안전한 첫 이동을 선택.
- 점령 순서를 PRIORITY로 출력.

위험 지도는 칸별 상한이므로 모든 칸의 최악 위협이 동시에 실현 가능한 적 계획이라는 뜻은 아니다. 이는 안전을 위한 근사이며 아래 약점으로 따로 기록했다.

### 탐색과 행동 선택

각 내 후보 3개와 상대 후보 3개의 조합을 최대 4턴 시뮬레이션한다. 중간에도 같은 정책으로 다음 행동을 다시 계산한다. 실제 160턴이 가까우면 남은 턴 수로 깊이를 줄인다.

```text
매 턴 상태 입력
    후보 = 정책 3종으로 생성한 전체 명령 묶음
    for 내 후보 i, 적 후보 j:
        최대 4턴 동시 전이
        경제·점수·병력·도착 가능성 평가
        payoff[i][j] 기록
    3×3 행렬에서 양측 regret matching 600회
    평균 전략 분포로 내 후보 한 개 선택
    그 후보의 첫 턴 명령만 출력하고 END/flush
```

후회 최소화는 각 행이 적의 혼합 행동에 비해 얼마나 유리했는지 누적하고, 양의 후회에 비례해 다음 선택 비중을 둔다. 평균 분포를 사용하지만 600회의 유한 반복이며 근사 payoff 자체에도 오차가 있다.

전체 탐색이 내부 160ms 예산을 넘으면 미완성 행렬을 사용하지 않고 미리 생성한 균형형 후보를 출력한다. 이 여유는 파싱·출력과 환경 차이를 위한 것이며, 시간 검사는 루프 경계에 있어 서버에서 최대 소요 시간을 확인해야 한다.

현재 난수 시드는 고정이므로 같은 입력에서 재현 가능하다. 탐색이 혼합 분포를 계산하더라도 고정 시드를 아는 상대가 이론적으로 패턴을 예측할 수 있다는 한계가 있다. 실제 필요성이 확인되면 재현 모드와 경기 모드의 시드를 분리한다.

전체 대전 108회에서 몰수 결과 0회. 해당 대전군에서 관측된 최대 응답 시간은 약 **37ms**다. 첫 턴을 포함한 측정이며 로컬 머신 수치다. 제공 ZIP 검사에서 stdout 한 줄 최대 87바이트, stderr 0바이트였고 출력 제한 경고가 없었다.

추가로 정상 경기의 병력 규모를 넘겨 모든 통행 칸에 양측 병력을 넣은 합성 입력을 3회 처리했다. 모두 응답했고 최대 약 46.3ms, 한 응답 139줄·2245바이트였다. 이는 성능·입출력 스트레스 검사이며 합법적인 경기 경로에서 도달 가능한 상태라고 주장하지 않는다. [기록](../records/benchmarks/v1/stress.json)

예제 lv2 60전은 30개 맵을 양 진영으로 대전한 결과다. 60개의 완전히 독립적인 표본으로 취급하지 않는다. 자체 세 정책은 코드 구조를 공유하고 탐색의 상대 후보에도 들어 있어 매우 유리한 검사 상대다. **47/48을 미지의 참가자 상대 승률로 해석하면 안 된다.** 이후 서버 상급 10전 전승을 확인했고, 추가 로컬 40전에서는 시드 1017의 양 진영 패배를 발견했다. [후속 결과](04-벤치마크운영.md)를 참고한다. 실제 참가자 상대 성적은 아직 확인하지 않았다.

## 7. 최종 우승 후보의 구체 설계

### A. 상태와 점수 불확실성

지형은 고정 205개 통행 칸, 건물은 17개이므로 큰 신경망 없이도 상태를 작은 배열로 다룰 수 있다. 경기 중 결정은 다음을 함께 사용한다.

- 실제 공개된 병력·자원·소유권.
- 8개 점대칭 쌍의 점수 후보 집합.
- 건물별 소유 턴 수와 보급소 수령 이력.
- 내 역할 예약과 최근 상대 이동의 설명 가능 후보.

각 대칭쌍 j의 점수를 p_j, 그 쌍의 내 소유 개수-적 소유 개수를 c_j라고 하면 점수 차는 다음과 같다.

`Δscore = 3×중앙광장 소유 차 + Σ(c_j × p_j)`

범위 최솟값·최댓값은 c_j의 부호에 따라 p_j의 하한/상한을 선택해 계산할 수 있다. 서로 하나씩 가진 쌍은 c_j=0이므로 미공개여도 현재 점수 차에 영향이 없다. 모든 가능한 조합을 열거해도 상한 864개다.

장기 시뮬레이션은 대표 조합을 쓰되, 종반에는 결정이 바뀌는 점수 조합을 더 평가한다. 확실한 승리 조건과 기대 승리를 구분한다. 미공개 점수가 항상 독립 균등분포라고 단정하지 않는다.

**정보 누출 방지:** 시뮬레이션용 실제 점수 조합과 정책이 관측할 수 있는 점수를 분리한다. 샘플링한 숨은 값을 시뮬레이션 속 봇에게 처음부터 알려주면 존재하지 않는 정보로 행동하는 오류가 생긴다. 공개 이벤트 이후에만 관측에 반영한다.

### B. 경제·역할 계층

건물 가치는 고정 순위가 아니라 도착 시간과 유지 가능성을 포함한다.

`가치 = 점수 변화 + 남은 기간 경제 이익 + 증원 시간 이익 + 상대 기능 차단 - 이동 비용 - 손실 위험`

평가를 위해 서로 다른 단위를 같은 숫자로 섞는 가중치는 최종 승리 자체가 아니라 비종료 상태의 추정에만 쓴다. 종료 상태에서는 실제 우선순위로 승패를 먼저 판단한다.

F와 목표의 배정은 최단 거리, 적 도달 시각, 호위 수요, 기존 임무 변경 비용을 포함한 소규모 이분 배정으로 만든다. W는 모든 개체를 쪼개기보다 1명 차단, 동률 호위, 우세 공격, 예비대 등의 묶음으로 배정한다.

예산 제약과 TELE 한 번 제약은 모든 임무가 공유한다. 서로 다른 임무가 동일한 생산 자원·동일 부대를 각각 전부 사용할 수 있다고 계산하면 안 된다.

### C. 서로 다른 행동을 만드는 포트폴리오

다음 후보는 가중치만 다른 정책이 아니라 행동 목적이 달라야 한다.

| 정책 | 주된 행동 |
|---|---|
| 안전 확장 | 위험이 작은 미점령 목표에 F를 분산 |
| 경제 확보·유지 | 공학관·회관 확보와 재탈환, 수비 인원 예약 |
| 병원 압박 | 적 생산 거점 중립화와 아군 전방 생산 |
| 호위 돌파 | F+충분한 W의 도착 시각을 맞춤 |
| F 차단 | 적의 현재 칸을 쫓기보다 다음 점령 목표에서 대기·요격 |
| 두 방향 공격 | 상대의 한 부대가 동시에 막기 어려운 목표 두 개를 공격 |
| 점수 방어 | 현재 확실한 리드에 필요한 건물 집합과 증원 유지 |
| 종반 중립화 | 남은 턴 안에 적 점수 감소가 가장 큰 행동 선택 |
| 긴급 철수 | 죽을 F를 빼서 소유권 중립화를 방지 |
| 정보 수집 | 점수 공개가 목표 선택을 바꾸는 경우만 S 활용 |

각 후보는 생산 위치·수량, 병력 이동, TELE, PRIORITY를 포함한 **전체 명령 묶음**이다. 임의로 각 후보의 부분 행동을 섞으면 호위가 깨질 수 있으므로, 섞은 뒤 다시 자원·인원·도착 결과를 검증해야 한다.

### D. 전술 계층: 중요한 곳에 계산 집중

후방 병력은 미리 계산한 거리와 역할을 따른다. 다음 위치의 2~4개 핵심 부대에만 세밀한 행동 후보를 추가한다.

- 다음 턴 소유권이 바뀔 건물.
- 수비 F가 죽을 수 있는 소유 건물.
- 병원과 연결 역.
- 상대 W와 동률·1명 우세의 경계에 있는 집단.
- 마지막 몇 턴에 점수 차를 바꾸는 F.

핵심 부대의 후보는 이동 4방향·대기·역 이동·필요 인원만 분할·합류를 포함한다. 형식상 가능한 모든 인원 분할을 열거하지 않고 `{1, 동률에 필요한 수, 1명 우세에 필요한 수, TELE 5, 전원}` 등의 의미 있는 문턱을 사용한다.

이는 비대칭 행동 추상화 연구의 아이디어를 이 게임에 맞춘 것이다. [근거 논문](https://arxiv.org/abs/1711.08101)

### E. 동시 행동 행렬과 상대 추정

내 전체 후보 a_i와 적 후보 b_j를 동시에 실행해 Q_ij를 계산한다. 기본 목표는 제한된 후보 집합에서 `max_x min_y xᵀQy`에 가까운 혼합 전략을 찾는 것이다.

상대 관측을 이용한 공략은 안전 성능을 지키는 제한과 함께 쓴다. 예를 들면 다음 형태다.

```text
관측한 적 정책 분포 q_hat에 대한 기대값을 높이되,
모든 적 후보 j에 대해 x^T Q[:,j] >= v_safe - epsilon을 유지한다.
```

실제 구현에서는 별도 최적화 라이브러리 없이 작은 행렬에 대한 후회 최소화, 안전 후보와의 혼합, 후보 점검으로 근사한다. 이 제약의 효력도 **열거한 적 후보와 추정 payoff에 한정**된다.

적이 같은 자원을 여러 병원에서 중복 사용하거나 하나의 W를 여러 칸에 동시에 보내는 가짜 최악 상황을 행렬 열로 만들지 않는다. 위험 지도는 후보 제거의 보조 수단이고 최종 검증은 적의 합법적인 공동 행동으로 한다.

### F. 탐색 깊이와 시간

300ms 전체를 소모하지 않는다. 우선 안전 정책을 생성하고, 완성된 작은 행렬을 확보한 뒤 추가 시간을 쓴다.

- 평시: 짧은 전이와 경제·역할 평가.
- 접전: 주요 부대에 후보 수를 더 배정.
- 종반: 남은 턴이 짧고 분기 수를 줄일 수 있을 때 160턴까지 탐색.
- 임계 시각: 약 180~220ms 안에 새 탐색을 중단하고 출력 준비. 실제 서버 측정으로 조정.

다음 버전의 초기 실험값으로 `내 후보 5 × 적 후보 4 × 점수 조합 2 × 깊이 3 = 120회 전이`를 검토할 수 있다. **이 설정의 서버 시간은 아직 측정하지 않았다.** 1차의 36회 전이보다 많으므로 캐시·후보 공유·조기 중단을 넣고 실제 시간을 보고 조절한다. 평균 시간뿐 아니라 최대, 상위 99백분위, 밀집 병력 상태를 확인한다.

부분적으로만 평가한 행·열을 유리한 후보처럼 사용하지 않는다. 비교 조건이 완성된 작은 행렬을 fallback으로 항상 남긴다.

### G. 종반 전용 평가

종료 상태에서는 각 점수 조합별로 공식 승리 판정을 그대로 실행하고 승·무·패를 사용한다. 현재 점수에 작은 계수를 주고 병력 가치에 큰 계수를 주는 식으로 공식 우선순위를 뒤집지 않는다.

종반 후보에는 F 철수, 적 건물 중립화만 하고 다른 목표로 전환, F/W 동시 도착 탈환, TELE로 5명 수비 보강, 새 유닛 즉시 이동을 반드시 포함한다. 마지막 생산에서는 점령·전투를 방해하지 않는 범위에서만 병력 타이브레이커를 높인다.

## 8. 이 최종 설계도 가진 약점

| 남는 약점 | 영향 | 대응과 폐기 기준 |
|---|---|---|
| 후보에 없는 상대 전술 | 행렬의 안전성도 무의미해질 수 있음 | 서버 패배 정책을 추가. 상대 집단 확대 후에도 특정 유형에 반복 패배하면 후보 생성기 교체 |
| 짧은 탐색의 경제 단견 | 당장 점수와 장기 생산 기반을 혼동 | 역할 유지, 경제 거점 상실의 지속 비용. 장기 성과가 개선되지 않으면 상위 경제 계획 별도 탐색 |
| F·W 공동 배정의 비선형성 | 각각 좋아 보이는 배정이 같이 실패 | 완성된 명령 묶음을 재시뮬레이션. 독립 최적 배정의 보장은 주장하지 않음 |
| 숨은 점수의 평균화 | 1점 승부에서 오판 | 대칭쌍의 범위·가능 조합 평가. 정보 가치가 높을 때만 정찰 |
| 역할 고정의 경직성 | 잘못된 임무에 집착 | 목표 상실·위험 변화·큰 가치 개선 시 예약 해제 |
| 혼합 전략의 변동성 | 같은 대진에서 결과가 흔들릴 수 있음 | 여러 난수 반복, 맵별 묶음 통계, 안전 후보 유지 |
| 엔진 재현 결함 | 탐색 깊이가 깊을수록 잘못된 확신 | 차등 검사 확대, 실패 상태 저장, 공지 변경 시 재검증 |
| 후보·깊이 증가 | 시간 초과 몰수 | 완성된 fallback, 시간 계측, 성능 악화 기능 제거 |

복잡한 새 기능은 기본 버전보다 종합 성능이 낮으면 채택하지 않는다. 한 실패 시드만 고치고 다른 맵에서 약해지면 원복한다. 알고리즘 이름보다 실제 실패 집합의 감소가 채택 기준이다.

## 9. GPU를 충분히 쓸 수 있을 때

사용자는 GPU 자원을 많이 쓸 수 있고 최종 마감까지 시간이 있다고 밝혔다. 그러나 지금 규칙에서 제출 추론은 CPU이고 학습 가중치를 넣을 수 없다.

따라서 우선순위는 다음과 같다.

1. C++의 빠른 시뮬레이터와 CPU 병렬 대전으로 충분한 기준 데이터를 만든다. GPU로 옮기는 데 걸리는 개발 비용부터 측정한다.
2. 필요하면 GPU에서 병렬 환경·정책 학습을 연구용 상대나 전략 반례 생성기로 활용한다. 이 모델을 제출하지 않는다.
3. 연구용 상대에게 당한 전술을 분석하고, 규칙을 준수하는 명시적인 행동 후보와 계획 로직을 작성한다.
4. 외부에서 학습한 모델·가중치·그 변형을 제출하는 방식은 현재 제안에서 제외한다. 향후 운영진이 허용을 명시할 때 별도의 경로로 검토한다.

GPU 보유 자체가 이 작은 격자 게임의 탐색 봇보다 높은 성능을 보장하지 않는다. 이 작업에서는 실제 GPU 학습·원격 자원 결제·대규모 학습 실행을 하지 않았다.

## 10. 1차 이후 검증 순서

1. 사용자가 ZIP을 업로드하고 빌드·검사 결과 확인.
2. 서버 중·상 난도 테스트. 결과의 상대 이름, 코드 버전, 시드, 진영, 승패, 리플레이를 기록.
3. 패배를 규칙/시간 오류, 생산, 경제 거점 상실, 경로·호위, 전술, 종반으로 나눔.
4. 재현된 패배를 가장 작은 상태나 짧은 리플레이로 남김.
5. 한 가지 구조적 수정만 적용하고 기존 버전·공개 예제·서로 다른 상대에 대전.
6. 변경에 사용하지 않은 새 시드, 양 진영, 필요하면 여러 난수로 최종 비교.

발전 단계별 검증용 상대에는 F 다방향 확장, 공학관 후 W 집중, 병원 러시, 회관 수비, 중앙 방어, 역 기습, 150턴 이후 중립화, 과거 버전을 포함한다. 예제와 세 내부 정책만으로는 충분하지 않다.

권장 채택 기준은 **오류·몰수 0, 새로운 시드에서도 개선, 취약 상대군 성능 악화 없음, 최대 시간 여유 확보**다. 특정 승률 임계값을 달성했다고 곧 우승하는 것은 아니므로 실제 리더보드와 대진 분포를 함께 본다.

## 11. 재실행

프로젝트 루트에서:

```bash
g++ -std=c++20 -O2 submissions/first/main.cpp -o artifacts/first_bot
g++ -std=c++20 -O2 tests/simulator_bridge.cpp -o artifacts/simulator_bridge
python3 tests/test_rules.py
python3 tests/test_simulator.py
python3 tests/benchmark.py --start 100 --seeds 25 \
  --output records/benchmarks/v1/baseline_holdout.json
python3 tests/benchmark.py --seeds 8 \
  --opponent './artifacts/first_bot 2' \
  --output records/benchmarks/v1/ablation_attack.json
```

`first_bot`의 선택 인자 0/1/2는 각각 고정 정책을 실행하는 대조군 모드다. 대회 실행은 인자 없는 기본 모드를 사용한다. 고정 시드와 동일 환경에서는 패배 시드도 재현 가능하다. CPU 부하로 내부 시간 예산이 달라지는 경우 fallback 선택 때문에 결과가 바뀔 수 있다.
