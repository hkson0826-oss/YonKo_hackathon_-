# 서버 상급 전승 이후의 벤치마크

확인일: 2026-09-27. 제출 v1은 그대로 유지했다.

## 서버에서 직접 확인한 사실

로그인된 Chrome의 경기 목록에서 `benchmark-hard` 상대 **10경기 모두 승리, 모두 Y 진영**을 확인했다. Firecrawl의 공개 접근은 로그인 페이지로 이동하여 경기 내용을 읽을 수 없었고, 실제 결과는 사용자가 열어 둔 Chrome에서 확인했다.

[사용자가 지정한 경기](https://yonsei-vs-korea-hackathon.kr/matches/01a0e263-3a78-7ccc-829b-f96020e26ee7)는 다음과 같다.

- 정상 즉시 승리(`instant`), 종료 36턴.
- Y 37점, K 0점. Y가 건물 17개 소유.
- 최종 병력: Y F7/W185/S0, K F9/W20/S0.
- 마지막 턴의 Y 응답 17ms, 출력 922바이트.

확인한 17ms는 이 경기 마지막 턴의 값이다. 모든 경기·모든 턴의 최대 시간이 아니다. 다른 9경기의 종료 턴과 세부 전투는 개별 확인하지 않았다.

이 결과는 제출물이 서버에서 정상 동작하고, 그 상대와 공개 연습 맵에 대해 유효한 전략이라는 근거다. 최상위 참가자 상대 성능, K 진영, 160턴 접전의 판단을 증명하지 않는다. 같은 상대·같은 공개 맵·같은 결정적 봇으로 반복한 전승은 독립적인 새 검증이 아니다.

## 기존 코드에 있는 것과 없는 것

| 항목 | 용도 | 한계 |
|---|---|---|
| `yk-python-sample/example_lv1.py` | 가까운 건물 확장 기준선 | 매우 약한 상대 |
| `yk-python-sample/example_lv2.py` | 소규모 호위·차단 기준선 | 서버 중·상 봇과 동일하지 않음 |
| `yk-development-tools/runner` | 임의 두 프로그램, 임의 시드, 양 진영, 리플레이 | 강한 상대 봇 자체를 제공하지 않음 |
| `bots/dist/starter/play_local.py` | 한 경기 실행·리플레이 저장 | 기본 상대는 lv1 |
| `bots/dist/starter/run_tests.py` | ZIP·컴파일·명령·출력 검사 | 승률·전략 강도 벤치마크가 아님 |
| `tests/benchmark.py` | 앞선 작업에서 추가한 다중 시드·양 진영 대전 | 상대 정책과 맵 구성을 별도로 선택해야 함 |
| `artifacts/first_bot 0/1/2` | v1의 방어형/경제형/공격형 고정 정책 | 모두 같은 코드 계열이고 v1 탐색의 상대 후보에 포함됨 |

**서버의 `benchmark-hard` 소스는 배포되어 있지 않다.** 배포 문서는 내부 기준 봇을 포함하지 않는다고 명시하며, `runner/smoke.py`도 내부 봇을 요구하는 운영용 검사라 제거됐다고 기록한다. [운영 문서](../yk-development-tools/docs/PLATFORM_OPERATIONS.md), [제외 기록](../yk-development-tools/docs/platform-sdk-provenance.json)

현재 레포에 숨겨진 더 높은 난도의 공식 상대가 있다는 근거는 발견하지 못했다. 다른 게임의 Lux/MicroRTS 봇은 규칙·상태·행동 프로토콜이 달라 이 러너의 상대 명령으로 바로 사용할 수 없다.

## 이번에 추가 실행한 더 까다로운 검사

v1 대 자체 공격형 고정 정책을 **새 시드 1000~1019, 양 진영 40경기**로 실행했다. 추가 튜닝은 하지 않았다.

**38승 2패, 무승부 0, 몰수 0.** 두 패배는 동일한 시드 1017이다.

| v1 진영 | v1 점수 | 상대 점수 | 종료 |
|---|---:|---:|---|
| Y | 1 | 25 | 160턴 점수 판정 |
| K | 4 | 23 | 160턴 점수 판정 |

동일한 조건으로 두 경기를 다시 실행해 같은 점수의 패배를 재현하고 리플레이를 저장했다. 이 맵은 이제 발견된 회귀 검사 사례로 취급한다. 이 결과를 보고 다음 버전을 조정하면 더 이상 최종 미사용 검증 맵이 아니다.

원시 결과: [40경기](../records/benchmarks/v1/benchmark-attack-unseen.json), [패배 재실행](../records/benchmarks/v1/benchmark-attack-1017.json), [Y 리플레이](../records/replays/attack-1017/seed-1017-Y.json), [K 리플레이](../records/replays/attack-1017/seed-1017-K.json).

이는 “현재 봇을 깨뜨릴 수 있는 검사가 이미 있다”는 증거다. 공격형 봇이 모든 맵에서 서버 상급보다 강하다는 순위 증거는 아니다. 그 직접 대전은 실행하지 않았다.

## 앞으로는 단일 상대보다 상대 집단

v2가 v1에 강하고 v3가 v2에 강해도 v3가 v1보다 모든 상대에 강하다는 보장은 없다. 자기 복제끼리만 붙이면 공통된 전략 누락도 잘 드러나지 않는다. 따라서 서로 다른 역할의 상대를 남겨야 한다.

1. **고정 기준선:** 제출 v1, 예제 lv1/lv2, 공식 서버 상급 결과.
2. **과거 버전:** 한 번 좋은 성과를 낸 버전은 수정하지 않고 보관.
3. **공략형 상대:** F 다방향 확장, 공학관 후 W 집중, 병원 압박, 점유 방어, 종반 중립화 등 행동 목적이 다른 봇.
4. **실패 사례:** 시드 0/Y, 시드 1017/양 진영과 앞으로의 서버 패배 리플레이.
5. **미사용 검증:** 개발·튜닝에서 보지 않은 새 시드. 확인 후 수정에 이용했다면 다음 검증은 다시 분리.

1~2는 지금 바로 가능한 검사다. 3의 완전히 독립적인 봇 집단은 아직 구현하지 않았다. 지금 있는 0/1/2는 시작점이고, 가중치만 다른 세 변형으로 충분하다고 판단하지 않는다.

후속 작업에서 다른 구현 계열의 팀원 봇을 받아 40경기에서 우리 v1 기준 25승 15패를 기록했다. 이 봇도 고정 상대에 포함할 수 있다. [브랜치와 대전 결과](05-팀원봇대전.md)

개선판의 채택은 전체 평균 승률 하나로 결정하지 않는다. 상대별 승무패, Y/K별 성적, 최종 점수 차, 160턴 경기 결과, 몰수 및 최대 응답을 함께 본다. 평균 점수 차는 진단 지표이며 공식 승패 우선순위를 대체하지 않는다. 표본 수는 경기 수와 서로 다른 맵 수를 함께 기록한다.

이미 모두 이기는 약한 상대의 비중을 늘리면 평균 승률만 쉽게 높아지므로, 상대 유형별 성적을 따로 유지한다. Elo 하나도 순환적인 상성을 모두 설명하지 못한다. 후보끼리의 대전 행렬을 남기는 편이 낫다.

## 바로 실행하는 명령

프로젝트 루트에서 현재 공격형 대전:

```bash
python3 tests/benchmark.py \
  --candidate './artifacts/first_bot' \
  --opponent './artifacts/first_bot 2' \
  --start 1000 --seeds 20 \
  --save-losses records/replays/attack-unseen \
  --output records/benchmarks/v1/benchmark-attack-unseen.json
```

`--seeds 20`은 Y/K를 모두 실행하므로 40경기다. `--save-losses`는 이번 작업에서 추가했으며 패배·무승부 리플레이를 저장한다. 같은 저장 폴더와 파일명으로 다시 실행하면 해당 로컬 결과를 갱신하므로 실험별 경로를 사용한다.

새 봇을 빌드한 뒤 v1과 비교하는 명령 예시:

```bash
# 아래 first_bot_v2는 향후 새 버전을 빌드한 실행 파일의 예시 이름이다.
python3 tests/benchmark.py \
  --candidate './artifacts/first_bot_v2' \
  --opponent './artifacts/first_bot' \
  --start 2000 --seeds 50 \
  --save-losses records/replays/v2-v1 \
  --output artifacts/benchmark-v2-v1.json
```

새 버전이 없는 지금 이 두 번째 명령은 바로 실행할 수 없다. 새 후보마다 v1뿐 아니라 서로 다른 공략형·과거 버전에도 동일한 맵 양쪽 진영으로 평가한다. 현재 v1의 난수 시드는 고정이므로 같은 조건 반복만으로 다양한 경기 난수를 검증한 셈이 되지는 않는다.
