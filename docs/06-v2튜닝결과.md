# 제출 v2 튜닝과 검증 기록

제출 파일은 [submission-v2.zip](../artifacts/submission-v2.zip), 소스는 [submissions/tuned/main.cpp](../submissions/tuned/main.cpp)다. 기존 v1은 별도로 보존했다.

## 비교 결과

모든 대전은 공식 로컬 엔진에서 맵별 Y/K 양 진영, 최대 160턴, 턴당 300ms로 실행했다.

| 비교 | v1 | v2 | 용도 |
|---|---|---|---|
| 팀원 Python 봇, 시드 1000~1019 | 25승 15패 | **38승 2패** | 후보 선택에 사용한 개발 맵 |
| 팀원 Python 봇, 시드 3000~3019 | 33승 7패 | **38승 2패** | 후보 소스를 고정한 뒤 확인한 새 맵 |
| v2 대 v1, 시드 2000~2009 | 8승 12패 | **12승 8패** | 기존 버전과 직접 비교 |

위 대전은 무승부·몰수 0회였다. 새 맵에서 v2는 Y/K 각각 19승 1패였으며, 관측 최대 응답은 약 47.4ms였다. 직접 비교에서는 Y 5승 5패, K 7승 3패였다. 표본이 한정되어 있어 모든 상대·맵에서 우세하다는 뜻은 아니다. v2의 서버 대전 성적은 아직 확인하지 않았다.

새 맵 결과는 v2 ZIP을 전달한 뒤 완료됐다. 이 결과를 보고 제출 소스를 바꾸지 않았다.

## 채택한 변경

- 거리·건물 가치·배정된 병력 수를 사용하는 팀원 정책을 C++로 옮겨 네 번째 행동 후보와 상대 모델로 추가했다. 원본 팀원 커밋은 `351c32e`이며 코드에 출처를 기록했다. 이동 동률 처리 등의 차이가 있어 Python 원본과 행동이 완전히 같다고 보장하지 않는다.
- 탐색을 기존 3×3에서 **4×4 행동 조합**, 최대 4턴으로 확장했다.
- 평가값의 `tanh` 압축을 제거해 유리한 상태에서도 행동 간 차이를 비교하도록 했다.
- 소유한 공학관의 정책 가치, 회관 가치, 병력과 경제 거점의 평가 가중치를 높였다.

선택된 실험 이름은 `portfolio-assets`다. 10개 후보의 소스와 성적을 보관했다. 단순 전진 강화 후보는 초기 비교에서 악화됐고, 가중치만 변경한 후보는 개발 맵 전체에서 26승으로 개선 폭이 작았다. 현재 제출물에는 가장 좋은 결과를 보인 후보를 사용했다.

대전 결과에는 상대 명령, 시드, 진영, 승패, 종료 사유·턴, 최종 점수, 양쪽 최대 응답 시간을 기록했다. 결과 JSON과 실행 로그의 경기 행이 일치하는지 확인했다.

턴별 명령·상태가 들어 있는 상세 리플레이는 `--save-losses`를 켠 실행에서 패배·무승부만 저장한다. 초기 후보 선별 대전과 승리 경기 전체의 상세 리플레이는 저장하지 않았다. 최종 v2의 새 맵 패배 2경기는 모두 `records/replays/v2-team-holdout/`에 있으며 각 결과 행에도 경로가 있다. 저장된 리플레이의 최종 결과가 경기 결과와 일치하는지 확인했다.

제출 ZIP의 모든 파일은 `submissions/tuned/`와 일치한다. ZIP 검사·컴파일·실행·명령 검사는 통과했고 문제 및 출력 경고가 없었다. 이 로컬 검사는 실제 서버의 자원 격리를 대체하지 않는다.
