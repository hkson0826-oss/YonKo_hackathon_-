# 1차 이후 알고리즘 연구와 채택 기준

확인일: 2026-09-27. 분석 기준은 `jisang`의 `a3c810bfa58472d89396928e0fb6e34e945f20e9`, [v2 소스](../submissions/tuned/main.cpp) SHA-256 `53bb019625fabbbd3aa8a5b65af971912bb4cbdad8a9fde3009fadad5ba6d4c5`다. 외부 연구 결과를 이 게임에서 재현한 문서는 아니다. 아래의 적용 방식과 우선순위는 코드·규칙에 근거한 설계 판단이다.

**우선 제안은 v2의 정확한 전이 모델을 유지하면서 임무 배분·경제 거점 유지·후보 다양성을 개선하고, 다양한 상대를 대상으로 자동 튜닝하는 것이다.** 긴 탐색이나 대형 강화학습부터 붙일 근거는 아직 부족하다. 현재 봇이 못 만드는 행동은 탐색 깊이만 늘려도 생기지 않으며, 잘못 가정한 상대를 더 오래 시뮬레이션하면 오히려 판단이 나빠질 수 있다.

## 1. 이번에 새로 확인한 핵심

- **역할을 자주 바꾸는 문제는 기존 연구에서도 실제 실패였다.** PRHEA 연구는 긴 계획에서 공격·수비 스크립트를 오가는 비효율을 관찰하고, 역할 변경 시점만 따로 표현하는 Sparse PRHEA를 제안했다. 여기서는 복잡한 유전체보다 임무 예약과 변경 비용부터 비교한다. [R5](https://arxiv.org/abs/2104.10429)
- **깊은 탐색이 부정확한 상대 모델을 보완한다고 볼 수 없다.** Ground War 연구에서 RHEA는 틀린 상대 모델에 특히 민감했다. 한 게임·작은 계산 예산의 결과이므로 일반 법칙은 아니지만, 상대 모델이 빈약한 상태에서 깊이를 늘리는 제안의 중요한 반례다. [R6](https://arxiv.org/abs/2006.08659)
- **자기 대전 상대 선택 자체가 최적화 대상이다.** 2L은 프로그램 전략을 합성할 때 탐색 중 얻은 정보를 사용해 유용한 참조 상대를 고른다. 최신 봇 한 개를 이기는 수정만 반복하면 약한 학습 신호와 상성 순환에 빠질 수 있다는 직접적인 근거다. [R11](https://arxiv.org/abs/2307.04893)
- **튜닝 방법은 변수 종류에 맞춰 골라야 한다.** NTBEA는 이산 설정, CMA-ES는 연속 가중치, SMAC3는 조건부·혼합 설정과 여러 문제 인스턴스에 걸친 설정 탐색에 각각 적합한 근거가 있다. 어느 방법도 이 대회에서 비교하지 않았으므로 무작위 탐색을 포함한 동일 예산 대조가 먼저다. [R7](https://arxiv.org/abs/1802.05991), [R8](https://arxiv.org/abs/1604.00772), [R9](https://arxiv.org/abs/2109.09831)

이전 [1차 연구](02-Firecrawl조사.md)의 넓은 후보 목록에서, 이번에는 **실패 조건·현재 코드의 결손·실험 설계**까지 구체화했다. 연구 검색 및 관련 논문 확장 뒤 핵심 본문을 직접 확인했다. 원자료·검증 상태는 [연구 색인](../records/research/round2/README.md)에 남겼다.

### 배정 최적화의 범위

R1의 최적성은 충돌 없이 목표에 도달하는 TAPF 문제의 최소 완료시간에 대한 것이다. 이 게임은 아군 병력이 겹칠 수 있고, 적과 겹치면 전투하며, F/W 생산과 점령 비용을 공유한다. 따라서 논문의 충돌 금지 제약을 그대로 가져오지 않는다.

초기 구현은 F 개수가 적을 때 **F→목표의 작은 배정 문제**로 시작한다. 비용에는 거리, 도착 시 적 위협, 호위 공급 거리, 기존 임무 변경 비용을 둔다. W는 개별 1명 전체 최적화보다 `{차단 1명, 동률 방어, 1명 우세, TELE 한도, 나머지 예비대}` 같은 의미 있는 묶음을 사용한다. 완성된 전체 행동을 공식 전이와 대조한 시뮬레이터로 다시 평가한다. 이 배정이 전역 전략 최적해라는 주장은 하지 않는다.

### 전술 탐색을 넓히는 순서

PGS 계열은 스크립트가 제안하는 행동을 조합한다. R2는 일부 유닛의 행동 제한을 풀어 전술 자유도를 높이며, 기존 PGS의 상대 행동 고정 가정도 본문에 명시한다. 여기서는 **생산 예산·호위·TELE 제약을 지키는 전체 명령 묶음**을 먼저 만들고, 위험한 부대의 부분 변경을 재평가한다.

CMAB의 naive sampling은 개별 변수 통계로 새로운 조합을 탐색하고, 이미 평가한 공동 행동의 통계로 좋은 조합을 선택한다. 독립 통계만으로 최종 조합이 옳다고 결정하는 방법은 아니다. 논문도 매우 적은 계산 예산에서 개별 통계의 신뢰도가 낮다고 지적한다. 당장 모든 병력에 CMAB를 쓰기보다, 중요 부대의 몇 개 결정을 고르는 대조 후보로 둔다.

### CEM/RHEA를 곧바로 주력으로 바꾸지 않는 이유

CEM식 제안은 역할 계획 분포에서 표본을 생성하고 상위 계획으로 분포를 갱신하는 실험 후보다. **이 게임에 적용된 기존 논문의 검증된 알고리즘이라고 표현하지 않는다.** R5의 포트폴리오 RHEA와 S1의 양측 공진화는 인접 근거이며, CEM 변형 검색에서 수집한 S3는 모델 축소·지역해 위험을 검토할 보조 자료다. S3의 본문은 이번에 검증하지 않았다.

가장 먼저 비교할 것은 같은 계산량에서 `고정 style 4턴`과 `역할 유지 + 소수 변경 4턴`이다. 여기서 이득이 보이면 깊이를 늘린다. R6은 부정확한 상대 모델의 영향을 줄이기 위해 깊이만 줄여도 모든 문제가 사라지지 않았음을 보고한다. 상대 다양성과 모델 오류 측정을 깊이 실험과 함께 둔다.

|---|---|---|
| 정책 포함 여부, 역할 유지 턴, F 목표 수, 탐색 깊이 | 무작위 탐색 ↔ NTBEA | 대부분 이산이며 변수 상호작용이 있음 |
| 경제 가치·위험·거리·임무 변경 비용 등 적은 수의 실수 계수 | 무작위 탐색 ↔ CMA-ES | 연속 블랙박스 최적화에 맞는 표현. 범위·스케일 명시 |
| 탐색 종류별로 활성화되는 서로 다른 설정 | 무작위 탐색 ↔ SMAC3 | 조건부 공간과 여러 인스턴스에 대한 racing 지원 |
| 코드 구조·목표 생성 방식 자체 | 증거 기반 별도 후보 작성·제거 실험 | 잘못된 행동 공간은 숫자 조절만으로 해결하기 어려움 |

NTBEA의 적합도 모델은 통계 평균·횟수·분산을 저장한다. 이 테이블은 **오프라인 다음 후보를 고르는 실험 도구**로 사용한다. 제출 봇 안에 학습된 룩업 테이블을 옮기는 제안이 아니다. CMA-ES/SMAC3도 실험용 도구로만 둔다. 설명 가능한 게임 로직 상수의 자동 튜닝과 학습 가중치·테이블 제출의 경계가 불명확하면 실제 제출 전에 운영진 해석을 확인한다.

첫 실험 공간은 모든 상수를 한꺼번에 열지 않고, 공식 패배와 연결된 6~12개 설정으로 제한한다. 계획 예시는 후보 16개를 같은 개발 맵 8개·양 진영·상대 4개에서 비교하는 1,024경기다. 이는 **미실행 예시 예산**이며 실제 경기 처리량 측정 후 줄이거나 늘린다. 중도 탈락 기준은 한 맵 패배가 아니라 같은 맵·진영·상대 묶음의 상대적 결과다. 결승 후보는 별도 선택 맵, 최종 채택은 사용하지 않은 검증 맵으로 비교한다.

공식 최종 순위는 반대 학교 전체 팀과 각 1회 경기한 뒤 승점률, 승률, 상대 승점률 기반 동률 지표 순서다. 따라서 실제 출전 진영인 **Y의 승점률을 주목표**로 삼고, K 대전은 진영 취약점과 일반화 검사로 별도 보고한다. 내부 양 진영 평균만으로 Y 성능 하락을 가리면 안 된다. [공식 규칙](https://yonsei-vs-korea-hackathon.kr/rules)

개발 리더보드의 보정 점수 산식은 현재 확인되지 않았다. 사이트 설명은 상대 실력을 고려한다는 수준이며 최종 점수와 분리해야 한다. 추정식을 공식 점수라고 부르거나 그 추정값만 최적화하지 않는다. 공식 승무패, 상대별·진영별 결과, 최종 점수 차, 경제 거점 유지, 종반, 오류·시간을 함께 남긴다.

## 5. 자기 대전과 AI 수정 순환

1. 공식 패배에서 상태와 당시 합법 관측을 저장한다. 관찰과 원인 가설을 분리한다.
2. v2·팀원 봇·독립 공략형을 버전 고정한다. 정책 난수와 맵 난수를 분리한다.
3. 한 후보에는 한 구조적 가설을 우선 반영한다. 예: `경제 거점 수비 예약` 또는 `F+W 도착 시각 정렬`.
4. 빠른 반례 검사 후 여러 상대·양 진영 대전을 진행한다. 실패한 후보도 해시와 기각 이유를 남긴다.
5. 새로 발견한 공략형을 상대 집단에 추가한다. 모든 약한 상대를 없애면 상대 다양성을 잃을 수 있으므로 전체 집단 탐색 비중을 유지한다.
6. AI는 경기 지표와 턴 증거를 읽고 다음 후보를 만든다. 실행 중인 후보 소스는 변경하지 않는다.
7. 보류 맵까지 보고 수정했다면 그 맵은 개발 집합으로 옮긴다. 새 후보는 새 검증 맵이 필요하다.

이는 PSRO·2L에서 얻은 운영 원리를 코드 후보에 적용한 제안이다. 현재 프로젝트에 완전한 PSRO 학습기나 2L 합성기가 구현되었다는 뜻은 아니다. 유한한 상대 집단의 균형도 미지 참가자에 대한 최적성 증명이 아니다.

## 6. GPU 연구의 역할과 한계

사용자가 정정한 자원은 **RTX 3090 최대 8개**다. 실제 VRAM·원격 접속·CPU/RAM·사용 시간은 아직 확인되지 않았다. 이번 연구에서 GPU 학습을 실행하지 않았다.

- **바로 할 수 있는 일:** CPU 경기 병렬 실행, 실패 상태 수집, 배정·탐색·튜닝 비교. 이는 GPU 수와 별개다.
- **GPU가 기여할 후보:** 합법 관측에서 행동·가치를 학습하는 연구 상대, 여러 독립 학습 seed, 배치 추론, 어려운 상대·전술 탐색. 먼저 단일 장치의 처리량과 CPU 환경 병목을 측정한다.
- **제출 경로:** 연구 모델이 발견한 전술을 사람이 읽을 수 있는 명시적 계획으로 구현하고, 실제 C++ CPU 봇에서 별도로 검증한다. 모델 성능이 좋아졌다고 제출 봇 성능이 개선된 것은 아니다.

R12의 oracle imitation은 실제 환경 전체 상태를 아는 교사와 부분 관측을 보는 학생을 구분한다. 이 프로젝트의 학습 입력에는 당시 합법 관측만 사용한다. 숨은 실제 점수를 교사에게 공개하는 특권 실험은 별도 상한선 연구로 표시해야 하며, 그 행동을 정상 봇의 재현 가능한 판단으로 간주하면 안 된다. 현재 단계에서는 특권 교사보다 합법 관측의 깊은 탐색을 먼저 비교한다.

S2의 프로그램 sketch 학습은 흥미로운 인접 방법이지만, **신경망을 결정트리·소스 배열로 바꿨으므로 규칙상 허용된다는 논리는 성립하지 않는다.** 자동 증류된 가중치·룩업·정책의 제출은 현재 경로에서 제외한다. 연구용 반례와 명시적 게임 로직 개선을 우선한다.

## 7. 우선순위와 폐기 기준

| 순서 | 할 일 | 채택·보류 판단 |
|---|---|---|
| P0 | 공식 규칙·리플레이·시뮬레이터 정합성, 합법 관측 확인 | 규칙 오류는 튜닝으로 덮지 않음. 반례·차등 검사 통과 후 진행 |
| P1 | 역할 예약, 경제 거점 수비, F/W 도착 정렬, 종반 점수 범위 | 공식 실패와 연결되는 지표 개선 및 새 맵의 주요 상대군 회귀 확인 |
| P2 | 전략이 다른 독립 상대 추가, 작은 설정 공간 자동 튜닝 | 무작위 탐색 대비 같은 예산에서 더 좋은 후보를 찾는지 확인 |
| P3 | 중요 부대 국소 탐색, 상대 후보 확대, 작은 RHEA 대조 | 동일 시간 예산의 기준선보다 개선되고 최대 응답 시간 여유가 있는지 확인 |
| P4 | 1개 GPU 연구 상대 → 효과 확인 후 여러 장치 | 연구 상대가 새로운 실패를 찾고, 실제 제출 가능한 수정으로 이어질 때 확대 |

P1 수정들이 반복적으로 새 상대에서 회귀하거나 임무 배분 구조가 반례를 표현하지 못하면, 현재 포트폴리오에 계수를 더 붙이지 않고 **목표·시간·호위 묶음을 중심으로 하는 새 후보 생성기**를 별도로 작성한다. 그 경우에도 v2를 고정 기준선으로 남긴다. 최적 알고리즘이나 우승은 보장할 수 없으며, 위 우선순위의 목적은 측정 가능한 다음 개선을 만드는 것이다.
