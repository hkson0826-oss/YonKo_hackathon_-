빌드 상세에는 소스 검증·이미지 조립 완료와 프로토콜 smoke 대기 문구가 함께 남아 있었다. 그것을 최신 경기 실행 결과로 해석하지 않는다. 이후 상급 10전과 공식 5경기의 실행 결과는 별도 근거다. [제출 이력](https://yonsei-vs-korea-hackathon.kr/submissions), [모의 전투](https://yonsei-vs-korea-hackathon.kr/practice)

## 보정 점수와 최종 순위는 별도다

개발 리더보드 도움말은 일부 상대와의 결과에 상대 실력을 반영한다고 설명한다. 정확한 수식, 정규화·사전값·반올림 방법, 경기 내 점수 차 반영 여부는 공개된 설명에서 확인되지 않았다. **61.0%는 우리 단순 승률 80%와 같은 값도, 최종 승률의 확인된 예측값도 아니다.** 보정식을 임의로 역산해 튜닝 목표로 사용하지 않는다. [대회 결과와 도움말](https://yonsei-vs-korea-hackathon.kr/leaderboard)

공식 운영 규칙에 따르면 개발 참고 순위는 최종 순위에 반영되지 않는다. 최종은 등록 진영을 유지하고 **반대 학교 모든 팀과 각각 한 번** 경기한다. 최종 순위의 비교 순서는 다음과 같다.

1. 승점률: `(승리 수 + 0.5×무승부 수) / 전체 경기 수`.
2. 승률: `승리 수 / 전체 경기 수`.
3. 상대 기반 동률 지표: `(이긴 상대들의 승점률 합 + 0.5×비긴 상대들의 승점률 합) / 전체 경기 수`.
4. 여기까지 같으면 공동 순위. 상위 7팀 경계의 동률은 같은 최종 코드·등록 진영과 새 맵으로 별도 결정전.

한 팀만 실행 오류가 나면 그 팀의 몰수패, 두 팀 모두 오류가 나면 무승부다. 학교 대항 결과는 상위 7팀에 더 많이 들어간 학교로 정하며 개인상과 구분한다. 위 3번은 **최종 동률 지표**이며 개발 보정 점수와 동일하다고 확인된 산식이 아니다. [공식 운영 규칙](https://yonsei-vs-korea-hackathon.kr/rules)

우리의 평가 주목표는 **Y 진영에서 다양한 상대에 대한 승점률**이다. 양 진영 대전은 여전히 맵·정책 취약점을 찾는 데 필요하지만, K 결과를 합쳐 Y의 회귀를 감추면 안 된다. 점수 차·점령-턴·전사 수·경제 거점 유지 시간은 원인을 진단하는 보조 지표다. 특히 이번 패배는 누적 점령 점수가 앞섰어도 마지막 건물 점수에서 졌다.

## 일정과 참여 요건

모든 시각은 KST다. 상세 운영 규칙의 일정이 대시보드의 일반 안내인 ‘추후 안내’보다 구체적이다.

| 날짜 | 코드 반영 마감 → 공개 |
|---|---|
| 9/27 | 20:00 → 22:00 |
| 9/28~9/30 | 08:00 → 10:00, 20:00 → 22:00 |
| 10/1 | 08:00 → 10:00, 마지막 리더보드 15:00 → 17:00 |
| 10/1 | **23:00 새 ZIP 업로드 종료** |
| 10/1 | **23:59 최종 코드 선택·보고서 제출 종료** |
| 10/2 | 08:00 최종 결과 공개 예정 |

업로드만으로 대회 사용 코드가 바뀌지 않는다. 이전 선택은 변경 전까지 유지된다. 검사 중 코드 선택은 경고와 함께 가능하지만 실패 시 이전 코드로 자동 복구되지 않는다. 최종 선택이 없거나 사용할 수 없으면 몰수패다. [운영 규칙](https://yonsei-vs-korea-hackathon.kr/rules)

모의 전투 한 번은 등록 진영에서 서로 다른 맵 10경기다. 수료 전투 기준은 **중급 한 회차에서 6승 이상**이고 무승부는 승리에 포함되지 않는다. 현재 보이는 테스트 이력 4건은 하급 1건·상급 3건이며, **중급 기록은 확인되지 않았다.** 상급 전승이 중급 요건을 자동 대체한다고 가정하지 않는다. 다음 사용자 테스트에서 중급 한 회차도 확인할 항목이다. 모의 전투는 리더보드·최종 순위와 별개다.

보고서는 PDF이며 100점: 전체 전략 15, 병종 전략 20, 지역·건물 20, 개발 과정 30, 회고 5, 완성도 10이다. LLM 사용은 허용되며 모델·프롬프트·목적·범위를 남겨야 한다. 이번 근거→가설→비교→채택·기각 기록은 개발 과정 항목의 자료가 된다. [공식 보고서 양식](https://yonsei-vs-korea-hackathon.kr/downloads/report-template-20260927.docx)

같은 팀 구성원의 협업과 달리 경쟁 팀 사이 코드·전략·제출물 공유는 금지다. 외부 공개 라이브러리·예제와 LLM 활용은 허용 범위를 따르며 출처를 보존한다. 대회 중 게임·밸런스는 변경하지 않는다고 안내한다. 이 문서는 운영팀에 질의를 보내거나 타 팀에 연락한 기록이 아니다.

## 최신 웹에서 재확인한 실행·제출 제한

| 항목 | 공식 값 |
|---|---|
| 실행 | CPU 전용, GPU 불가 |
| 언어 | C++20/GCC 12.2.0, Python 3.12.14/NumPy 2.3.3 |
| 턴 시간 | 첫 턴 3000ms, 이후 300ms. 입력 전송·시작부터 `END` 수신 완료까지 |
| 메모리·경기 | 384MiB, 경기 전체 최대 3분 |
| ZIP | 압축 5MiB, 해제 20MiB, 최대 200개 파일 |
| 파일 | 소스·헤더·모듈 허용, 임의 데이터·학습 가중치·실행 파일 금지 |
| 출력 | 턴 stdout 64KiB·4096줄, 한 줄 1KiB, 경기 stderr 1MiB |
| 기타 | 프로세스 32개 제한, 네트워크·파일 쓰기·추가 실행 제한 |

GPU는 오프라인 연구용이다. 학습 가중치를 배열이나 다른 소스 표현에 숨겨 제출하는 경로는 채택하지 않는다. 연구 모델이 찾아낸 전술을 명시적인 C++ 규칙으로 구현하고 별도 성능 검사를 통과시키는 계획은 [GPU 실험 계획](11-GPU실험계획.md)에 정리했다. [공식 개발·제출 상세](https://yonsei-vs-korea-hackathon.kr/rules)

게임은 15×15, 160턴, 동시 행동이다. 생산→이동→전투→효과→수입→점령→공개→종료 판정 순서와, 소유 F 사망 시 즉시 중립화·적 건물 2단계 점령·당일 할인 소유권 참조 시점·대칭 점수 추론은 [기존 전체 규칙 정리](01-대회규칙과제출.md) 및 배포 엔진과 함께 확인했다. 웹 설명과 이번 분석에 필요한 핵심 전이 규칙 사이의 차이는 발견하지 못했다. 이 확인이 모든 서버 구현과 로컬 엔진의 바이트 단위 동일성을 보장하지는 않는다.

구조화된 관찰·경기 ID는 [site-observations.json](../records/official/round1/site-observations.json)에 보존했다. 로그인 정보·이메일·임시 서명 다운로드 URL은 기록하지 않았다.
