# 1차 이후 제안: 임무 배정과 국소 동시 행동 탐색

기준: 공식 1차 5경기, 최신 사이트 규칙, v2 소스, 팀원 변경 비교, Firecrawl 원문 조사, CPU 처리량 측정. **다음 후보의 구현 명세와 검증 계획이며, 새 봇의 승률 검증 결과가 아니다.** 현재 제출 추천은 검증된 `artifacts/submission-v2.zip`을 유지한다.

## 판단

v2는 확장·기초 경제·전이 계산이 작동한다. 공식 4승, 상급 10승, 기존 독립 팀원 상대 성적이 근거다. 그러나 네 개의 전체 정책만 고르는 구조는 ‘F 한 명을 방어 경합에 쓰기’, ‘공학관 한 곳의 생산 혜택을 계속 지키기’, ‘공격 부대 일부만 남기기’를 충분히 표현하지 못한다. 이 상태에서 계수와 탐색 깊이만 늘리는 것은 한계가 있다.

따라서 다음 주력 후보는 **정확한 전이 모델은 재사용하고, 행동 생성기를 임무 단위로 바꾸는 설계**다. 위험 거점에만 F/W 공동 배치 후보와 동시 행동 탐색을 사용한다. 모든 모듈을 한 번에 교체하지 않고 아래 순서대로 기준선과 비교한다. 분석을 마쳤다는 이유만으로 새 설계가 v2보다 강하다고 결론내리지 않는다.

근거: [패배의 턴별 분석](07-공식1차경기분석.md), [8개 접근의 장단점과 원문](08-다양한접근과근거.md), [공식 평가 목표](10-사이트운영과보정점수.md).

## 후보의 한 턴

1. **합법 관측 갱신.** 공개 점수와 알려진 대칭쌍만 확정한다. 미공개 점수는 가능한 범위를 유지한다. 현재 자원·생산 위치·TELE·점령 비용을 각각 예약한다.
2. **위협과 임무 생성.** 건물별로 1~3턴 도착 가능한 F/W, 적 생산과 TELE 가능성을 확인한다. `획득`, `적 점유 중립화`, `우리 점유 방어`, `F 경합`, `호위`, `공학관 유지`, `예비대`를 후보로 만든다.
3. **작은 공동 배정.** F→목표 비용은 거리·점수·경제 혜택·위협·호위 도착·임무 변경 비용을 반영한다. W를 의미 있는 묶음으로 배정하고 생산 위치까지 포함한다. 수비에 F가 필요 없는 경우와 필요한 경우를 구분한다.
4. **필요한 곳만 행동 확대.** 위험한 거점 2~4개 주변에서 잔류·합류·분할·한 칸 이동·철수·F 경합 조합을 만든다. 후방의 단순 이동은 기존 스크립트를 사용한다.
5. **동시 행동 대조.** 상대 확장·공학관 압박·재점령·집중 공격·종반 중립화 후보와 우리의 전체 합법 명령 묶음을 정확한 전이로 비교한다. 제한된 후보에서의 강건한 선택이며 전체 게임 균형이나 최적해는 아니다.
6. **완료한 최선 행동 출력.** 시간 예산을 넘기기 전에 탐색을 중단하고 이미 검증·완료한 명령을 반환한다. 예산 소진 시 무조건 특정 기본 정책으로 되돌리는 방식과 비교한다. 선택 임무와 핵심 평가 근거를 오프라인 로그에 남긴다.

공학관 가치는 건물 점수에 상수를 크게 더하는 것보다 **남은 기간에 실현 가능한 W 생산 절약**으로 평가한다. 예상 생산 자원 B라면 한 턴의 단순 비교는 `floor(B/2)-floor(B/3)`명이다. 점령 유지 가능성·증원 거리·다른 자원 사용·남은 턴으로 할인해야 한다. 공학관 2개의 할인은 중첩되지 않으므로 두 번째 건물의 가치는 백업·적 할인 차단·점수다.

임무는 0/2/4턴 유지 설정부터 비교한다. 위험 변화, 도착 불가, 대상 가치 급변, 더 높은 우선 방어 요구가 생기면 즉시 해제한다. 계속 유지하는 것 자체가 목적은 아니다. 임무 변경 횟수와 목표까지 거리 감소를 함께 측정한다.

최종 평가에서는 실제 승패·동률 순서를 먼저 유지한다. 점수 차는 같은 승패 예측 안의 보조 비교값으로만 사용한다. 미공개 점수로 추정한 승리를 확정 승리처럼 rollout 중단에 사용하지 않는다. 가능한 점수 범위에서 승패가 갈릴 때만 더 많은 점수 시나리오를 평가한다.

## 스스로 확인한 약점과 대응

| 설계의 약점 | 그대로 적용하면 생길 실패 | 대조·중단 기준 |
|---|---|---|
| 수비 예약이 공격을 줄임 | 경제를 지키다 중앙 점수와 승기를 내줌 | 공격형·분산형 상대로 Y 승점률과 점령 시점 비교. 유지시간만 늘고 승률이 줄면 기각 |
| 임무의 관성 | 상대가 바뀌었는데 목적지를 고집함 | 예약 해제 유무를 분리 검사. 왕복·목표까지 순진도·F 사망 기록 |
| 선형 배정은 F/W 결합을 놓침 | 따로는 좋은 목표지만 같이 못 도착함 | 공동 도착 후보를 평가. 작은 반례에서 배정 전체를 열거해 비교 |
| 적 도착 최대치를 건물마다 독립 가정 | 같은 적이 여러 곳을 동시에 공격한다고 보아 과도하게 수비함 | 실제 양립 가능한 상대 명령 묶음으로 전이 평가 |
| 제한된 상대 후보의 오차 | 긴 탐색일수록 오차 누적 | 독립 상대·새 공략형을 유지하고 깊이 증가와 상대 모델 확대를 분리 |
| 최악 점수만 사용 | 이길 공격도 회피함 | 범위 최악·기대·혼합을 같은 관측에서 비교. 확정/불확실 종료 분리 |
| 임무·후보 조합 증가 | 300ms 또는 384MiB 초과 | 후보 수·전이 수 상한, 전술 중요도 순 확장. 독립 CPU 검사와 서버 테스트 |
| 공식 한 패배에 과적합 | 알려진 방송국만 지키고 다른 맵에서 퇴보함 | 해당 맵은 개발 사례로만 사용. 새 맵과 다른 전략 상대 검증 |

역할 예약과 국소 수정을 해도 같은 배정 실패가 반복되면 네 정책 포트폴리오를 더 늘리지 않는다. **F 목표·W 수비 묶음·생산 위치를 함께 선택하는 새 행동 생성기**를 별도 후보로 만들고 v2와 같은 계산 예산에서 비교한다. 전체 엔진·프로토콜까지 새로 작성할 필요는 없다.

## 구현·실험 순서

| A | v2 선택 정책·예산 중단·평가 로그를 로컬 분석 모드로 추가 | 관측→명령, 선택 정책, 시간·전이 수 | 출력 프로토콜·행동 불변 검사, 로그 용량 제한 |

| B3 | 공동 도착·임무 예약 | 호위 부족·목표 전환·종반 보유 | B1/B2와 분리한 기여 확인 |

다음 후보의 우선 핵심은 **B1/B2**다. 관측 가능한 반례와 생산 격차가 있고 구현 범위도 작다. 세부 GPU 파일럿은 [별도 계획](11-GPU실험계획.md)을 따른다.

## 벤치마크를 더 어렵고 유용하게 만들기

서버 상급 10승은 실행과 기본 전략을 확인하는 지표로 유지한다. 후보 선택에는 다음 상대 집단을 쓴다.

- 고정 v1, 고정 v2, 팀원 원본: 기존 성능·회귀 기준.
- 독립 공학관 압박형: 할인 박탈과 생산을 우선.
- 재점령·F 경합형: W 동률일 때 F를 함께 넣고, 빈 건물은 2턴 계획.
- 집중 공격형·분산 중립화형: 두 방향의 취약성을 검사.
- 종반 점수형: 남은 거리·점령 단계에 맞춰 생산과 점령 임무 전환.
- 새로 발견되는 공략형: 버전을 보존하고 최신 모델과 별개로 계속 평가.

위 독립 공략형들은 **구현 예정 목록**이다. 공식 상대의 비공개 코드를 복제했다고 주장하지 않는다. v2 강제 정책만으로 이 목록을 채우면 코드의 공통 맹점을 공유하므로 독립적인 규칙 기반 구현을 최소 2개 추가한다. 팀원 최신 브랜치와 main 새 ZIP의 내용은 [팀원 변경 검토](09-팀원변경검토.md)를 참조한다.

개발 시드는 기존 분석 맵과 4000/4001을 포함한다. 맵 seed와 정책 난수 seed는 별도로 기록한다. 새 선택·검증 시드는 실행 전에 목록과 해시를 고정한다. 같은 맵을 작업자 수만 바꿔 반복한 CPU 12회 실행은 새로운 12개 성능 표본이 아니다.

첫 구조 비교는 후보·상대 1조합당 개발 맵 8개×양 진영 16경기부터 시작한다. 명백한 오류가 없고 유망한 후보만 선택 맵 32개 이상으로 확대한다. 최종 비교는 사용하지 않은 맵·상대에서 수행한다. **8개나 32개로 충분한 통계적 확신을 보장하지 않는다.** 차이가 작으면 표본을 늘리거나 기존 v2를 유지한다.

보고값은 상대별 Y 승점률, K 진영 진단, 맵별 대응 결과 차이, 맵 단위로 묶은 불확실성 구간, 몰수·최대 및 P95/P99 응답 시간이다. 같은 맵의 양 진영·여러 상대·반복 난수를 모두 독립 경기로 취급해 구간을 좁히지 않는다. 내부 상대 분포가 실제 참가자 분포와 다르다는 한계도 남긴다.

## 기록과 완료 상태

실행별로 `records/benchmarks/<run-id>/`에 계획·소스 해시·상대·시드 목록·전체 요약·오류·손실 및 대표 승리 리플레이를 둔다. AI는 완료된 실행의 근거를 읽고 다음 소스 버전을 수정한다. 진행 중인 코드·설정은 덮어쓰지 않는다. 대전 행렬에는 이전 강한 상대와 새 공략형을 함께 둔다.

이번에 완료한 것은 공식 5경기 분석·반례 검사, 사이트 운영 확인, 8계열 문헌 비교, 팀원 변경 비교, CPU 처리량 실측, GPU 계획이다. 새 전략 구현·대규모 튜닝·GPU 학습은 아직 실행하지 않았다. 기존 제출 ZIP과 봇 소스는 변경하지 않았다.

작업은 `jisang`에 기록한다. `main`은 다음 검증된 제출물과 필요한 공유 기록만 별도 반영한다. 로컬 운영 규칙 `AGENTS.md`는 공유하지 않는다.
