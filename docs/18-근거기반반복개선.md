# v2 패배 분석에서 시작하는 반복 개선

2026-09-28. [첫 대규모 리그](17-다양한후보리그결과.md) 다음 작업이다. 목표는 기존 v2의 패인을 더 정확히 구분하고, 코드 개선과 다른 행동 생성·탐색 방식을 실제 평가 결과로 다시 수정하는 것이다. 실행 전 계획이며 결과는 완료 배치마다 별도 기록한다.

## 사전 평가와 반복 순서

설계에 임의로 10점을 주어 우승을 보장하지 않는다. 아래 항목을 모두 통과하면 **대전 가능한 후보**로 분류한다. 제출 승격은 별도의 새 맵 검증 결과로 판단한다.

1. 바꾸려는 실패의 관측·턴·원본 경로가 있다.
2. 코드의 원인 가설과 미확인 인과를 구분한다.
3. 공식 전이·합법 관측을 지킨다.
4. 적용한 논문 아이디어와 생략한 부분을 밝힌다.
5. 기존 코드 개선과 독립적 대안을 함께 비교한다.
6. 자신의 실패 조건·예상 회귀를 구체적으로 적는다.
7. 관련 규칙 반례와 합법 명령 검사를 통과한다.
8. 컴파일·시간·출력 프로토콜을 검사한다.
9. 변경 소스·설정·상대·맵을 고정한다.
10. 평가 후 수정·폐기 기준과 다음 검증 맵을 정한다.

**설계 → 자체 비판 → 반례 검사 → 첫 대량 개발 대전 → 실패 분석 → 실제 코드 수정 → 두 번째 대전 → 새 선택·최종 검증** 순서로 진행한다. 같은 후보를 반복 실행한 것을 코드 개선 루프라고 부르지 않는다. 수정 전후 ID와 해시, 근거, 성적을 연결한다. 다음 배치에서 고칠 수 없는 원천적 문제가 드러나면 해당 접근을 폐기하고 이유를 남긴다.

## 세 접근

| 계열 | 첫 구현의 초점 | 사전 약점 |
|---|---|---|
| v2 원인 분리 | F 수비·경합, 종반 점령 단계, W 잔여 병력 배분, 우리 정책만 수정 | 국소 반례 해결이 전체 승리로 연결되지 않을 수 있음 |
| 공동 임무 배정 | F 목적지·같은 턴 W 호위·생산 위치·충족 후 잉여 배분 | 위험 과소평가·분산 패배, 단기 경매의 목표 흔들림 |
| 행동 조합 탐색 | 병종·일부 출발지의 정책 혼합, 완료한 최선 행동 보존, 상대 예측 | 계산량, 혼합 명령 충돌, 틀린 상대 모델에 대한 과신 |

정확한 후보별 사전 검토는 `records/league/loop2-design/`에 남긴다. 기존 [문헌 검증](../records/research/round2/README.md)을 재사용하며 새로운 주장은 필요한 원문을 추가 확인한다. 공식 상대 코드가 없으므로 한 턴 대체 행동을 전체 공식 경기 승리 재현이라고 주장하지 않는다.

## 비교 조건

- 첫 개발: 7000–7007의 8개 맵, 양 진영. 수정 후 개발: 7100–7107의 새 맵.
- 고정 상대: v2, 팀원, 이전 결합 수비, 공동 도착 호위, 종반 평가 후보. 지난 리그에서 전부 진 약한 직접 공략형 3개는 주 평가에서 제외한다.
- 최종 배치에서는 개발 상위·다양성 후보 6개와 v2를 7200–7215에서 선택한다. 주 후보와 보조 후보를 고정한 뒤 7300–7363의 64개 미사용 맵에서 검증한다.
- 주목표는 Y 승점률이다. K·상대별 결과·점수·생산·집중도·응답 시간을 별도로 본다. 병력 집중도는 정체의 보조 지표이며 정상적인 집중 공격도 높게 나올 수 있다.
- 주 후보만 승격 가능하다. Y 개선 3%p 이상, 맵 단위 bootstrap 95% 하한 양수, 어느 상대에서도 Y 회귀 10%p 초과 없음, 기준선·후보 오류·몰수 0을 모두 요구한다. 보조 후보를 사후 선택하면 새로운 최종 검증이 필요하다.
- 같은 소스 해시의 중복 설정은 제외한다. 기존 원본과 제출 ZIP을 보존한다. **모든 경기 리플레이**를 저장해 기준선 승리도 대응 분석할 수 있게 한다.

공유 CPU 서버는 16개 worker부터 사용하며 기존 CPU·RAM 90% 상한과 TMP 실행·결과 회수·프로세스 정리를 유지한다. 패키지가 필요하면 TMP 격리 환경에 설치하고 제거한다. 각 배치는 새 경로·소스 커밋으로 실행하고 `jisang`에 단계별 커밋·푸시한다.

첫 배치 명령:

```bash
python3 experiments/run_remote_tmp.py --host yonsei-root \
  --output-dir records/league/loop2-iteration1 \
  --command python3 experiments/iterative_campaign.py \
  --arena output --phase explore --seed-start 7000 --maps 8 --workers 16
```

두 번째 배치는 첫 결과를 읽고 수정한 다음 실행한다. 시작 전 후보 ID 목록을 명시하고 `--phase final --revision 2 --seed-start 7100 --selection-start 7200 --holdout-start 7300`을 사용한다. 기존 후보 소스 해시는 유지하고 새 수정은 별도 ID로 만든다. 이번 검증까지 읽은 뒤 추가 수정하면 7300–7363은 더 이상 미사용 맵이 아니다.

## 첫 평가와 실제 재수정

첫 배치는 [2,058경기](../records/league/loop2-iteration1/README.md)를 완료했다. 개발 Y는 v2 16/40, 자유 이동을 포함한 국소 탐색 33/40, 공동 배정 포트폴리오 31/40, 좁은 수비 위협 범위 30/40이었다. 8개 맵에서 후보를 고른 결과이므로 아직 제출 승격은 아니다. 공격적 공동 배정 단독은 5/40, 종반 목표 가치 할인 단독은 14/40으로 후속 확대에서 제외했다.

이후 같은 코드를 재실행하는 데 그치지 않고 **새 후보 12개**를 만들었다. 기존 24개 생성 소스의 해시는 모두 보존했다. [두 번째 후보 목록·검사·맵 고정](../records/league/loop2-design/iteration2-plan.json).

| 개정 계열 | 실제 실패에서 확인한 근거 | 구현한 대조 |
|---|---|---|
| v2 원인 분리 | 7002/154턴 F 한 명의 대체 이동으로 19:22→19:18 가능. 전체 승리 증명은 아님 | 즉시 F 경합·중립화 후보를 초기 행동에서 재평가. 평균/최악 상대 평가·수비 예약을 분리 |
| 공동 배정 | 초반 F 동일 방향 집중, F 과잉·유휴, 호위 W가 멈춘 F와 다른 곳으로 감 | 새 정책의 초반 적용 지연, F 생산 상한, 막힌 F의 다음 칸으로 W를 보내는 경유점 호위 |
| 국소 탐색 | 7001/34턴 무조건 F 잔류는 악화. 160턴 대기는 3점 회복. 평가값만 고친 후보는 실제 행동을 못 바꿈 | 점령·위협 출발지 우선, F/W·대기 분리 후보, 종반 평가만의 대조, 상대 적합도·혼합 역할 유지 대조 |

각 근거와 반증은 [v2 개정](../records/league/loop2-design/v2-forensics-iteration2.md), [공동 배정 개정](../records/league/loop2-design/joint-allocation-iteration2.md), [탐색 개정](../records/league/loop2-design/adaptive-search-iteration2.md)에 있다. 일부 사례는 실행 중 회수한 편향된 패배 표본이므로, 전체 첫 배치 성적을 다시 읽고 확대·제외 판단을 보완했다.

두 번째 배치는 기존 유망 후보·대조군 9개와 신규 12개, v2를 비교한다. 예정 경기는 4,892개다. 개발 1,760경기 이후 별도 선택 1,120경기, 사전에 고정한 두 후보와 v2의 최종 검증 1,920경기, 실행 검사·상호 대전을 포함한다. 두 배치 합계 예정은 **6,950경기**다.

## 개선 이유와 추가 반증

[대응 승리 두 쌍의 검사](../records/league/loop2-design/v2-gain-analysis.md)는 640턴을 공식 엔진으로 재현했다. 7001 맵에서 먼 F를 향한 불필요한 거점 수비 목표 제거가 실제 W 경로 변경과 연결됐다. 공학관 할인은 양쪽 153턴으로 같았지만 후보의 본관 수입이 294자원 더 많았다. 한 명의 첫 이동이 최종 승리의 단일 원인이었다고 단정하지 않으며, 집중도가 높아도 이긴 사례가 있어 무조건 분산하는 규칙도 채택하지 않는다.

기존 고정 상대가 v2 구조를 많이 공유한다는 약점을 확인해, 최종 결과가 나오기 전에 [교차 계열 추가 감사](../records/league/loop2-design/cross-family-audit-plan.md)를 고정했다. 최초 잠금 주 후보와 v2를 이번 공동 배정·자유 행동·종반 탐색 등 6개 상대, 새 맵 32개에서 768경기 비교한다. 기존 최종 검증을 대체하지 않고 추가 회귀 검사로 사용한다. 컴파일 뒤 경기 프로세스에는 384MiB 주소공간 제한을 적용한다.

제출 승격 후보가 나오면 [제출 준비 검토](../records/league/loop2-design/submission-readiness-review.md)에 따라 실제 대전한 동결 소스를 포장한다. 전 경기 출력량·ZIP 멤버·해시·SDK 경고까지 검사하며 GCC 버전과 실제 플랫폼의 차이는 따로 밝힌다.

두 번째 개발·선택을 완료한 뒤 `a_v2_terminal_local`을 주 후보로 잠갔다. [독립적인 소스·성적 비판](../records/league/loop2-design/locked-primary-review.md)은 부모와 240경기 승무패가 같았다는 점, 세 출발지·병종 전량 이동·네 상대 정책·협력적 시간 중단의 한계를 기록했다. 최종 검증 결과는 이 선택에 사용하지 않았다.

방어 범위 축소의 새 맵 회귀와 공동 F/W 방어의 차이는 [두 번째 대응 분석](../records/league/loop2-design/iteration2-guard-analysis.md)에서 960개 공식 전이로 확인했다. 최초 분기의 실제 상대는 공격하지 않았으므로 실현된 구출이라고 주장하지 않는다. 별도의 합법적인 가상 공격에서 공동 방어의 규칙상 기능을 검증했다.
