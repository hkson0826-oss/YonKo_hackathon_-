# s3 단일 후보의 새 맵 확인

2026-09-28 KST. 앞선 `f3_v2_warrior_reserve`는 추가 32맵에서 실패했으며 그 실행의 추천은 **v3 유지**다. 이 결론은 변경하지 않는다. 기존 후순위의 소스를 수정하지 않고 별도 실행 ID에서 한 차례만 검증한다. 사용자가 요청한 지속 개선과 오전 8시 마감에 맞춘 마지막 사전 계획이다.

## 선택과 고정

새 주 후보는 `s3_v2_screen_paired_guard`, SHA-256 `1703701340ede10b652b0aa024e29c3fd411e2809ae34de1e3d0b39620d496df`다. 비교 기준은 현재 제출물 v3, SHA `52268569e17d7fc40fd46f0996b2da684768902b4af27ec059c4b068911c4473`다. 신경망이나 새 파라미터 조정은 없다. 원래 선별 탐색에서 네 상대 모델 각각에 대한 비악화 조건을 적용한 후보다.

이 후보는 앞선 선택·80맵 holdout 등 **이미 본 자료로 골랐다.** 그 성적을 이번 독립 검증 성적으로 다시 세지 않는다. 새 맵 결과를 보고 다른 후보로 바꾸거나 같은 후보의 추가 실행으로 실패를 구제하지 않는다. 이 확인도 실패하면 현재 v3를 유지한다. 원래 실패한 실행과 이번 실행의 기록·판단을 구분한다.

상대 9종은 v3, v2, teammate, a_v2_tactical_local, j_balanced_portfolio, j_v2_reclaim_relay의 고정 6종과 s3_selective_contact, r3_opponent_league, f3_v2_warrior_reserve의 추가 3종이다. 마지막 f3는 기존 80맵에서 강점을 보인 참고 상대이며, 추가 검증 실패를 숨기거나 검증된 제출물로 취급하지 않는다. 전부 소스 해시로 고정한다.

## 통과 조건

기존 조건을 완화하지 않는다. 본 확인은 완전한 paired 일정과 오류·몰수0, 전체 및 고정군 Y 개선≥3%p와 맵 bootstrap95% 하한>0, 추가군 Y 비회귀, 상대별 Y 회귀≤10%p, 전체 K 회귀≤5%p, v3 직접 양진영 승점률≥50%, 교차 대전의 후보·v3 정상 실행을 모두 요구한다. 소스와 조건은 첫 새 맵 실행 전에 잠근다.

추가 감사는 완전한 일정·정상 실행, 전체·고정군·추가군 Y 비회귀, 상대별 Y 회귀≤12.5%p를 모두 요구한다. 본 확인이 실패하면 추가 감사나 새 ZIP 생성으로 넘어가지 않는다. 상대 9종의 결과를 분리해 보고하며, bootstrap은 맵 단위5,000회로 기존과 동일하다. 순차적으로 여러 후보를 조사했다는 선택 편향과 제한된 내부 상대군의 한계는 최종 보고에도 남긴다.

둘 다 통과하면 같은 고정 소스로 새 ZIP을 만들고, 실제 추출본을 TMP GCC12.2로 빌드해 384MiB 주소공간·일반턴300ms·첫턴3000ms 아래 SDK 및 CPU 검사를 한다. 두 원격 실행의 전 경기 리플레이·소스 해시 검증과 독립 TMP 정리 확인도 필수다. 기존 v3 ZIP은 보존한다.

## 자원·기록·마감

`ssh yonsei-root`의 전용 `/tmp`에서 workers24, 52개 중 최대46개 CPU 범위(88.46%), 컴파일 프로세스768MiB/대전384MiB 제한을 사용한다. 본 확인 상한5400초, 추가 감사3600초다. 기존 부하·가용 메모리를 시작 때 다시 확인하며 전역 패키지나 설정은 바꾸지 않는다. 원본을 회수하고 검증한 뒤 자기 TMP·자식 프로세스를 정리한다.

실행 경로는 `records/league/loop3-s3-confirmation`, 추가 감사는 `records/league/loop3-s3-audit`다. 모든 코드는 `jisang`에 커밋·푸시해 고정하고, main에는 확정 제출물과 필요한 요약만 공유한다. 오전7시15분 이후 새 실험은 시작하지 않으며, 오전8시 제출은 사용자가 진행한다.
