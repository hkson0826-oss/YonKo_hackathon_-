## 남은 약점과 판단 범위

- 본 확인에서 `s3_selective_contact` 상대 Y 승률은 58/128, **45.31%**다. 전체 평균이 개선돼도 이 상성은 우세하지 않다.
- 감사 Y에서 `r3_opponent_league` 상대는 v3보다 1승, `f3_v2_warrior_reserve` 상대는 3승 적었다. 각각 −2.08%p, −6.25%p로 사전 허용 범위 안의 실제 회귀다.
- 감사 추가 3종의 Y 개선은 +3.47%p지만 CI가 **[−7.64, +14.58]%p**로 0을 포함한다. 추가군 개선이 확정됐다고 해석하지 않는다.

상대 대부분이 v2/v3에서 파생됐으므로 전체 참가자나 리더보드 보정 점수를 대표하지 않는다. 기존 f3의 추가 감사 실패와 그 실행의 **v3 유지** 결론은 보존한다. 이전 80맵 결과는 이번 s3를 고르는 데 사용한 선택 자료이며 새 독립 검증에 합산하지 않았다. 새 결과를 본 뒤 후보를 바꾸거나 재시도하지 않았다. ZIP은 14,441 bytes이며 SHA-256은 `b3f7fee0154ff08a7f563e8b0036dd7b649d136e949e641ebe69a8c0ba7cd3da`다. 실제 ZIP 추출본을 TMP의 Debian GCC12.2로 빌드하고 SDK 기본 실행 1경기와 새 맵9450·9451의 CPU 4경기를 통과했다. 384MiB 주소공간·일반 턴300ms·첫 턴3000ms에서 최대 후보 응답은 **130.73ms**, 오류·몰수·출력 경고 0이었다. CPU 4경기는 실행 검사이며 승률 선택에 사용하지 않았다.

컴파일러·빌드·실행 TMP와 두 원격 실행의 TMP·관련 프로세스를 정리했고 전역 패키지를 설치하지 않았다. RLIMIT_AS는 RSS/cgroup 제한과 다르며, 호스트 CPU·링커·커널·격리는 공식 컨테이너와 다르다. **업로드와 제출 선택은 사용자가 진행한다.**
