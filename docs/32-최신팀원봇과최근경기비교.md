# 최신 팀원 봇과 최근 경기 비교 — 2026-10-01

팀원 최신 세 후보를 소스·ZIP·실행 인자까지 구분해 **384경기, 서로 다른 24맵**에서 비교했다. 모두 **서버의 봇당 0.25vCPU 제한을 적용하지 않은 로컬 CPU 실험**이다. Siphon은 확대 직접전에서 63승 33패였지만, 같은 공통 상대를 둔 비교에서는 24승 24패로 v8의 36승 12패보다 낮았다. 특정 팀원에게 강한 결과를 전체 성능 개선으로 판단하지 않는다. 이 작업에서 서버 업로드·선택·복원은 하지 않았다.

최근 공식 **10월 1일 10:00 회차는 제출9로 치른 Y 진영 24경기, 12승 12패**이며 12승 중 상대 기권승이 2개다. 현재 대시보드의 선택은 08:00 업로드된 **제출10 `v9_2.zip`**으로 서로 다르다. 서버 ZIP을 새로 내려받아 해시를 확인하지 않았으므로, 같은 파일명만으로 아래 로컬 소스와 동일하다고 간주하지 않는다.

## 전략 차이가 실제로 드러난 부분

공통전 T20의 동일한 48경기 평균에서 Siphon은 W를 더 많이 모았지만 소유 거점과 점수는 적었다. 아래는 같은 **quota 미적용 로컬 경기**의 사후 분석이다. 숨은 점수를 포함한 값을 봇 입력에 넣지 않았다.

|---|---:|---:|---:|

이는 경제·집단 호위를 위한 Siphon의 적은 F와 집중 배분이 확장 속도와 교환되는 관측이다. 이 평균만으로 패배의 단일 원인을 확정하지 않는다. Siphon은 적 TELE 위험을 계산하지만 자신의 TELE·S 생산·정보획득 전용 목표는 쓰지 않는다. 점수 열거의 `P(win)`도 현재 소유권을 종반까지 유지한다는 조건의 점수 분포이며 상대의 미래 행동을 예측한 승률은 아니다.

기존 SDK 계약 12개에 Siphon을 넣은 원시 결과는 8통과·4실패지만 실패의 의미를 구분했다. 마지막 턴 무방비 적 거점의 기존 F 중립화와 신규 F 중립화는 **최소 호위4명의 가상 생산 대기** 때문에 합법적인 즉시 승리 행동을 버렸다. 두 장면에서 정지 상대의 공식 전이로 각각 3:6→3:2, 3:4→3:2를 재현했다. 다른 실패 하나는 W1 병원을 6턴 내 회수하지 못한 목표 지연이다. 마지막 하나는 병원 신규 F로 T159 점령·T160 21:12 승리했지만 최종 F 위치를 요구한 과한 테스트 단언으로, 성능 실패로 세지 않는다. [Siphon 상세 검토·원명령](../records/teammates/latest-20261001/siphon-review/review.md).

main v9_2의 새 F 경로 안전은 시간이 충분한 T140/141 반례에서 효과가 있었지만 T159의 사망 경로와 마지막 턴 신규 F 중립화 누락은 남았다. v9-lock은 해당 신규 F 반례를 통과했지만 공격 경로 F 안전을 모두 해결하지는 않았다. 이들은 정지 상대의 작은 개발 반례이며 전체 경기 승률과 별개다. [v9 두 계열 상세 검토](../records/teammates/latest-20261001/v9-review/review.md).

로컬 main v9_2의 대표 패배도 두 종류였다. Siphon전은 병원→공학관→회관을 잃으며 T119에 끝났고, 양쪽 W 전투 손실이450으로 같아도 생산532:661 차이로 병력이 벌어졌다. 반면 v8전은 경제 거점을 유지한 채 T139 **27:5에서 최종15:18**로 역전됐다. 원래 합법 관측으로 재실행한 T140–160 명령21개가 일치했고, LOCK이 이미 잃은 거점을 F 목표에서 제외하며 임무를 왕복시키는 동작을 확인했다. 특정 새 패치 하나가 회귀를 일으켰다고 입증한 대조 시험은 아니다. [SDK559턴 재현·원명령·모드 근거](../records/teammates/latest-20261001/v9-loss-review/review.md).

팀원이 말한 Siphon **Y 77승 19패, 5회 실행·12맵**은 `0f06e158` 커밋 본문에 있다. 원래 상대·시드·K진영·경기 로그가 함께 게시되지 않아 그 실험을 독립 재현하지 못했다. main v9_2의 17/24 대 이전15/24는 다른 후보의 개발 보고이며, 새 검증 중단·200ms 초과 응답·채택 대기를 명시한다. 200ms 초과 자체가 300ms 규칙 위반인 것은 아니다.

실제 출력 명령을 공식 엔진에 대조한 감사에서 문법 무시·생산비·출발 재고·이동/TELE 관련 문제는 0이었다. 프레임 수는 양측 관점을 두 경기로 중복 계산한 수가 아니다. [파일럿 Siphon 감사](../records/benchmarks/latest-teammates-20261001/pilot-siphon-action-audit.json), [파일럿 v9 감사](../records/benchmarks/latest-teammates-20261001/pilot-v9-variants-action-audit.json), [확대 직접전 감사](../records/benchmarks/latest-teammates-20261001/direct-confirmation-action-audit.json), [공통전 감사](../records/benchmarks/latest-teammates-20261001/common-opponents-action-audit.json).

## 새 CPU 공지와 별도 검증

10월 1일10:42:10의 **「[FAQ] 에이전트 CPU 사용 한도 및 실행 시간 관련」** 공지는 각 봇에 개별 **0.25vCPU**를 배정하며, 일반300ms·첫 턴3초는 실제 경과 시간으로 측정하고 본선에도 같은 조건을 적용한다고 명시한다. [공식 공지](https://yonsei-vs-korea-hackathon.kr/announcements). 위 로컬 리그·SDK smoke는 이 quota 조건의 재현 실험이 아니다. 벽시계 예산으로 탐색하는 봇은 가능한 탐색량과 선택 행동도 바뀔 수 있어, 로컬 응답시간에 단순히4를 곱해 서버 성능을 산정하지 않는다.

이 공지를 확인한 뒤 계획·실행 코드를 `c70656a6`에 먼저 고정했다. 기존 GCC16.2.1 바이너리를 사용하고, 새 맵23400에서 봇별 임시 cgroup **CPU 25% 제한10경기와 일반 CPU 대조4경기**를 추가했다. SDK 러너는 제한 밖에 두었고 양측 봇은 서로 다른 scope에서 실행했다. 실제 `cpu.max=25000 100000`, burst0, 메모리384MiB를 확인했다. CPU 계산0.250초가 실제1.081초로 늘어나는 calibration도 통과했다. [동결 계획·조건](../records/benchmarks/quarter-cpu-20261001/README.md).

이 맵에서 Siphon·main·lock은 각각 v8에0승2패, Mission4는2승0패였다. v8 자기전2개도 런타임 기준선에 포함했다. 일반 CPU 대조4경기는 main·lock 대 v8의 같은 맵 양 진영이다. **맵 하나의 민감도 검사**이므로 Mission4의 기존 최종 채택 실패를 뒤집거나 다른 후보의 전체 우열을 확정하지 않는다. 서버의 CPU 모델·quota 주기는 미공개이며, 여기서 선택한100ms 주기와 GCC16이 서버와 동일하다는 뜻은 아니다. lock의 시계 난수와 시간 예산 탐색도 남아 있어 양 조건의 승패 차이를 CPU만의 인과 효과로 설명하지 않는다. 앞선384경기를0.25vCPU로 다시 수행한 것도 아니다.

## 최근 공식 회차와 현재 선택

Chrome에서 명시적으로 **10월 1일 10:00 리더보드 회차**를 선택해 목록과 원본24개를 확보했다. 전부 제출9·Y 진영이며 목록의 12승 12패가 원본 winner와 일치하고, 원본 해시24개도 manifest와 일치했다. 12승은 즉시승6·점수승4·상대 기권승2, 12패는 즉시패9·점수패3이다. 기권승2개를 전략적 승리의 증거로 합산하지 않는다. [경기 목록·선택 상태](../records/official/round-20261001-1000/matches.json), [원본 manifest](../records/official/round-20261001-1000/raw-manifest.json). 이전 12경기 일부 원본 분석이나 옛 제출3/4 리플레이와 합치지 않는다.

현재 선택은 제출10 `v9_2.zip`, 업로드 10월 1일08:00, 사용 가능 상태다. 상세 처리 메시지는 소스 검사·이미지 조립 완료 뒤 **실제 게임 프로토콜 smoke 대기**라고 표시한다. 따라서 “사용 가능” 라벨을 서버 실전 검사 완료로 확대하지 않는다. [상세 원문·확인 시각](../records/official/round-20261001-1000/submission10-detail.json). 제출9의 경기 성적을 제출10 또는 이번 로컬 main v9_2/lock/Siphon의 성적으로 표시하지 않는다. 대시보드의 `10월 1일 00:09 공개` 표시는 경기 회차 라벨과 일치하지 않아 목록 원문에 둘 다 보존했다. 이번 작업은 서버 선택을 변경하지 않았다.

최신 패배에는 서로 다른 실패가 있다. **박박이전은 HALL·병원을 한 번도 확보하지 못한 채 T43에 종료**됐다. F8명 중1명만 죽었으므로 대량 F 손실이나 종반 전환으로 설명할 수 없다. 반면 **2325전은 경제 거점을 끝까지 지켰어도 F28명 중27명을 잃었다**. T16에는 입력부터 적 W2가 보이는 칸에 무호위 F를 보냈고, 공식 SDK에 적 정지·무생산을 적용해도 사망했다. 이것은 한 턴의 위험 확인이며 대체 행동의 전체 경기 승리를 입증한 것은 아니다. [전체24경기 요약](../records/official/round-20261001-1000/analysis/summary.md), [공개 입력·원명령 사례](../records/official/round-20261001-1000/analysis/cases.md).

**占쏙옙전은 T120 공개점수35:4에서 최종15:17로 역전**됐다. T155 병원에서 W7을 생산한 뒤 병원W65·공학관W17을 전부 옮겼다. 이후 두 거점을 잃었으며, 최종 W548:94인데도 졌다. W 532명이 세 칸에 몰렸으며 그중 W81이 있는 보급소는 여전히 중립이었다. 반대로 인공저능전은 W 생산869:905로 뒤져도17:16으로 이겼다. 따라서 생산 총량, F 안전, 실제 점령 도착 시각을 따로 봐야 한다. 상대 명령·서버 소스가 없으므로 이 공식 경기의 내부 모드를 LOCK으로 단정하지 않는다. 미공개 점수는 null과 합법 범위를 유지했다.

우리 생산·이동 장부는 실제 실행2,712턴을 SDK로 검사했다. 상대 명령이 없으므로 전체 전투 재현과 구분한다. 두 기권 경기의 마지막 BEFORE_COMMANDS 프레임은 생산·이동에서 제외했다. 우리 응답2,714개는 모두 status ok이고 공식 원본의 최대 기록은 일반214ms·첫 턴302ms였다. 이번12패를 시간 초과로 설명할 근거는 없다. 상대 기권의 내부 원인은 미확인이다.

현재 판단은 Siphon의 경제 공격과 점수 추론을 연구·고정 상대에 보존하되, 직접전 우위만으로 일반 개선이나 서버 교체를 선언하지 않는 것이다. 최신 main v9_2와 lock도 별도 버전으로 유지하고, 공식 제출9의 실패 원인을 현재 선택10에 적용할 때는 먼저 실제 소스 연결을 확인해야 한다.
