## CPU와 실행 검사

모든 후보·상대를 GCC 12.2.0, C++20, `-O2`로 빌드했다. 각 봇을 별도 cgroup에 두고 `cpu.max=25000 100000`, 메모리 384MiB, 주소 공간 384MiB를 적용했다. SDK 진행 프로세스는 봇 scope 밖에서 실행했다. 일반 턴 300ms, 첫 턴 3초는 실제 경과 시간으로 검사했다. 서버의 CPU 모델과 quota 주기는 공개되지 않아 완전히 같은 서버 환경이라고 주장하지 않는다.

- 128경기와 18,376프레임: 실행 오류·몰수·엄격 명령 검사 문제 0.
- v8 일반 응답 최대 195.40ms, 첫 응답 최대 224.38ms.
- 256개 봇 scope의 실제 제한과 제거 확인. 소스·바이너리·실험 코드 해시 불변.
- 제출 ZIP을 다시 빌드한 바이너리 해시가 경기 바이너리와 일치. SDK ZIP 검사와 실행 검사 통과.
- 별도 검토자가 원시 결과 집계, 승점, 양 진영 균형, 명령 검사, scope 정리를 재확인했다.

## 수정 후보를 채택하지 않은 이유

[새 가드](../submissions/deadline1500-flagguard-20261001/README.md)는 W의 생성·출발·도착을 반영하고, 현재 적 W보다 호위가 적은 F 이동을 정지 또는 인접 대피로 바꾼다. 공식 경기의 합법적인 한 턴 반례 두 개에서는 F를 하나씩 더 살렸고, 신규 W 호위와 출발 재고 계약도 통과했다.

그러나 전체 경기는 기존 v8의 17승에서 12승으로 낮아졌다. 한 턴의 안전성이 전체 경기 성능 개선을 보장하지 않았으므로 수정은 연구 후보로 보존하고 제출에는 포함하지 않았다. 상대가 떠나는 경우의 공격 기회 상실, 우회·정체 등은 후속 분석 대상이며 이번 승패 차이의 원인으로 확정하지 않는다.

같은 맵·진영·상대 32쌍에서 v8 승→가드 패는 8쌍, 패→승은 3쌍이었다. 대표 `23500/Y/s3`는 19:12 승에서 9:23 패로 바뀌었지만, 최초 명령 분기인 T4에는 해당 F의 목적지에 적 W가 없어 가드 조건이 성립하지 않았다. 상대 명령도 달랐다. 시간 예산 탐색의 실행 변동이 섞인 비교이므로 가드만의 인과 효과로 해석하지 않는다.
