# 격자형 턴제 전략 게임 봇: 기초 안내

> 원본: `한국어_자막_전사.txt`  
> 내용: 해커톤 참가자를 위한 게임 봇 구현 기초 강의

## 1. 해커톤의 목표

이 해커톤의 목표는 제한된 턴 안에서 자율적으로 판단하고 행동하는 게임 봇(에이전트)을 만드는 것입니다. 제출한 코드는 게임 동안 사람이 개입하지 않아도 매 턴 상태를 읽고, 행동을 결정하고, 명령을 출력해야 합니다.

가장 먼저 실제 게임 규칙을 정확히 이해해야 합니다. 어떤 유닛이 무엇을 할 수 있는지, 점수는 어떻게 얻는지, 자원과 턴 제한은 무엇인지가 전략의 출발점입니다.

## 2. 게임 환경의 예시

강의에서는 설명을 위해 다음과 같은 가상의 격자형 1:1 게임을 사용합니다.

- 맵에는 건물, 장애물, 상대 유닛, 점수 획득 대상이 존재합니다.
- 자원으로 여러 종류의 유닛을 생산합니다.
- 깃발병은 건물에 도달해 점수를 얻습니다.
- 전투병은 상대 유닛과 전투하거나 상대의 점수 획득을 방해합니다.
- 정찰병은 빠르게 이동하며 맵과 상대 정보를 파악하는 역할을 할 수 있습니다.
- 자원은 한정되어 있으므로 어떤 유닛을 얼마나 생산하고 어디에 배치할지 선택해야 합니다.

## 3. 봇은 상태를 행동으로 바꾸는 함수

게임 봇은 현재 상태(`state`)를 입력받아 이번 턴의 명령(`action`)을 출력하는 함수로 생각할 수 있습니다.

```text
state → 판단 로직 → action
```

상태에는 예를 들어 다음 정보가 포함될 수 있습니다.

- 현재 턴 수와 남은 턴
- 보유 자원
- 맵과 장애물의 상태
- 내 유닛과 건물의 위치 및 상태
- 관측 가능한 상대 유닛과 건물 정보

매 턴의 의사결정 루프는 다음과 같습니다.

1. 상태를 확인합니다.
2. 상태를 바탕으로 후보 행동을 평가합니다.
3. 이번 턴의 행동을 선택합니다.
4. 게임 엔진에 명령을 출력합니다.

## 4. 가장 단순한 봇부터 시작하기

처음에는 단순하고 검증 가능한 규칙으로 시작하는 것이 좋습니다.

```text
자원이 충분하면 깃발병을 생산한다.
깃발병이 있으면 가장 가까운 점수 건물로 이동시킨다.
```

이후 실제 경기 결과를 보며 전투, 위험 회피, 건물 점수, 정찰, 자원 배분 등의 조건을 하나씩 추가합니다.

## 5. 길찾기: BFS

유닛을 목표 지점까지 빠르게 보내려면 최단 경로가 중요합니다. 격자에서 한 칸씩 같은 비용으로 이동한다면 **BFS(너비 우선 탐색)** 를 사용할 수 있습니다.

### BFS의 핵심 아이디어

BFS는 시작점에서 가까운 칸부터 물결처럼 넓게 탐색합니다.

- 1번 이동으로 갈 수 있는 칸을 먼저 탐색합니다.
- 다음으로 2번 이동, 3번 이동이 필요한 칸을 순서대로 탐색합니다.
- 목표에 처음 도달한 경로가 최단 경로입니다.

보통 큐(`queue`)와 방문 여부 배열을 이용해 구현합니다.

```text
큐에 시작 위치를 넣는다.
큐에서 위치를 하나 꺼낸다.
상하좌우의 이동 가능한 미방문 칸을 큐에 넣는다.
목표에 도달하거나 필요한 범위까지 반복한다.
```

### 길찾기 구현 팁

- 매 턴 맵 전체를 계산할 필요는 없습니다. 목표를 찾았다면 탐색을 멈출 수 있습니다.
- 유닛마다 출발점이 다르므로 필요한 경우 유닛별로 거리를 계산합니다.
- 장애물·통과 불가 칸·점유 칸 등의 실제 게임 규칙을 반드시 반영합니다.
- 상황에 따라 DFS, 다익스트라, A* 같은 다른 경로 탐색도 고려할 수 있습니다.

## 6. 휴리스틱: 후보에 점수를 매겨 선택하기

가장 가까운 건물이 항상 최선은 아닙니다. 점수가 높은 건물은 멀더라도 가치가 있을 수 있고, 적이 많은 지역은 위험할 수 있습니다.

이런 판단에는 **휴리스틱** 이 유용합니다. 가능한 행동 또는 목표마다 점수를 계산하고, 가장 높은 점수의 후보를 선택하는 방식입니다.

```text
후보를 나열한다 → 후보 점수를 계산한다 → 최고 점수 후보를 선택한다
```

예시 점수식은 다음처럼 만들 수 있습니다.

```text
목표 점수 = 건물_점수 × 점수_가중치
          - 최단거리 × 거리_가중치
          - 위험도 × 위험_가중치
```

### 고려할 수 있는 요소

- **건물 점수**: 높은 점수의 건물을 우선시합니다.
- **거리**: 가까울수록 빠르게 점수를 얻을 수 있습니다.
- **위험도**: 적 유닛, 전투 가능성, 경로의 위험을 반영합니다.
- **남은 턴**: 게임 종료가 가까우면 먼 목표의 가치를 낮춥니다.
- **게임 국면**: 초반에는 확장과 점수 획득, 후반에는 점수 방어의 비중을 높일 수 있습니다.

가중치는 정답이 아니라 전략의 성격을 정하는 값입니다. 경기 결과를 바탕으로 조금씩 조정해야 합니다.

## 7. 유닛 생산과 역할 분담

한정된 자원을 어떤 유닛에 쓸지는 중요한 전략 문제입니다.

| 유닛 | 가능한 역할 |
| --- | --- |
| 깃발병 | 건물 점령과 점수 획득 |
| 전투병 | 적 유닛 제거, 지역 방어, 깃발병 호위 |
| 정찰병 | 빠른 정보 수집, 상대 전략 파악 |

상대가 전투병 중심이라면 호위나 대응 전투병이 필요할 수 있습니다. 반대로 상대가 전투에 치중해 점령이 느리다면, 빠르게 여러 건물을 점령하는 전략이 효과적일 수 있습니다. 특정 상대 한 종류에만 강한 전략보다 여러 전략에 대응할 수 있는 균형을 목표로 합니다.

## 8. 디버깅과 개선 방법

봇은 명령 형식 오류, 런타임 오류, 시간 초과, 무한 루프, 의도와 다른 판단 등의 문제를 일으킬 수 있습니다.

### 로그를 남기기

전체 리플레이만 보는 것보다, 매 턴 핵심 판단을 로그로 출력하면 원인을 빨리 찾을 수 있습니다.

```text
턴 번호 / 자원 / 선택한 생산 유닛 / 목표 좌표 / 후보 점수 / 이동 명령
```

로그를 통해 다음을 확인합니다.

- 봇이 실제로 어떤 상태를 읽었는가
- 어떤 후보들을 고려했는가
- 왜 해당 행동을 선택했는가
- 명령이 게임 규칙과 형식에 맞는가

### 반복 실험

1. 단순한 버전을 만듭니다.
2. 여러 전략의 상대와 대전시킵니다.
3. 패배 원인을 로그와 리플레이로 확인합니다.
4. 한 번에 하나의 가설만 수정합니다.
5. 수정 전후 성능을 비교합니다.

한 상대에게만 지나치게 강한 전략은 과적합일 수 있습니다. 다양한 유형의 봇을 상대로 테스트해야 합니다.

## 9. 성능과 언어 선택

턴마다 계산할 수 있는 시간에는 제한이 있을 수 있습니다.

- 익숙한 언어로 먼저 정확한 봇을 만드는 것이 좋습니다.
- 계산량이 커지면 불필요한 전체 맵 탐색과 중복 계산을 줄입니다.
- 실행 시간과 구현 난이도 사이에는 트레이드오프가 있습니다.
- 시간 초과 여부는 반드시 실제 실행 환경에서 확인합니다.

## 10. 핵심 요약

1. 게임 규칙을 정확히 이해합니다.
2. 봇을 `상태 → 판단 → 명령` 함수로 설계합니다.
3. BFS 등으로 유닛의 최단 경로를 계산합니다.
4. 휴리스틱 점수표로 생산·이동·전투 후보를 비교합니다.
5. 로그와 반복 대전으로 전략을 검증하고 개선합니다.

좋은 봇은 한 가지 규칙만 반복하는 봇이 아니라, 맵·자원·적·남은 턴에 따라 적절히 판단을 바꾸는 봇입니다.
