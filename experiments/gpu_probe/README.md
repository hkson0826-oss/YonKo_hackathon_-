# 동일 평가함수의 CPU/GPU 파라미터 배치 비교

신경망 없이 C++ 봇의 수식 계산을 CUDA로 옮기는 작은 실험이다. v2의 `evaluation`과 `building_value`를 공통 헤더로 구현해 CPU와 GPU에서 같은 계산을 한다. 공학관 보너스, HALL 추가 수입 보너스, 병력 가치 계수의 125개 조합을 참가자 관측 상태에 적용한다.

**전체 대전, 행동 생성, `advance`, 전략 탐색은 포함하지 않는다.** 이 실험의 속도 비율은 전체 봇·경기의 속도 비율이 아니다. 평가값이 달라지는 것만 확인하며 좋은 파라미터를 선정하거나 승률을 측정하지 않는다. 같은 상태에서 계수만 바꾸는 수식은 CPU에서도 특징량 캐시 등으로 더 줄일 수 있으므로, 실제 튜닝 작업은 전체 대전과 연결해 별도로 측정해야 한다.

## 실행

Python 표준 라이브러리, C++20/OpenMP 컴파일러, NVIDIA CUDA 드라이버와 NVRTC 공유 라이브러리를 사용한다. PyTorch·NumPy·CUDA 전체 툴킷은 필요하지 않다. NVRTC와 그 builtins 라이브러리는 같은 패키지 위치를 유지한다.

```bash
python experiments/gpu_probe/run_probe.py \
  --output-dir records/compute/gpu-probe-UNIQUE-ID \
  --nvrtc-lib /path/to/nvidia/cuda_nvrtc/lib/libnvrtc.so.12 \
  --device 0 --cuda-arch 86 \
  --batch-sizes 1024,16384,65536 --workers 1,4 --warmup 2 --repeats 3
```

`--cpu-only`는 CPU 대조만 실행한다. CUDA 드라이버가 장치를 찾지 못하면 GPU 결과를 `skipped`로 남기고 CPU 측정만 계속한다. GPU 실행 없이 GPU 속도를 계산하지 않는다. 출력 디렉터리가 이미 있으면 실행을 거부한다. 3090은 `--cuda-arch 86`을 쓰며, PTX 타깃 86은 이후 세대 GPU에서도 실행할 수 있다.

## 정확성·측정 범위

- 공식 리플레이 5개의 현재 관측과 과거 소유 이력을 사용한다. 미래 관측의 숨은 점수를 쓰지 않는다. v2의 순차 대칭 추정·기본 점수·점령 이력 추정을 그대로 따른다.
- 원본 v2 소스를 포함한 CPU 브릿지와 기본 파라미터 `(110, 35, 1.3)`의 결과를 모든 입력 상태에서 대조한다. 이는 평가함수 이식 검증이며 v2의 판단 가정이 옳다는 증거가 아니다.
- CPU와 GPU 모두 double을 쓰고 FMA 결합을 끈다. 최대 절대 오차 허용값은 `1e-8`이다.
- CPU는 네이티브 C++ 단일 스레드와 지정한 OpenMP 작업자 수를 비교한다. GPU는 CUDA 이벤트로 커널 시간을 측정하고, 별도로 전체 입력 업로드·커널·출력 다운로드 시간을 측정한다.
- 컴파일, 메모리 할당, 컨텍스트 생성, Python 입력 구성은 반복 측정에서 제외하고 준비 시간은 따로 남긴다. GPU 워밍업·반복 횟수와 입력 크기도 기록한다.
- 배치가 전체 상태×설정 조합 수를 넘으면 동일 조합을 반복한다. 고유 조합 수를 별도 기록한다. 이것을 새로운 경기 수·새로운 전략 수로 세지 않는다.
- 결과 JSON에 소스·원본 리플레이 SHA-256, Git 커밋, 명령 인수, 환경, 준비 시간, 각 반복 시간, 계산 결과 체크섬과 오차를 남긴다. 빌드 산출물은 실행 디렉터리에 저장하며 공유 시 소스·로그·결과 JSON만 선정한다.

```bash
python -m unittest discover -s tests -p test_gpu_probe.py
```
