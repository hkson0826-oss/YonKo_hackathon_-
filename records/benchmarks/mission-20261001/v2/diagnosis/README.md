# Mission v2: 제한된 후속 진단

호위 합류 변경 뒤에도 공통 상대 성능이 개선되지 않았다. v1은 3승 21패, v2는 2승 22패다. 대표 seed19013 K/j_balanced 경기에서는 **HALL이 두 버전 모두 16턴 중립화되고 17턴 상대 소유**가 된다. 경제 거점 방어 누락은 남아 있다.

| 공통 상대 24경기 평균 | v1 | v2 | v2 arena v8 |
|---|---:|---:|---:|
| 승리 | 3 | 2 | 16 |
| 20턴 점수 | 13.83 | 15.21 | 17.75 |
| 20턴까지 W 생산 | 91.25 | 91.46 | 88.08 |
| 20턴까지 F 사망 | 0.25 | 0.08 | 0.50 |
| W 잔류 인원턴 / 이동 전 W 인원턴 | 49.35% | 39.16% | 12.78% |
| 최종 점수 | 5.54 | 3.67 | 22.83 |
| 최종 F 생존 | 6.50 | 6.42 | 5.42 |

W의 잔류 비율은 낮아졌고 20턴 점수도 높아졌으나 종반 점수는 개선되지 않았다. 잔류에는 필요한 방어도 포함된다. F 생존이나 W 이동량만으로 수정 성공을 판정할 수 없다. v1→v2 결과는 단일 실행 간 비교이며 반복 측정으로 인과 효과를 확정한 결과가 아니다.

대표 경기 원본은 v1 `ca61304a881abc2d17a4d2c8`, v2 `926f5990f21dee0d30a9187c`이다.

- 초기 ENG/HALL/병원 점령은 양쪽 모두 2/3/6턴이다.
- v2는 10턴 PLAZA 점령 뒤 12턴 상실한다. v1은 13턴 첫 상실이다. 따라서 첫 전선 손실은 HALL 침입보다 앞선다.
- v1 14턴 입력의 적 F는 `(11,7)`, 종료 위치는 `(11,8)`이다. v2 14턴 입력은 `(10,8)`, 종료 위치는 `(11,8)`이다. 두 경우 15턴 입력 `(11,8)` → 16턴 입력 `(11,9)` → 16턴 종료 HALL `(12,9)` 침입이라는 경로가 이어진다.
- v1의 ENG `(11,11)` W 11명 정체는 v2에서 그대로 반복되지 않는다. v2는 15–17턴 입력·종료에 W 1명만 남는다. 그런데 15턴 `(10,11)` W 10명을 8명 위·2명 왼쪽으로 보낸 다음, 16턴 `(10,10)` W 13명을 전부 아래로 보낸다. HALL로 보내는 병력은 없다. 'ENG에 11명이 묶임'이라는 v1의 구체적 현상을 v2 실패 원인으로 그대로 재사용하면 안 된다.
- 최종 v1은 123턴 0:30, F 사망 0명·생존 7명이다. v2는 106턴 0:33, F 사망 2명·생존 7명이다. F가 살아 있는 동안 거점을 잃는 문제가 유지된다.

같은 조건 v8의 재실행은 v1 arena의 146턴 31:0에서 v2 arena의 76턴 27:0으로 바뀌었다. v8과 j_balanced 소스 해시는 두 실행에서 같다. 시간에 영향을 받는 탐색 등 원인을 따로 검증하지 않았으므로 변화의 원인을 단정하지 않는다. 고정 소스도 매번 같은 경기 경로를 보장하지 않았다는 실제 관측으로만 기록한다.

`review.py`는 기존 결과·분석 JSON을 읽고 v2 공통 상대 경기에서 SDK 생산·이동 단계만 적용해 W 잔류를 집계한다. 모든 턴의 전체 게임 전이를 다시 실행하지 않았다. 이동 집계는 각 스냅샷에서 SDK `step_move`와 일치했다. 두 대표 경기의 10–20턴 원본 명령·병력·소유권 변화, 집계와 입력 해시는 `evidence.json`에 있다. 원본 전체 명령 검사와 경기 전이 감사는 root의 실행 기록을 따른다.

후속 v3에서는 HALL 회귀 사례로 필요한 최소 수비의 도착 기한을 검사하고, 호위 합류 변경을 유지한 경우와 제거한 경우를 별도로 비교하는 것이 적절하다.

## HALL SDK 회귀 계약

실제 코어의 내부 판단을 호출하지 않고 공개 프로토콜과 SDK만으로 계약을 추가했다. 원본 합법 관측을 1–13턴 입력한 뒤, 14턴 입력의 F `(11,7)` 한 명만 D,D,R로 침입시킨다. 다른 적은 정지하고 생산하지 않는다. 사망한 F에는 후속 명령을 보내지 않는다. 양측 전체 명령은 SDK 적용 전에 문법·예산·경로·출발 재고를 엄격히 검사한다.

v2는 16턴 HALL 중립화로 실패했다. v3 소스 `5cff84e533234f02fa8665de009ec7b2d10641c5baf5a33ac3fcc7edddb434e1`은 합류 on/off 모두 15턴에 침입 F를 제거하고 18턴까지 HALL을 유지했다. `hall-contract-summary.json` 및 각 실행 JSON에 소스·원본 해시와 전체 원명령을 보존했다. 이 결과는 방어 회귀 계약의 통과이며 전체 대전 개선을 뜻하지 않는다.
