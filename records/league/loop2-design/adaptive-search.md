# 두 번째 루프: 행동 조합과 제한 시간 탐색

2026-09-28. 기준은 수정하지 않은 [v2](../../../submissions/tuned/main.cpp)다. [생성기](../../../experiments/local_league/adaptive_search.py)는 8개 후보를 만든다. 승률은 아직 이 문서의 근거가 아니다. 실제 대전에서 기존 v2·팀원·지난 리그의 강한 후보를 이겨야 채택한다.

## 관찰에서 출발한 변경

지난 리그에서는 전체 병력이 늘어도 특정 거점에 정체해 다른 거점을 잃었다. 또 양측 rollout의 정책을 함께 바꾸면 우리 행동 개선과 상대 예측 변경이 섞였다. 이번 탐색에서는 원본 상대 스크립트 4개를 그대로 유지하고 우리 행동만 확대한다. 기존 4개 완성 정책을 고르는 대신 F 이동·생산과 W 이동을 결합하거나 중요한 출발지의 명령만 바꾼다.

| 후보 | 새 결정 구조 | 약점과 기각 조건 |
|---|---|---|
| `a_asymmetric_mix` | F/생산 정책과 W 정책을 교차한 4개를 기존 4개에 추가 | 생산 수와 호위가 안 맞을 수 있다. F 손실·주요 상대 회귀가 늘면 기각 |
| `a_pgs_local` | 초기 완성 정책 선택 후 중요한 출발지 3곳의 행동을 탐욕적으로 교체 | 국소 최적·수정 순서 의존. 더 많은 연산만 쓰고 승률이 안 오르면 기각 |
| `a_pgs_hybrid` | 혼합 정책에서 출발하는 국소 수정 | 후보 수 증가가 수정 시간 감소로 이어짐. 별도 요소 비교 필요 |
| `a_opponent_fit` | 직전 관측을 재현하는 상대 스크립트에 가중치 부여 | 실제 상대가 후보 밖에 있으면 오판. 동일 상대의 새 맵에서 회귀하면 기각 |
| `a_fit_pgs` | 상대 가중치와 국소 행동 수정을 결합 | 예측 오차 감소가 승리 증가와 같지 않음. 두 단독 후보와 비교 |
| `a_progressive` | 깊이 2에서 상위 3개를 추리고 초반 6/후반 4턴으로 재평가 | 얕은 평가가 장기 투자를 탈락시킬 수 있음. 깊은 비교 3개가 모두 완료될 때만 교체 |
| `a_score_scenarios` | 숨은 대칭 점수의 합법 하한·상한으로 각각 평가 | 전체 조합을 탐색하지 않아 강건성 보장 없음. 관측된 점수는 바꾸지 않음 |
| `a_local_unabstracted` | 중요 출발지에서 스크립트 밖의 인접 칸 이동도 검사 | F/W 전량 이동만 추가하며 최적 분할은 아님. 각개격파·빈집 증가에 주의 |

모든 후보는 상대 결과의 가중 평균 75%와 최악값 25%를 쓴다. 상대 적합도 후보도 각 스크립트 가중치가 0.10 아래로 내려가지 않는다. 적합도는 직전 실제 관측에 대해 원본 정책으로 예측한 상대 병력·소유권·자원 오차의 이동 평균이며 신경망이나 오프라인 학습 가중치를 사용하지 않는다. 상대 관측의 미공개 점수는 알 수 없으므로 상대 내부 판단을 완전히 재현할 수는 없다.

숨은 점수 시나리오는 중앙광장 3점, 중앙의 미공개 쌍 2/4점, 양 진영의 미공개 쌍 1/2점이다. 한쪽이라도 공개된 대칭 쌍은 기존 추론 값을 보존한다. 모든 미공개 쌍이 동시에 낮거나 높은 두 경우만 본다. 이는 공식 게임의 가능한 점수 범위를 이용한 대조 실험이지 전체 가능 점수 조합의 최악값은 아니다.

## 스스로 검토하고 고친 내용

1. **초안의 혼합 행동은 합법성을 보장하지 못했다.** 두 정책의 생산·이동량이 다르기 때문이다. 생산부터 자원에 맞춰 계산한 뒤 원래 위치의 병력만 차감하고, 도착 병력을 같은 턴 다시 이동시키지 않는 `a_clean`을 추가했다. 실제 생산 순서, 병원 소유권, 1회·최대 5명 역 이동, 일반 인접 이동을 확인한다.
2. **일부 상대만 평가한 후보는 채택하지 않는다.** 네 상대 모두 끝난 후보만 기존 최선과 비교한다. 시간이 끝나면 마지막으로 완전 평가한 최선 행동을 반환한다. 시작 단계조차 끝나지 않으면 원본 정책 0이 기본값이다.
3. **서로 다른 깊이의 평가값을 비교하지 않는다.** 상위 3개를 깊게 보는 후보는 세 개를 모두 깊게 평가했을 때만 얕은 선택을 교체한다.
4. **혼합 역할이 영속하지 않는 한계를 명시했다.** 실제 실행은 첫 턴 명령이며 이후 rollout은 기반 정책을 사용한다. RHEA나 지속 임무 예약을 구현했다고 부르지 않는다.
5. **같은 명령 재평가를 줄였다.** 국소 수정 결과가 현재 명령과 같으면 건너뛴다. 전체 후보와 최대 3개 출발지 평가가 끝나면 즉시 반환하고 시간을 채우지 않는다.

검색 예산은 결정 시작부터 135ms이며 매 rollout 전이에 앞서 검사한다. 하나의 정책 생성·전이 실행 도중에는 선점하지 않으므로 실제 최대 응답은 대전에서 측정한다. 300ms 충족 여부는 실측으로 판정한다. 설계 검토를 통과한 것과 10점짜리 승률 성능을 증명한 것은 다르다. 이 문서로 승리 보장을 선언하지 않는다.

## 연구의 적용 범위

Firecrawl `firecrawl-research-index` 스킬을 적용해 구성된 MCP의 논문 본문 조회로 두 핵심 쟁점을 다시 확인했다. [출처 기록](adaptive-search-sources.json).

- [Asymmetric Action Abstractions](https://arxiv.org/abs/1711.08101): PGS는 스크립트가 제공하는 유닛 행동을 한 부분씩 바꾸고 더 좋은 완성 행동을 유지한다. 이번 구현은 유닛 ID가 없는 게임에 맞춰 출발지의 병력 묶음을 부분으로 삼았다. 원 논문의 전투 전용 실험이나 전체 비추상화 공간 보장을 이 게임으로 이전하지 않는다. `a_local_unabstracted`도 세 묶음에 제한된 인접 이동만 추가한다.
- [Opponent Modelling in an RTS Game](https://arxiv.org/abs/2006.08659): 부정확한 상대 모델에서 RHEA가 민감하게 악화됐으며 짧은 horizon만으로 문제를 모두 해결하지 못했다. 따라서 상대 적합도 후보를 별도 대조군으로 만들고 후보별 최소 가중치와 최악값을 유지한다. 이 비율이 최적이라는 근거는 없다.
- [Portfolio Search and Optimization](https://arxiv.org/abs/2104.10429): 이전에 확인한 역할 변경 문제를 설계 제한으로 활용했다. 이번의 국소 첫 행동 수정은 장기 역할 계획이나 진화 알고리즘의 재현이 아니다.

## 검사와 다음 평가

`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_league_adaptive_search.py -v`

검사는 8개 실제 C++ 컴파일, 공식 전이·관측 블록의 불변, 생산·이동·역 이동 합법화, 숨은 대칭 점수 보존, 상대 가중치 합계·하한, 중단 시 미완료 평가 제외와 기본 행동 반환을 확인한다. 모든 컴파일과 실행은 `/tmp`의 자동 삭제 폴더에서 수행한다.

2026-09-28 최종 코드로 3개 검사를 54.399초에 통과했다. 8개 후보를 각각 `g++ -std=c++20 -O2`로 컴파일한 검사도 포함한다. 강함과 최대 응답 시간의 판단은 실제 경기 배치에 남긴다.

대전 전에 검사 통과가 필요하다. 이후 개발 맵에서 오류·최대 응답과 상대별 승률을 확인하고, 실패가 관측되면 별도 ID로 고친 뒤 새 맵에서 다시 비교한다. 상대와 맵이 고정된 실제 경기 결과 없이 내부 평가 함수의 점수만으로 후보를 승격하지 않는다.
