# 교차 계열 추가 감사 사전 계획

계획 작성 UTC: **2026-09-27T15:51:57.681139+00:00**. 최종 holdout 결과를 기준으로 상대·기준을 바꾸지 않는다. 새 후보 코드는 만들지 않으며, 2차 선택 단계의 `locked-finalists.json`에 기록된 **첫 주 후보 한 개**만 v2와 비교한다. 후보 ID는 그 잠금 기록에서 그대로 가져와 실행 시 `--candidate`에 지정한다.

## 목적과 한계

기존 강한 상대 집단은 v2·팀원·r_combined·r_joint_escort·r_terminal_margin이다. 다수 상대가 같은 v2 행동 공간과 평가 구조를 공유하므로 이 집단의 개선이 서로 다른 탐색·배정 계열에서도 유지되는지 추가 검사한다. 새 상대들도 대부분 v2 전이·관측·기본 정책을 재사용한다. 완전히 독립적인 참가자 분포나 모든 알고리즘 계열을 대표하지 않는다.

고정 상대는 `j_balanced_portfolio`, `a_local_unabstracted`, `q_threat_window`, `a_v2_tactical_local`, `j_v2_reclaim_relay`, `teammate` 여섯 개다. 독립적인 공동 임무 생성·부분 자유 행동 탐색·방어 창 변경·종반 개별 행동 탐색·경유점 호위를 포함한다. 성적이 나쁘거나 주 후보와 같은 ID라는 이유로 상대를 제거하지 않는다. 자기대전도 v2와 주 후보의 동일 상대·동일 맵·양 진영 비교에 그대로 남긴다.

## 일정과 판정

미사용 맵 **7500–7531의 32개**에서 v2와 잠금 주 후보가 고정 상대 6개와 양 진영으로 겨룬다. 총 **2×6×32×2 = 768경기**, 각 후보 Y192·K192경기다. 전체 리플레이를 저장한다.

기존 문서와 계획의 7000–7007·7100–7107 개발, 7200–7215 선택, 7300–7363 holdout, 7400/7401 교차대전 및 이전 campaign-001의 5900/6000/6100/6200/6300대 맵과 겹치지 않음을 확인했다. 실행 명령이 변경되면 실제 사용 맵과 이 분리도 다시 확인해야 한다.

추가 통과 조건은 다음과 같다.

1. 계획한 768경기가 중복·누락 없이 완료되고 v2·후보의 오류·몰수가 모두 0이다.
2. 같은 맵·상대에 대응시킨 후보의 **Y 승점률 차이가 0 이상**이다.
3. 어느 고정 상대에서도 **Y 승점률 차이가 −12.5%p보다 낮지 않다**. 32맵에서 네 경기 차이까지 허용하는 경계다.

맵 단위 paired bootstrap 95% 구간을 함께 남기되 이 감사의 독립 통과 기준으로 추가하지 않는다. 원래 holdout의 개선 3%p·구간 하한 양수·상대별 회귀 한도 등의 승격 기준은 별도로 충족해야 한다. **추가 감사는 기존 holdout을 대체하거나 실패를 상쇄하지 않는다.** 여기서 다른 후보를 재선정하지 않는다. 실패 사례를 보고 코드를 바꾸면 새 후보와 새로운 검증 집합이 필요하다.

## 실행·기록

`experiments/cross_family_audit.py`는 기존 `local_league.prepare/run`과 `league_campaign.paired_interval`을 사용한다. revision 2 생성기로 필요한 ID만 동결하고 소스·SDK·해시·실행 환경·상대·시드·명령을 보존한다. `audit-policy.json`, `plans/audit.json`, `runs/audit/summary.json`, 모든 결과·리플레이와 `audit-result.json`에 전체·상대별 Y 차이를 남긴다.

공용 서버 실행은 기존 TMP 감독기를 통해서만 수행한다. CPU/RAM 90% 상한·결과 회수·TMP와 자식 프로세스 정리를 그대로 적용한다. 이 계획 작성과 드라이버 구현 자체는 서버에 접근하지 않으며 진행 중인 2차 실험의 소스를 변경하지 않는다.

## 제출 주소공간 한도 추가 검사

준비·컴파일을 마친 뒤 `league.run`을 호출하기 직전에 부모 프로세스의 `RLIMIT_AS` soft를 **402,653,184바이트(384MiB)** 또는 기존의 더 낮은 한도로 제한한다. hard 한도는 변경하지 않는다. 경기 worker와 그 자식 봇이 이 한도를 상속하고, 종료 시 부모의 기존 한도를 복구한다. 원격 TMP 감독기의 기존 768MiB 주소공간 상한 안에서 더 좁히는 방식이며 컴파일에는 적용하지 않는다.

실제 요청·적용 soft/hard 바이트 값은 `audit-resource-limit.json`과 `audit-result.json`에 기록한다. 주소공간은 RSS와 다르고, 이 검사는 제출 컨테이너와 동일한 환경이라는 뜻이 아니다. OOM·프로세스 실패·몰수는 원래 결과에 남기고 감사 통과를 허용하지 않는다.

`--selection-lock`으로 잠금 JSON 사본을 제공하면 빌드 전에 `primary_candidate`와 CLI 후보의 일치를 검사한다. 제공하지 않은 경우 호출자가 잠금 기록을 확인해야 하며 보고서에도 파일 검증이 없었음을 명시한다. 공식 holdout 주 후보를 결과에 따라 바꿀 수는 없다.
