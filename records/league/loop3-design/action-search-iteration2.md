# s3 두 번째 수정: 선별 탐색의 성공을 보존하고 채택 조건을 검증

완료된 첫 개발 배치에서 `s3_screen_refine`은 Y 38승/48경기, K 39승/48경기였다. v3는 각각 27승과 40승이었다. 서로 다른 맵은 8개, 상대는 고정 6종이다. 후속 실험의 **보존 부모는 `s3_screen_refine`**이며, 이 개발 결과만으로 제출 승격을 결정하지 않는다.

기존 `variants(source)`의 7개 생성 결과를 모두 원래 SHA-256과 대조해 보존했다. 새 후보 4개는 같은 v3 입력에서 `variants_iteration2(source)`로만 추가한다. 기존 제출 소스·공식 전이·관측·평가 함수는 바꾸지 않았다.

## 성공·실패 쌍을 먼저 재확인

전체 결과에서 `j_balanced_portfolio` 상대 Y 경기 중, 맵 번호가 가장 작은 패→승 사례와 승→패 사례를 각각 골랐다. 이전 [회귀 진단](s3-iteration1-failures.md)의 큰 실패 두 경기만으로 보수화하지 않기 위한 점검이며 대표성 있는 무작위 표본은 아니다.

| 항목 | 성공 사례 | 실패 사례 |
|---|---|---|
| 맵 / 첫 분기 | 8101 / 12턴 | 8103 / 10턴 |
| v3 최종 Y/K | 14/21, 160턴 패배 | 36/0, 125턴 승리 |
| 부모 최종 Y/K | 30/0, 80턴 승리 | 7/34, 160턴 패배 |
| 달라진 최초 이동 | (6,4) F가 아래 대신 위 | (6,7) F가 아래 대신 오른쪽 |
| 기본/확장 3턴 혼합 평가 | 137.516894 / 138.691263 | -48.698378 / -43.053144 |
| 혼합 평가 증분 | +1.174369 | +5.645234 |
| 상대 script별 평가 증분 | +1.420985, +0.370985, +1.757292, +0.370985 | +34.012500, +34.012500, +34.012500, -30.826964 |

두 사례 모두 첫 분기 이전의 상태·명령이 같고, 그 턴 상대 명령도 같다. 원본과 후보의 실제 출력을 재현했다. v3 65ms와 135ms의 선택, 후보 확장 직전 seed 행동도 같았다. 실제 경기 525턴과 내부 rollout 144개 전이의 병력·자원·소유를 공식 엔진으로 확인했다. 내부 평가는 합법 관측에 기반한 미공개 점수 추정과 위치 항을 포함하며 리더보드 점수나 실제 최종 점수가 아니다.

성공 사례는 3턴 점수·병력 총량 이득이 없는 작은 위치 개선이었다. 실패 사례는 상대 0~2를 가정할 때 Y가 3점을 더 얻지만, 상대 3에서는 오히려 K가 3점을 더 얻었다. 기존 75% 가중 평균 + 25% 최악값은 이 교환을 전체적으로 유리하게 평가했다. **처음 다른 행동이 최종 승패를 단독으로 만들었다는 인과 실험은 아니다.** 이 자료는 어떤 평가 위험을 다음 실험에서 분리할지 정하는 근거다.

## 기각한 변경

기본 행동 대비 평가 이득을 2/5/10 이상으로 제한하는 단순 문턱을 검토했다. 2와 5는 성공 사례의 +1.174를 버리면서 실패 사례의 +5.645를 통과시킨다. 10은 둘 다 버린다. 따라서 이 사례에 근거해 특정 숫자를 최적 문턱으로 정하지 않고, 첫 후보를 **동일 상대별 평가 차이의 하한 0**으로 바꿨다. 작은 이득 자체를 실패로 취급하는 가설은 지지되지 않았다.

## 새 후보 4개

| 후보 | 부모 대비 변경 | 가설과 주된 약점 |
|---|---|---|
| `s3_v2_screen_paired_guard` | 같은 seed와 새 행동을 같은 자기 continuation·같은 4개 상대 script·같은 3턴 깊이로 평가한다. 모든 상대에서 새 행동의 평가가 seed 이상이고 혼합 평가는 현재 최선보다 높을 때만 채택한다. | 평균 이득 뒤의 특정 상대 회귀를 막는다. 고정 상대 모두에게 유리해야 하므로 실제로 유익한 위험 감수도 기각할 수 있다. |
| `s3_v2_screen_roundrobin` | 출발지마다 후보를 하나씩 순환 선별하고, 얕은 선별 상한을 100ms에서 85ms로 줄인다. 상위 8개를 기존 깊이로 확인한다. | 특정 출발지가 선별 시간을 독점하는 것을 줄이고 깊은 확인 시간을 남긴다. 부모 상위 출발지의 좋은 후보를 놓칠 수 있으며 순서·시간 변경 효과를 따로 분리하지는 않는다. |
| `s3_v2_screen_continuation` | 상속한 continuation에서 개선된 후보만 다른 자기 continuation에서도 seed와 쌍 비교한다. 대안은 배정 정책 3, 원래 3이면 정책 0이다. 대안에서 손해가 없을 때만 채택한다. | 한 후속 정책에만 유리한 행동을 줄인다. 두 고정 정책도 실제 다음 턴 재탐색을 그대로 재현하지는 않는다. 추가 평가로 확인하는 후보 수가 줄어든다. |
| `s3_v2_screen_intact_base` | v3의 기본 탐색에 전체 135ms를 허용하고 남는 시간에 부모와 같은 선별을 수행한다. | 65ms 분할 때문에 원래 좋은 행동을 놓치는 효과를 비교한다. 기본 탐색이 길면 확장을 전혀 하지 못한다. 총 예산은 늘리지 않는다. |

첫 게이트의 비교 대상은 **각 rollout 마지막 상태의 `evaluation()` 값**이다. 개별 원점수만 비교하지 않는다. 기본 행동과 후보의 4개 응답을 모두 완료한 경우에만 `min_j(new[j] - seed[j]) >= 0`을 적용한다. 중단된 응답을 빼고 평균하거나 미완료 결과를 채택하지 않는다. 통과 후보 중에는 부모와 동일한 혼합 평가를 사용한다. 기준은 고정 seed이며 그 턴 중간 최선으로 바꾸지 않는다.

후속 정책 후보도 기준과 후보를 같은 대안 continuation으로 완전히 평가한다. 종료까지 1턴만 남으면 continuation이 영향을 주지 않으므로 중복 평가하지 않는다. 모든 후보는 135ms 협력적 예산에서 완료된 incumbent을 반환하며 공식 300ms·384MiB 적합성은 실제 리그에서 별도로 확인한다.

## 검사와 재현

`tests/test_v3_action_search.py`에 기존 7개 SHA 보존, 새 4개 고유 생성, 공식 전이·평가·합법 관측 보존 검사를 추가했다. C++20/O2로 새 4개를 각각 컴파일하고 실행해 다음을 검사한다.

- F/W 독립 대기, 부분 분할, 두 출발지 결합, 생산 예산, 도착 병력의 같은 턴 재사용 금지.
- 실제 성공·실패 평가 벡터를 사용한 게이트 반례: 작은 성공 이득 통과, 평균이 높아도 한 상대에서 크게 악화하는 경우 거부.
- 쌍 평가의 4개 결과를 모았을 때 기존 `a_evaluate()`와 같은 혼합 값.
- 예산이 이미 끝났으면 평가 결과·incumbent을 갱신하지 않음.
- 합법적인 행동 반환과 합성 상태에서 20ms 협력적 탐색이 300ms 안에 종료됨.

```bash
PYTHONDONTWRITEBYTECODE=1 python -m unittest \
  tests.test_v3_action_search.V3ActionRevisionTests -v
```

컴파일·실행 중간물은 `/tmp`의 `TemporaryDirectory` 안에만 생성해 제거한다. 검사 결과·환경·새 소스 해시·사례 증거는 [action-search-iteration2.json](action-search-iteration2.json)에 기록한다. 이 검사는 강함이나 공식 서버 실행 보장이 아니며, 부모와 새 후보의 같은 맵 양 진영 대전이 다음 판단 근거다.

사례 재현은 기존 `audit_s3_failures.py --arena records/league/loop3-iteration1 --case-selection <사례목록> --output /tmp/<새파일>.json`을 사용한다. JSON의 `matched_case_selection`을 임시 사례목록으로 저장하면 된다. 최초 사례 계측을 마친 뒤 추가한 canonical 경로 지원에서 변수 이름이 겹치는 결함을 실제 재실행 중 발견해 수정했고, 이 두 사례는 수정된 경로로 재실행해 확인했다. 과거 `s3-iteration1-failures.json`은 변경하지 않았다.
