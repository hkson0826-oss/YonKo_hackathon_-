# v3 행동 탐색 확장 — 1차 후보

기준은 `submissions/iterative-v3/main.cpp`의 `a_v2_terminal_local`이다. 제출 소스는 수정하지 않고 `experiments/local_league/v3_action_search.py:variants(source)`가 후보 7개를 생성한다. 강함은 아직 미확인이다. 아래 설계는 첫 개발 리그에서 반증할 가설이다.

## 관찰과 범위

v3는 4개 전체 정책을 평가하고 중요 출발지 3곳을 고친다. 스크립트 밖에 추가하는 행동은 해당 출발지 F/W 전량의 같은 목적지 이동뿐이다. 따라서 한 종류만 잔류, 일부 병력 잔류, 한 출발지의 두 목적지 분할, 단독으로 나쁜 두 변경의 공동 적용을 충분히 탐색하지 않는다. 이는 소스로 확인한 탐색 공간의 제약이며 모든 실제 패배의 원인이라는 주장은 아니다.

새 후보는 v3의 전이, 관측 해석, 평가 함수, 숨은 점수 추정, 생산 정책을 그대로 둔다. 먼저 최대 65ms 동안 원래 탐색을 수행하고 완전히 평가한 행동·후속 정책·평가값을 넘겨받는다. 추가 탐색을 합쳐 135ms를 사용한다. 같은 출발지의 재배치는 원래 자원과 생산량만 사용하며 도착 병력을 다시 출발시키지 않는다. 모든 새 행동은 기존 `a_clean`을 거친다.

65ms에서 원래 탐색을 나누므로 원래 v3가 65~135ms에 찾았을 개선을 잃을 수 있다. 따라서 새 탐색이 기존 최선보다 낮은 내부 평가를 채택하지 않는다는 사실이 v3 대비 승률 보장을 뜻하지 않는다. 또한 내부 상대 4종과 깊이 3의 한계도 남아 있다.

## 후보와 약점

| 후보 | 구조적 변경 | 주된 실패 가능성 |
|---|---|---|
| `s3_role_wait` | F 단독, W 단독, 둘 모두에 대해 이동·대기를 따로 평가 | 잘못된 상대 예상에서 호위가 끊길 수 있음 |
| `s3_split_reserve` | 1개·절반·1개 잔류, 두 이웃 칸으로 병력 분할 | 분산 병력이 적 합류에 각개격파될 수 있음 |
| `s3_joint_origins` | 가까운 두 출발지의 합류·교대·잔류/진행을 공동 평가 | 상위 출발지 4곳과 제한된 공동 이동 형식만 열림 |
| `s3_beam_actions` | 각 출발지 수정 후 완전 평가한 행동 3개를 유지 | 폭 3에서 전제 행동이 잘리거나 후반 출발지 시간 부족 |
| `s3_screen_refine` | 넓은 후보를 1턴 평가, 상위 8개를 원래 깊이로 재평가 | 즉시 손해를 감수하는 장기 행동이 선별에서 누락 |
| `s3_selective_contact` | 적 접촉·미점령 건물·종반에 관련된 출발지만 세밀하게 제어 | 접촉 전 전략적 분할을 놓침 |
| `s3_revisit_search` | 좌표 탐색 후 역순 재방문, 최대 2회 | 국소 최적·상대 모델 오류는 여전히 남음 |

`s3_selective_contact`는 해당 출발지가 없으면 v3 원래 판단에 전체 예산을 준다. 다른 후보는 동일한 출발지 중요도 순서와 상위 4곳을 사용한다. Beam은 낮은 중간 평가의 완성 행동도 제한적으로 남기며, 공동 수정은 두 변경을 하나의 완성 행동으로 평가하므로 단독 변경의 채택 여부에 의존하지 않는다. 선별 후보의 1턴 점수는 기존 3턴 최선과 직접 비교하지 않는다.

## 원문 근거와 적용 한계

- [Moraes·Lelis, Asymmetric Action Abstractions (2017)](https://arxiv.org/html/1711.08101): 일부 유닛만 세밀하게 제어하는 비대칭 추상화와 PGS/SSS의 국소 최적 정체를 확인했다. 이 게임에서는 출발지·병종 묶음을 선택적으로 연다. 논문의 최적 전략 값에 대한 이론은 제한 시간 근사 탐색의 승률 보장이 아니다. 원문은 주로 전투 장면을 다루며 이 게임의 점령·경제·미공개 점수 전체와 같지 않다.
- [Ontañón, Combinatorial Multi-armed Bandits (2017)](https://arxiv.org/html/1710.04805): 개별 행동 통계로 조합을 탐색하되 완성 조합 자체의 값을 보관하는 구분을 확인했다. 여기서는 그 구분을 공동 행동 평가와 beam에 반영했다. CMAB/MCTS를 그대로 구현한 것은 아니며 논문의 수렴 성질을 주장하지 않는다. 호위·동시 합류의 강한 상호작용 때문에 개별 행동의 이득을 단순 합산하지 않는다.
- [Barriga·Stanescu·Buro, Combining Strategic Learning and Tactical Search (2017)](https://arxiv.org/html/1709.03480): 전략 정책과 적 접촉 유닛의 전술 탐색을 결합하는 방법을 확인했다. 여기서는 기존 C++ 정책이 전략 초기점을 제공하고, 실제 전체 상태로 전이를 평가한다. 논문의 CNN·가중치·축약 전투 상태를 사용하지 않는다. 접촉 전 전략 오류를 전술 검색만으로 해결하지 못한다는 한계는 남는다.

Firecrawl configured MCP에서 연구 검색 → 관련 논문 확장 → 메타데이터 및 본문 확인을 수행했다. `read_paper`는 스킬 예시의 `id`가 실제 서버 스키마와 달라 처음 거부되었고, `paperId`로 재시도해 성공했다. 후속 후보인 상태 조건부 MCTS 추상화(arXiv:2406.00614)는 학습된 동역학과 결합하므로 이번 고정 규칙 C++ 구현에는 직접 적용하지 않았다. 진화 기반 micro 논문(arXiv:1803.10316, 1803.10314)은 연구 인접 자료로 남기며 이번 후보의 검증된 구현 근거로 사용하지 않는다.

## 검증과 다음 수정 기준

검사 명령: `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p test_v3_action_search.py -v`. 빌드·실행 파일은 `TemporaryDirectory(dir='/tmp')` 안에만 둔다. 원본 전이·평가·관측 불변, 7개 소스 구별, C++20/O2 빌드, F/W 독립 잔류, 부분 분할·공동 합류, 생산 병력 보존, 미완료 평가 거부와 시간 만료 fallback을 검사한다. 테스트 결과 및 고정 소스 해시는 `action-search-validation.json`에 기록한다.

성능 채택은 별도 공식 엔진 리그의 같은 맵 양 진영 비교로 결정한다. v3·v2·팀원·기존 강한 후보를 포함하고 오류·몰수·출력·300ms·384MiB 제약을 별도로 확인한다. 1차 결과를 보고 수정한 시드는 개발 집합이며 새 선택/최종 검증 시드를 사용한다. 첫 실전 패배에서 행동의 부재, 잘못된 평가, 탐색 시간 부족 중 확인 가능한 원인을 분리한 후 `variants_iteration2(source)`에만 새 후보를 더한다. 현재 후보를 실행 중 덮어쓰지 않는다.
