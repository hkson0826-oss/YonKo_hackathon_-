# 최종 후보 게이트 독립 재집계

`ff8b2063bc86c5649741efa08f827a027ee954fd`의 회수본 9,198경기를 직접 읽어 **주후보 `f3_v2_warrior_reserve`의 기존 holdout·crossplay 게이트 11개가 모두 통과하며 기록과 일치함**을 확인했다. 다음 32맵 추가 감사와 최종 패키징은 이 검토 시점에 미완료다. 이후 단계까지 통과했다고 해석하지 않는다.

기존 분석 helper를 사용하지 않고 각 경기 `result.winner`에서 승점을 다시 계산했다. 모든 단계의 계획·jobs·결과 조건과 개수를 대조했고 중복·누락 없이 오류 0, 몰수 0이었다. smoke 50, 개발 2,560, 선택 2,688, holdout 3,840, crossplay 60경기다. 잠금·manifest·실제 소스/팀원 ZIP 해시도 일치했다. 입력 SHA와 세부 재집계는 [JSON](final-gate-independent-review.json)에 보존했다.

## 표본과 시간 한계

개발 8맵의 결과는 후보 수정과 상대 선정에 사용됐고, 선택 24맵도 주후보 선정 자료다. 이 두 구간을 독립 검증 성적으로 합치지 않는다. 80개 holdout 맵은 선택과 분리됐지만 상대는 제한된 고정군이며 다수가 v2/v3 기본 구조를 공유한다. 수치와 CI는 실제 미지의 참가자나 리더보드 보정 점수에 대한 보장이 아니다.

주후보의 holdout 관측 응답은 183,645개, p95 **68.448ms**, 최대 **129.449ms**였다. 후순위 s3는 182,906개, p95 122.479ms, 최대 177.433ms이며 135ms 초과 관측 응답은 725개였다. 이것은 **스케줄링·프로토콜 입출력을 포함한 실제 응답시간**이 내부 135ms 탐색 예산보다 길었다는 관측이다. 이 사실만으로 내부 탐색 제한 위반이나 버그라고 단정할 수 없다. 두 후보 모두 러너의 공식 일반 턴 300ms/첫 턴 3000ms 제한을 통과했다.

135ms는 계산 중간에 확인하는 협력적 탐색 예산이며 정책 생성·전이 한 덩어리를 강제로 선점하지 않는다. 현재 주후보에서는 135ms 초과 관측이 없었지만 다른 CPU·컴파일러·부하에서 같은 최대값을 보장하지 않는다. 이번 리그는 프로세스별 384MiB 주소공간 제한을 적용했으며 RSS/cgroup 제한이나 공식 컨테이너와 동일한 재현은 아니다. 주후보의 별도 32맵 감사와 최종 ZIP의 GCC 12.2·CPU 검사가 남아 있다.
