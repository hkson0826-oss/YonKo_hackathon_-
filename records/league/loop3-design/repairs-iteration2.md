# f3 2차 수정: 생산 편향과 거점 호위 분리

완료된 [1차 개발 리그](../loop3-iteration1/README.md)를 보고 만든 네 후보다. 기존 여섯 후보의 생성 소스는 바꾸지 않았다. 입력은 기존 v3 소스이며 `variants_iteration2(source)`가 새 후보만 반환한다. 새 후보의 승률은 아직 측정하지 않았다.

## 관찰에서 수정으로

1차는 시드 8100–8107, 고정 상대 6종, 진영별 48경기다. v3는 Y 27승/K 40승, `f3_matching`은 30/35승, `f3_econ_mission`은 30/38승이었다. 이 두 부모를 비교군으로 유지한다. `f3_supply_flow`는 24/26승, `f3_flow_mission`은 26/26승이어서 이번에는 생산 흐름 추정을 더 조정하지 않는다. 작은 개발 표본이며 f3 두 부모의 Y 개선 구간도 0을 포함한다.

[8100/8103 패배 분석](f3-iteration1-failures.md)은 추가 F가 항상 유효하지 않고, 더 많은 W 생존이나 경제 거점 하나의 보존도 승리를 보장하지 않는다는 반례다. 특히 [8100 실제 결정 계측](f3-opening-audit.md)에서 원래 평가는 W4 계획을 F1/W2 계획보다 2.4 높게 평가했지만, 일대일 접근 보정은 순위를 4.73878968만큼 바꿨다. 세 번째 턴에 추가 경제 임무는 생성되지 않았으므로 여기서는 임무 생성이 원인이 아니다. 같은 관측과 계획에서 평가 변경이 초기 선택을 바꿨다는 것까지 확인했으며, 이 첫 생산 차이가 전체 패배의 원인이라는 증명은 아니다.

반대로 **8101/Y 대 v3**에서는 matching이 22:6으로 승리하고 대응 v3는 6:24로 패했다. 두 경기는 3턴 직전까지 실제 상태와 상대 명령이 같았다. 첫 물리적 차이는 F 한 개가 `(2,6)→(1,6)`으로 이동한 것이며, v3는 `(2,6)→(2,7)`로 이동했다. 양쪽 생산은 F1/W1로 같았다. 공식 엔진으로 두 경기 320개 상태를 재현했다.

| 8101 Y 전체 경기 | matching | v3 |
|---|---:|---:|
| ENG 할인 적용 생산 턴 | 146 | 155 |
| 수입 단계 HALL 소유 개수의 합 | 127 | 113 |
| 수입 단계 실제 자원 증가 | 1,854 | 1,826 |
| F 생산 / 사망 | 23 / 17 | 26 / 20 |
| W 생산 / 사망 | 759 / 684 | 758 / 664 |
| 최종 W | 75 | 94 |

이 승리는 생산량이나 병력 보존량의 단순 우위로 설명되지 않는다. 접근 평가가 유효한 이동을 고르는 사례가 있다는 관찰이며, 첫 이동이 이후 결과를 유발했다는 인과 주장은 하지 않는다. 따라서 생산 선택 편향은 줄이고 이동 차별화는 남기는 후보를 분리했다. 이 사례도 개발 자료로 편입되며 독립 검증에 재사용하지 않는다.

## 네 후보와 반례

| 후보 | 실제 변경 | 남는 약점 |
|---|---|---|
| `f3_v2_soft_matching` | 원래 접근 평가에 일대일 보정의 40%만 적용한다. | 40%는 위 계획 쌍의 순위를 보존하는 개발 선택이다. 다른 맵의 추가 F 한계가치를 교정한다는 보장은 없고 좋은 이동 신호도 약해진다. |
| `f3_v2_movement_matching` | 초기 네 계획은 v3 평가로 고르고, 생산을 고정한 국소 이동만 matching 평가로 비교한다. | 생산·이동의 결합 개선을 놓칠 수 있고 척도 전환 재평가에 시간을 쓴다. |
| `f3_v2_safe_econ_mission` | 추가 경제 임무가 다른 보유 거점의 원래 안전한 F/W 방어를 새로 깨는 경우 그 임무만 제외한다. | 낮은 가치 거점을 버리는 유리한 교환을 놓칠 수 있다. 원래 네 계획의 위험 행동까지 차단하지는 않는다. |
| `f3_v2_warrior_reserve` | 적 F 진입 또는 아군 F 사망 위험이 있는 보유 거점에서 필요한 W만 남기는 선택지를 추가한다. F 이동과 생산은 유지한다. | 인접 적의 최대 집중을 보수적으로 가정한다. 도달 가능한 적 생산 F/W는 동시 비용 제약을 완화한 상한이므로 과잉 방어가 가능하다. |

`movement_matching`은 평가 척도 전환 시 incumbent도 새 척도로 완전히 다시 평가한다. 이를 끝내지 못하면 이미 완성된 초기 행동을 반환한다. 이후 `a_local`의 `a_patch`와 `a_clean`은 그 행동의 생산을 보존한다. 같은 총 135ms 탐색 예산을 쓰며 새로운 별도 예산을 추가하지 않았다.

두 방어 후보는 합법 관측의 현재 병력·생산 자원과 한 칸 도달 가능성만 사용한다. 이동 후 도착 병력을 진단에 합산하되, 도착 병력을 같은 턴에 다시 출발시키지 않는다. W reserve는 이미 출발하도록 계획된 해당 거점의 W 일부만 취소한다. 병력이 부족하면 후보를 만들지 않고, 충분하면 필요한 최소 수를 남긴다. 기존 계획을 강제 덮어쓰지 않고 기존 평가·상대 모델과 비교한다. 7338의 F 강제 대기 실패와 8103의 다른 거점 손실 반례 때문에 모든 F를 강제로 묶는 변경은 넣지 않았다.

## 확인한 범위

- 기존 여섯 생성 소스 SHA가 기존 manifest와 동일하고 새 네 후보는 서로 다른 소스다. v3 원본·공식 전이·상대 정책은 변경하지 않았다.
- C++ 임시 빌드와 규칙 검사를 `/tmp`에서 실행하고 정리했다. 검사 명령은 `PYTHONDONTWRITEBYTECODE=1 python -m unittest tests.test_v3_repairs -v`다.
- 실제 8100 합법 관측에서 soft/movement 두 후보는 3턴 F1/W2 생산 편향을 제거하고 W4를 선택했다. 이는 그 상태의 결정 검사이며 경기 승리 검사가 아니다.
- 실제 8101 합법 관측에서 movement-only 후보는 matching의 첫 F 이동 `(2,6)→(1,6)`을 보존했다.
- 양 진영·4개 턴의 합성 상태에서 movement-only의 최종 행동 생산이 v3 생산과 같다. 척도 전환의 재평가·중단 분기도 검사한다.
- 경제 임무가 다른 보유 거점의 F 호위를 빼앗으면 제외하고, 위협이 사라지면 허용하는 조건 반례를 검사했다.
- W20 거점으로 적 W9/F1이 진입하는 반례에서 W10만 남기는 행동을 공식 엔진에 넣어 소유권 유지, 아군 W1 생존, 적 F 제거를 확인했다. 부족한 병력·위협 없는 상태·도착 병력 재사용은 허용하지 않는다.
- 45개 합성 상태의 양 진영·네 정책·모든 거점에서 생성된 방어 행동의 재고, 생산비, 이동·순간이동 제약을 확인했다.

정량 근거·입력 SHA·새 후보 SHA·검사 결과는 [repairs-iteration2.json](repairs-iteration2.json)에 있다. 8101 수입·생산 계산은 기존 [분석 함수](../../../experiments/analyze_gain_cases.py)의 `REPLAYS`를 `records/league/loop3-iteration1/runs/development/replays`로 지정한 뒤 JSON의 두 `matched_success` 항목을 `check_case(map_seed, candidate, job_id, sha256)`에 전달하면 재현된다. 함수가 반환하는 과거 고정 상대 라벨 `v2`만 실제 메타데이터 `v3`로 정정했으며, 수치 계산은 그대로다.

다음 리그는 새 개발 시드와 강화 상대 `s3_selective_contact`, `r3_opponent_league`를 포함하여 네 수정의 실제 손익을 비교한다. 여기서 확인한 국소 결정 개선을 전체 승률 개선으로 간주하지 않는다.
