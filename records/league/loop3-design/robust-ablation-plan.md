# r3 요소별 비교 계획

첫 개발 배치 결과를 보기 전 코드 검토다. 현재 생성기와 최초 8개 후보는 변경하지 않는다. 비교 기준은 고정 제출 `v3`이며, 아래의 신규 대조군 이름은 **결과 후 필요할 때 만들 가설**이다.

## 현재 코드에서 함께 바뀌는 것

v3는 135ms 안에서 자체 정책 4개를 먼저 비교하고, 중요 출발지 3곳의 정책 교체·인접 F/W 전량 이동을 순차 탐색한다. 각 행동은 상대 정책 4개를 각각 고정한 깊이 최대 3으로 평가하며 `평균 75% + 최악 25%`를 쓴다. 미래 우리 행동은 해당 `APlan.continuation` 정책이다. 모든 깊이는 남은 턴 수에 의해 줄어든다.

| 후보 | 평가 상대·목적 | 깊이 / 계산 예산 | 첫 행동 후보·continuation 변화 | 반드시 보존할 부모 |
|---|---|---|---|---|
| `r3_lower_tail` | 기존 4종, 평균 50%+하위 2종 평균 50% | 3턴·135ms, 기본 전이 수는 v3와 같음 | 자체 후보와 continuation 규칙은 v3와 같음 | v3, 아래 4종·3턴 공통 대조군 |
| `r3_opponent_league` | 4종+F/W 혼합+F 사냥, 75/25 | **2턴**·135ms, 6×2 전이. 추가 모델 자체 생성 비용 존재 | 후보 규칙은 같아도 실제 평가 완료 개수는 달라짐 | v3, 4종·2턴 대조군 |
| `r3_switching_adversary` | 매 단계 4종 중 한 턴 뒤 평가가 최악인 응답을 선택, 하나의 적대 경로 | 3턴·135ms, 단계당 4전이. own continuation은 선택한 경로에서 재계산 | 자체 후보 규칙은 같음. **고정 상대 집합+75/25에서 동적 탐욕 최소로 동시에 변경** | v3, 고정 4종의 순수 최악 평가 대조군 |
| `r3_local_counter` | 4종의 첫 응답에서 상대 W 한 출발지 이동/대기를 국소 수정, 75/25 | **2턴**·135ms+국소 검사 | 우리 후보/continuation은 유지. 상대 **첫 턴만** 수정하고 다음 턴은 원래 j 정책 | 4종·2턴 대조군, 이 후보 자체 |
| `r3_joint_counter` | 첫 응답에서 최대 두 출발지를 순차 수정 | 2턴·135ms, 국소 검사 증가 | `local_counter` 대비 **출발지 1→2와 W만→F/W 공동 수정이 동시에 변경**. 완전한 두 출발지 조합 탐색은 아님 | `r3_local_counter`, 필요 시 2출발지 W만 대조군 |
| `r3_population_fit` | `opponent_league`와 같은 6종, 직전 관측 오차 기반 평균 가중치+최악 25% | 2턴·135ms. **추가 6개 한 턴 역검사가 자체 탐색 시간을 소비** | 후보 규칙과 continuation은 같음. 시간 부족이면 탐색 범위는 달라짐 | `r3_opponent_league`, 동일 역검사 비용·균등 가중치 대조군 |
| `r3_minimax_regret` | 별도 최대 5×6 행렬에서 최대 기회손실 최소화 | **v3 탐색 65ms** 후 전체 135ms 내 2턴 행렬. 미완성이면 65ms 행동 복귀 | 최종 후보는 65ms 국소 행동+원래 4정책. **국소 행동의 continuation을 0으로 재설정**하고 나머지 행은 j 유지 | v3, v3 65ms, 같은 행렬의 75/25 선택 대조군 |
| `r3_mixed_matrix` | 같은 행렬에 256회 양측 regret matching, 평균 혼합 표본화 | 위와 같고 행렬 반복·표본화 비용 추가 | 위와 같으며 **난수 표본화** 추가. 원래 고정 RNG seed를 사용하므로 독립 정책 seed 다양화는 하지 않음 | `r3_minimax_regret`, 같은 행렬의 순수 maximin 대조군 |

공통 차이도 무시하면 안 된다. 최초 6종의 `r3_fixed`는 기존 4상대에도 `a_clean`을 적용하지만 v3 내부 상대는 `policy`를 바로 전이한다. 원본 정책이 이미 합법이면 같지만, **모든 관측에서 무효과라고 아직 입증하지 않았다.** 최초 6종은 평가 마지막에도 deadline을 검사하여 결과를 버리며, v3는 다음 전이 직전에만 검사한다. 이 차이는 제한 직전의 채택·복귀에 영향을 줄 수 있다. 행렬 두 후보의 65ms 기준 탐색은 원본 v3 evaluator를 그대로 사용하고, 행렬 상대에는 `a_clean`을 적용한다.

`lower_tail`을 단순히 “더 보수적”이라고 해석하지 않는다. 값이 `[-100,10,10,10]`이면 v3 목적값은 −38.125, lower-tail은 −31.25로 오히려 단일 최악값의 영향이 작다. 또한 위의 전이 개수가 같아도 정책 생성 비용과 초기에 끝나는 승패 상태 수는 달라서 같은 CPU 작업량은 아니다.

## 결과 후 최소한의 원인 분리

첫 배치로는 **구현 전체의 상대 성능**을 비교한다. 특정 기능의 효과라고 단정하지 않는다. 모든 최초 후보의 ID·소스 SHA와 v3를 보존하고, 개선 또는 큰 회귀가 관찰된 계열만 다음 대조를 추가한다.

1. 상대 확대/국소 대응이 유망하면 **동일한 r3 공통 처리·4상대·75/25·깊이 2**를 우선 대조군으로 둔다. v3보다 좋아도 이것만큼 좋다면 다양성보다 깊이/탐색 처리량의 효과일 수 있다. lower-tail 분석에는 같은 공통 처리의 깊이 3 대조군이 필요하다.
2. 공동 대응이 유망하면 `local_counter`를 버리지 않는다. 먼저 2출발지 W만으로 출발지 수 효과를 분리한 후, F 동반 수정의 효과를 비교한다. 두 번의 개별 수정이 이득을 못 내지만 조합은 이기는 반례는 현재 순차 방식의 명확한 한계다.
3. 관측 적합도가 유망하면 `opponent_league`와 비교하고, 필요할 때 역검사를 똑같이 수행하되 균등 가중치를 유지한 대조군으로 시간 비용을 맞춘다. 예측 오차 감소와 승률 향상은 따로 보고한다.
4. 행렬 방식이 유망하면 먼저 **65ms 기준 행동만 반환**하는 부모를 보존한다. 같은 후보/continuation/행렬에서 75/25, 순수 maximin, minimax regret, 혼합을 비교해야 선택 목적의 효과를 주장할 수 있다. 국소 부모의 실제 continuation 보존은 별도의 수정으로 분리한다.

추가 진단은 재생한 합법 관측의 동일 입력에서 완성 평가 수, 마지막 완료 시점, 행렬 완성·채택·복귀 비율, 선택 action/continuation을 측정하면 된다. 현재 동결된 봇에 계측을 삽입하지 않고 이후 별도 진단 빌드로 수행한다. 같은 초기 맵을 쓰는 전체 경기 비교는 중간 상태까지 동일한 비교가 아니다. 개발 결과로 정한 새 후보·공략 상대는 다음 실행 전에 다시 고정하고, 선택·최종 검증 시드나 사전 승격 기준은 바꾸지 않는다.
