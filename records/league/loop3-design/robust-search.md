# v3 상대 불확실성 후보: 실행 전 설계

기준선은 제출 v3(`52268569e17d7fc40fd46f0996b2da684768902b4af27ec059c4b068911c4473`)다. 실제 상대 정책이나 관측 파서·공식 전이·종반 평가는 바꾸지 않는다. 우리 행동의 평가에 쓰는 내부 상대 모델과 작은 행렬의 선택 방식만 바꾼다. 패배 분석 담당의 직접 수리, 행동 탐색 담당의 F/W 분할·대기 개선과 별도 계열이다.

## 실행 전에 판단한 약점과 비교

| ID | 변경 가설 | 실패 가능성과 반례 | 예산 |
|---|---|---|---|
| r3_lower_tail | 평균 50%+하위 2상대 평균 50% | 네 정책 밖의 응답은 못 보고 지나치게 보수적일 수 있음 | 4상대×3턴 |
| r3_opponent_league | 기존 4종+F/W 혼합+F 사냥 2종 | 모델 다양성과 깊이 감소가 함께 바뀜. 먼 전략 대응은 부족 | 6상대×2턴 |
| r3_switching_adversary | 매 예상 턴 상대가 우리 다음 상태 평가를 가장 낮추는 정책 선택 | 동시행동 상대가 실제 우리 명령을 본다는 가정은 불가. 내부 최악 대응 시험으로만 사용. 탐욕적 한 턴 최소라 장기 최악 경로 아님 | 4응답×3턴 |
| r3_local_counter | 가까운 상대 W 출발지 1곳의 인접 이동/대기 탐색 | 거리가 먼 W와 두 부대가 함께 가야 이득인 공략을 놓침 | 4상대×2턴+첫 턴 국소 응답 |
| r3_joint_counter | 상대 출발지 2곳 F/W 전량 공동 이동을 순차 수정 | 첫 수정만으로 이득이 없으면 두 수정의 시너지를 못 발견. 완전 조합 탐색 아님 | 위 항목의 출발지 최대 2곳 |
| r3_population_fit | 공개된 직전 전이 오차로 6상대 가중, 각 최소 10% | 관측 오차가 전략 오차만은 아니고 전략 전환에 지연. 예측 적합도가 승률과 동일하지 않음 | 6개 한 턴 역검사+6상대×2턴 |
| r3_minimax_regret | v3 국소 행동+4정책의 완성 행렬에서 최대 기회손실 최소화 | 최저 절대 성과를 최대화하는 maximin과 다름. 후보별 미래 스크립트 가정이 다르고 기준 행동은 style 0으로 연장 | 기준 탐색 65ms+최대 5×6×2턴 |
| r3_mixed_matrix | 같은 행렬에서 양측 regret matching 256회 후 평균 전략 표본화 | 전체 게임 Nash 보장 없음. 행렬 오차·정책 난수의 분산. 혼합의 지원집합은 최대 5개뿐 | 위 항목+작은 행렬 반복 |

모든 후보의 공통 deadline은 decide 시작부터 135ms다. 미완성 경로/상대 집합/행렬을 평가값으로 채택하지 않는다. 행렬 미완성 시 65ms 내 완결된 기준 탐색 행동으로 복귀한다. cooperative 시간 검사여서 마지막 policy+advance 한 덩어리, 초기 네 정책 생성 등은 초과할 수 있다. 공식 300ms 보장은 별도 CPU/제출 검증이 필요하다. 군집 수, 출발지 수, 원점 물량, 생산 예산, 순간이동 1회 제한은 기존 `a_clean`을 재사용한다. 도착 물량은 같은 턴 이동 풀에 다시 넣지 않는다.

## 논문 원문 확인과 실제 적용 범위

2026-09-28 KST에 configured Firecrawl MCP research-index를 검색하고 관련 문헌 확장 및 본문 확인을 수행했다. [원문 수집 기록](robust-search-sources.json)에 도구 결과를 남겼다.

- [Hannan consistent selection 분석](https://arxiv.org/abs/1804.09045): 동시행동 게임에서 단순한 무후회 선택만으로 트리 전체 수렴이 보장되지 않으며 공동 행동 가치의 평균화 등의 조건이 필요함을 본문에서 확인했다. 여기서는 완성된 작은 정상형 행렬의 regret matching만 빌린다. MCTS·CFR 또는 논문의 수렴 정리를 구현했다는 주장은 하지 않는다. 관련 선행 [1310.8613](https://arxiv.org/abs/1310.8613)도 함께 확인했다.
- [RTS 상대모델 정확도 연구](https://arxiv.org/abs/2006.08659): 제한 예산에서 모델 비용과 자체 탐색의 교환, RHEA의 상대모델 오류 민감도를 본문에서 확인했다. 본 게임은 논문의 RTS가 아니므로 `population_fit`의 우월성 근거로 쓰지 않는다. 동일 예산에서 고정/혼합/동적 응답을 비교하는 반증 가능한 가설로 사용한다.
- [Anytime PSRO](https://arxiv.org/abs/2201.07700): 단조 exploitability 보장은 상대를 제한하지 않는 정확한 대응 조건에 연결되며 RL 근사 APSRO에는 같은 보장이 없음을 본문에서 확인했다. 이번 구현은 여섯 휴리스틱 응답만 탐색하므로 APSRO 구현이나 exploitability 감소 보장이라고 부르지 않는다. 다음 배치에서 v3 공략형 후보를 고정 상대에 추가하는 운영 원리만 차용한다.
- [행동 다양성 연구](https://arxiv.org/abs/2103.07927), [단일 정책 응답으로 경험 게임 해석](https://arxiv.org/abs/2106.01901), [XDO](https://arxiv.org/abs/2103.06426), [EGTA 전략 탐색 평가](https://arxiv.org/abs/2105.10423)는 검색·관련 문헌 확장에서 보존했다. 현재 DPP, 신경망, extensive-form double oracle는 구현하지 않았다. 특히 다양성 자체를 성능으로 간주하지 않고 고정 기준선과 새 공략 상대를 함께 평가한다.

## 예정 검증

1. 8개 소스의 구분, 원본 v3 불변, 관측·전이·실제 정책 보존 검사.
2. `/tmp` 전용 빌드와 정합성 검사: 원점 물량·혼합 생산·재이동 방지, 관측 가중치, 미완성 평가 기각, matching pennies/지배 전략/최대 regret 행렬 반례.
3. 국소 상대가 F 거점을 공격하는 반례를 공식 `engine.pipeline.run_turn`으로 대조.
4. root의 별도 개발 시드 양 진영 리그에서 v3 대비 상대별 결과·시간·몰수 확인. 첫 배치 이전에 어떤 후보도 개선 확정으로 취급하지 않는다. 개발 결과를 보고 새 ID의 revision을 작성하며 최초 8개 소스는 보존한다.

## 사전 검사 완료

7개 검사 통과(20.306초). 8소스 C++20 구문 빌드와 O2 브리지, 960개 모델 행동, 공식 엔진 F 피격 반례, 혼합 행렬·관측·만료 검사를 확인했다. 첫 검사에서 공학관 W 할인으로 생산 수가 3인데 테스트가 2로 가정한 오류를 발견해 테스트를 공식 비용 계산식으로 고쳤다. 후보 소스 변경은 없었다. [소스 해시와 검사 범위](robust-search-validation.json)를 남겼으며, 실제 승률은 root의 첫 배치를 기다린다.
