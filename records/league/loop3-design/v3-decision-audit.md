# 7338 / Y / 121턴: 대기 후보는 있었고, 평가에서 탈락했다

**이 사례의 직접 원인은 F 대기 후보 부재가 아니다.** 원래 네 스크립트 중 3번이 해당 F를 남겼고, 국소 탐색도 이 대안을 다시 평가했다. 내부 3턴 평가는 위로 이탈하는 행동을 더 높게 매겼다. 따라서 이 사례를 대기 행동 추가만으로 해결했다고 주장하면 안 된다.

입력은 [기존 리플레이](../loop2-iteration2/runs/holdout/replays/f68cd4938fe81851c1314689.json.gz), 원본은 `submissions/iterative-v3/main.cpp` SHA-256 `52268569e17d7fc40fd46f0996b2da684768902b4af27ec059c4b068911c4473`이다. [재현 스크립트](../../../experiments/audit_v3_decision.py)와 [계측 원문 JSON](v3-decision-audit.json)을 보존했다.

## 관측·시간 검증

공식 엔진으로 120개 선행 상태 전이를 검증하고, 각 시점에 `serialize_turn(state, "Y", turn)`을 호출했다. 원본 봇에는 INIT와 **1~121턴 합법 관측**만 전달했다. 121턴에도 건물 ID 2·4·6·8의 점수는 `-1`이며, 봇은 원래 코드의 대칭 추정으로만 이를 채웠다. 실제 미공개 점수나 상대의 미래 명령을 검색 입력에 넣지 않았다.

원본 바이너리는 관측 121개에서 원래 `decide()`를 실행했다. 계측 바이너리는 1~120턴의 소유권·점수 공개·점령 누적 이력을 원래 코드로 갱신한 뒤 탐색만 생략했고, 121턴부터 후보 값을 수집했다. v3는 상대 기억 기능이 꺼져 있어 이전 탐색 결과를 다음 결정에 사용하지 않는다. **원본 121턴 출력 = 계측 출력 = 저장된 실제 경기 명령**이 문자열 단위로 일치했다.

계측 검색 시간은 **64.04ms**, 제한으로 중단된 평가 **0회**였다. 모든 로그 출력과 별도 반사실 계산은 원래 결정을 반환한 뒤 수행했다. 계측 배열 저장 자체의 시간 영향은 있을 수 있지만, 이번 입력에서는 선택이 바뀌지 않았고 135ms 한도에 걸리지 않았다. 이 결과를 모든 환경·모든 턴의 시간 보장으로 일반화하지 않는다. 빌드·실행 파일은 `/tmp`에서 만들고 정리했다.

## 실제 후보와 선택 경로

관심 거점은 STATION `(8,10)`, 셀 158이며 직전 아군 F는 1기다.

| 초기 스크립트 | 해당 F 행동 | 3턴 집계 평가 |
|---|---|---:|
| 0 | 오른쪽 `(9,10)` | -558.2935 |
| 1 | 오른쪽 `(9,10)` | -569.4632 |
| 2 | 오른쪽 `(9,10)` | -570.1148 |
| 3 | 대기 | -525.5898 |

초기 최선은 대기하는 스크립트 3이었다. 국소 탐색 출발지 상위 3개는 `(8,10)` **11.00**, `(1,13)` **11.00**, `(2,7)` **10.83**으로, 관심 거점은 **1순위**였다. 해당 출발지에서 오른쪽 이동 -514.7857, 대기 -525.5898을 비교한 다음, 자유 인접 이동의 **위쪽 `(8,9)` -511.2077**을 채택했다. 아래는 -515.5316, 왼쪽은 -532.2057이었다. 뒤의 두 출발지에서는 이를 엄격하게 개선하는 후보가 없었다.

총 25개 평가 로그 중 F를 남기는 항목은 초기 3번과 국소 로그 5번이다. 최종 선택에서 `MOVE 8 10 F 1 U`만 제거한 행동은 **초기 스크립트 3 전체 행동과 정확히 같았다.** 즉 다른 생산·이동·우선순위 차이가 섞인 대기 비교도 아니다.

## 상대 모델별 깊이 1·2·3

각 칸은 `이탈 / 대기`의 평가값이다. 둘 다 첫 행동 이후 우리 continuation은 원래 선택된 **스크립트 3**을 사용한다. 아래는 검색 종료 뒤 같은 합법 상태에서 별도 재계산한 내부 시뮬레이션이며, 공식 경기의 다음 세 턴을 재현한 것은 아니다.

| 상대 스크립트 | 121턴 / 깊이 1 | 122턴 / 깊이 2 | 123턴 / 깊이 3 |
|---|---:|---:|---:|
| 0 | -376.188 / -379.404 | -396.019 / -371.628 | -456.052 / -435.635 |
| 1 | -376.188 / -379.404 | -482.244 / -457.853 | -528.662 / -511.445 |
| 2 | -380.596 / -383.812 | -486.022 / -461.630 | -531.321 / -510.904 |
| 3 | -487.062 / -468.195 | -579.337 / -561.479 | -501.979 / -576.498 |

집계식 `0.75 × 네 모델 평균 + 0.25 × 최악값`은 이탈 **-511.2077**, 대기 **-525.5898**로, 이탈에 **14.3821**의 우위를 준다. 세 모델에서는 깊이 3에도 대기가 더 좋지만 3번 모델에서 반대가 된다. 최악값의 모델도 이탈에서는 2번, 대기에서는 3번으로 바뀐다.

0~2번은 첫 턴 상대 F가 역으로 들어오지 않는다고 예측한다. 반면 **3번은 실제와 같은 `MOVE 8 9 F 1 D`와 인접 W의 아래 이동을 예측**한다. 따라서 모든 상대 모델이 이 공격을 누락했다는 설명도 틀리다. 다만 상대의 전체 행동이 공식 경기와 완전히 같다고 확인한 것은 아니다.

3번 모델의 소유권 경로는 다음과 같다.

| 첫 행동 | 121턴 | 122턴 | 123턴 |
|---|---|---|---|
| 이탈 | N | K | K |
| 대기 | Y, 양쪽 F 공존 | N | K |

대기한 경로에서 122턴 우리 continuation은 다시 **`MOVE 8 10 F 1 U`**를 생성한다. 즉 첫 턴의 수비를 후속 정책이 유지하지 않는다. 123턴 내부 전체 점수는 이탈 13:22, 대기 13:26이고, 아군 F는 각각 6기·5기다. 거점 하나의 소유권은 둘 다 K이므로 최종 평가 차이는 다른 거점과 병력 변화까지 포함한다. “다음 턴 이탈”은 확인됐지만, 이것 하나만이 14.3821 전체 차이를 만든다는 요소별 인과 검증은 수행하지 않았다.

## 공식 엔진 한 턴 검증과 해석 범위

실제 상대 121턴 명령을 두 봇 프로세스가 끝난 **뒤에만** 읽고, 공식 Python 엔진에 넣었다.

| 아군 행동 | 거점 소유권 | 게임 점수 Y:K |
|---|---|---:|
| 원래 선택 | N | 11:18 |
| 해당 F만 대기 | Y | 13:18 |

원래 선택의 공식 다음 상태는 저장 스냅샷 전체와 일치했다. 대기는 해당 턴 2점 보존에 성공한다. 그 이후 상대 반응이 달라지는 전체 경기의 승리나 최적성은 검증하지 않았다.

확인된 구현 효과는 **대기 후보의 존재**, **모델 3의 인접 F 공격 예측**, **대기 후 continuation의 이탈**, **3턴 집계가 이탈을 선택한 과정**이다. 남은 가설은 현재의 1턴 국소 변경과 고정 continuation 사이의 불일치가 수비·경제 임무를 과소평가한다는 것이다. 반복 대기·안전 조건부 임무 유지·후속 국소 재탐색 등을 별도 후보로 검증할 수 있으나, 이를 적용하려면 현재 진행 중인 리그 결과와 새 개발 실패를 함께 읽고 새 revision을 만들어야 한다. 동결된 v3와 최초 f3 후보는 변경하지 않았다.

재현 명령:

```bash
PYTHONDONTWRITEBYTECODE=1 python experiments/audit_v3_decision.py \
  --output /tmp/v3-decision-audit.json
```

결과를 저장할 경로만 인자로 받으며, 원본 리플레이·후보·서버·Git은 수정하지 않는다. CPU 속도나 실행 부하가 달라 출력 불일치 또는 시간 중단이 생기면 JSON의 일치 여부·중단 수를 먼저 확인해야 한다.
