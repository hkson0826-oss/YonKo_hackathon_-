# 로컬 경기 자료 시점 확인

`V4_replay/replay-haemonye.json`은 최신 자료가 아니라 **9월 27일 23:01 하면해전, 사이트 제출 3 / 로컬 v2의 38턴 43:0 승리**입니다. 상대·시각·버전은 9월 28일 저장된 인증 UI 관측과 game ID로 연결했습니다. 파일 SHA256도 9월 29일 감사 기록과 같습니다. 당시 누락됐다가 확보된 1차 경기 원본이며, 현재 v9 또는 독립 mission4의 성적으로 사용할 수 없습니다.

나머지 `V4_replay` 13개는 9월 28일 `round2/source-manifest.json`의 파일별 SHA256과 모두 일치합니다. 해당 UI 기록은 9월 28일 10:00 공개 회차, 사이트 제출 4 / `submission-v3.zip`(로컬 v3), 9승 4패로 연결합니다. **폴더 이름 V4는 로컬 v4 제출 증거가 아닙니다.** 서버 ZIP 바이트 동일성은 당시에도 확인되지 않았습니다.

기준 `records/official/latest-20261001/matches.json`의 10월 1일 00:30 v8 12경기와 game ID 중복은 0개입니다. 중복이 없다는 뜻이며, 새 회차라는 뜻은 아닙니다. 이번 파일 중 최신 공식경기라고 식별할 자료는 없습니다.

하면해전 마지막 관측은 Y F7/W141, K F4/W41이며 기존 UI 관측과 정확히 같습니다. 승리 기록의 공개 상태·경제 거점 변화만 별도 timeline에 저장했습니다. 최신 패배의 첫 원인·경제 붕괴·종반 결함으로 재해석하지 않았습니다. 명령 t의 합법 입력은 관측 t−1이며, 미공개 점수 null은 그대로 유지했습니다.

사용자 `experiments/analyze_loss_collapse.py`는 수정하지 않았습니다. `census()`는 병력 수가 아닌 그룹 수를 세고, 다섯째 배열 값은 HP가 아닌 인원수입니다. 상대 점수 null을 0으로 바꾸므로 점수 열세 판정은 사용할 수 없습니다. 5턴 병력 비율만으로 회복 불가능 시점을 확정할 수도 없습니다. 이 문제들은 9월 29일 감사에도 기록돼 있으며 현재 해시가 당시와 같습니다.

원본 수정, Git 명령, 브라우저 접근은 하지 않았습니다. 최신 경기 분석은 새 공식 목록·리플레이를 받은 뒤 해당 회차와 제출 버전에 연결해 진행해야 합니다. JSON에는 14개 원본 해시, 경기·평가·시리즈 ID, 출처와 버전 연결을 보존했습니다.

추가로 `Downloads` 및 `다운로드` 폴더의 `replay*.json`·`rolling-game*.json`만 읽었습니다. 해당 파일은 2개였습니다. `replay (1).json`은 이미 보존한 v8 붉은 산호초전과 SHA256까지 같고, `replay.json`은 기존 1차 신촌도 우리땅 패배입니다. 새 경기 ID는 없었습니다. 다운로드 시각을 경기 시각으로 간주하지 않았으며 그 밖의 개인 파일은 읽지 않았습니다.
