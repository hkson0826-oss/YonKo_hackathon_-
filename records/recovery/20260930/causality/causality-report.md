# guard4 검증과 첫 분기 감사

**guard4를 기각하고 기존 제출 v8(guard3)을 유지한다.** 개발 2맵·32경기에서 전체 +1승이었지만 Y는 1승 줄었고, 별도 선택 4맵·64경기에서는 Y·K가 각각 3승 줄었다. 선택 기준을 통과하지 못했으므로 최종 검증·패키징·제출로 진행하지 않는다.

| 배치 | 진영 | guard3 승/경기 | guard4 승/경기 |
|---|---|---:|---:|
| 개발 | Y | 6/8 | 5/8 |
| 개발 | K | 4/8 | 6/8 |
| 개발 | overall | 10/16 | 11/16 |
| 선택 | Y | 14/16 | 11/16 |
| 선택 | K | 12/16 | 9/16 |
| 선택 | overall | 26/32 | 20/32 |

두 배치 모두 실행 오류·몰수 0건이다. 명령 의미 검사도 96개 리플레이·14,709게임 턴에서 파싱 누락, 잘못된 목적지·순간이동, 생산 자원·이동 재고 초과가 없었다. 결과는 [개발 검사](development-actions.json)와 [선택 검사](selection-actions.json)에 있다. 실행이 유효하다는 사실은 승률 개선을 뜻하지 않는다.

## 개발 경기의 최초 차이

| 맵 / 진영 / 상대 | 결과 변화 | 최초 자기 명령·상태 차이 | 상대 최초 차이 |
|---|---|---|---|
| 16001 / Y / v3 | guard3 승 → guard4 패 | 13턴 ENG(3,7)에서 W2 대신 W3를 오른쪽으로 이동 | 14턴 |
| 16001 / K / v3 | guard3 패 → guard4 승 | 12턴 ENG(11,7)에서 W2 대신 W3를 왼쪽으로 이동 | 13턴 |
| 16000 / K / 균형형 | guard3 패 → guard4 승 | 4턴 (11,10)의 F 이동 방향이 왼쪽에서 위쪽으로 변경 | 25턴 |

모든 쌍은 해당 첫 분기 직전까지 상태가 같다. 첫 두 쌍에서 실제 guard4 명령을 공통 직전 상태에 넣고 원 guard3 함수만 적용하면 실제 guard3 명령과 정확히 같았다. guard4를 같은 명령에 다시 적용하면 바뀌지 않았다. 시간 제한 탐색 없이 방어 함수만으로 첫 행동 차이를 설명할 수 있다. 다만 원 실행의 내부 탐색 결과는 기록하지 않았으며, 이 검사는 첫 차이가 최종 승패 전체를 일으켰다는 인과 증명이 아니다.

Y 회귀의 ENG(3,7)는 현재 W3, 원 행동 후 예상 W5, 최근접 적 F 도착 5턴, 즉시 적 W 위험 0이었다. K 개선의 ENG(11,7)는 현재 W3, 예상 W3, 적 F 도착 6턴, 즉시 적 W 위험 0이었다. 따라서 생략 기준을 예상 W3 이상에서 W4 이상으로 올려도 관찰된 Y 회귀는 그대로이고 K 개선의 첫 변경을 제거하게 된다. 이 자료만으로 그 임계값 변경을 정당화하지 않는다.

균형형 상대의 첫 차이는 F 이동이다. guard3/guard4의 차이는 W 예약뿐이므로 이 첫 차이는 직접적인 방어 변경으로 설명되지 않는다. 기존 벽시계 제한 탐색의 실행량 차이와 일치하는 잡음이며, 그 경기의 개선을 guard4의 직접 성과로 귀속하지 않는다. 이후 상태와 상대 반응이 달라진 전체 경기는 따로 재현하지 않았다.

## 재현과 검증 범위

[프로브](development-probe.cpp)는 동결된 guard4 소스를 포함하고, [원 guard 함수](development-old-guard.inc)와 [진단 함수](development-inspect-guard.inc)를 함께 실행한다. [입력](development-fixtures.inc)은 실제 공통 상태와 양쪽 명령이고, [원 리플레이 식별·해시](development-fixtures.json), [출력](development-probe.log), [요약·파일 해시](validation-summary.json)를 보존했다.

저장소 루트에서 아래처럼 컴파일한다. `AUDIT_DIR`에는 이 파일들이 함께 보존된 경로를 넣는다.

```bash
g++ -std=c++20 -O2 -I submissions/recovery-20260930-guard4 AUDIT_DIR/development-probe.cpp -o /tmp/yk-development-causality-probe
/tmp/yk-development-causality-probe
```

기존 후보 제작 단계의 집중 검사 로그는 정확히 25개 PASS, 공식 엔진 기록 재현은 4개 경기의 앞 8턴씩 총 32전이(상태 전환)다. 이는 25경기나 32경기 승률 검증이 아니다. 이번 새 대전 수는 개발 32경기와 선택 64경기의 합계 96경기다. 이 감사에서는 선택 리플레이 전체의 전략적 패배 원인을 분석하지 않았다.
