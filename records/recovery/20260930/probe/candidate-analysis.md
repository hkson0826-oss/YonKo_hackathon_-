# guard4: 이미 충분한 W가 합류하는 경제 거점의 추가 예약 생략

실험 후보이며 아직 제출 권고는 아니다. 실제 전체 경기 승률 비교와 GCC12 제출 검증은 수행하지 않았다.

기준은 사이트 v8의 guard3 소스 SHA256 `61a4f25113d9bf2c387a59ddc770a3143de6311e3fd2e004827a66eb78edfbc9`다. 후보 SHA256은 `c7f1ed99244087eb2e9f5b4a6c8a49bfadd1687898c2ca99a3db4292e490713d`다. `protocol.hpp`, `generated.hpp`, `submission.json`은 기준과 동일하다.

기존 guard는 W를 최대 2명 재배치한다. 이미 정리된 원래 행동의 이동 후 W가 경제 거점에 3명 이상 있고 즉시 적 W 도달 위험이 0이면 그 거점에 추가 예약하지 않는다. 이후 다른 거점을 위해 두 번 예약해 각 1명이 빠져도 적어도 1명은 남는다. 이 보수적 하한 때문에 도착 W가 1~2명인 경우는 그대로 유지한다. `defense_limit` 상수를 예약 상한과 생략 조건이 함께 참조한다.

기록된 seed13003 두 회귀에서 원래 명령은 ENG에 K W6/Y W4를 도착시키는데 guard3가 W1을 추가로 붙잡았다. 공통 7턴 상태와 기록된 v4의 8턴 행동을 입력으로 guard3 함수를 직접 실행하여 실제 guard3 행동과 일치함을 재확인했다. 동일 입력에서 후보는 원래 행동을 완전히 보존했다. 탐색·벽시계는 이 검사에 포함하지 않았다.

검증 결과:

- `probe.cpp` 25개 검사 통과. 두 실제 최초 분기, 도착 W 0~5 경계, 같은 턴 생산과 자원 부족에 의한 정리, 다른 두 거점의 예약 후 W1 유지, F 호위, 적 W 위험, 150턴 종료, 적 F 순간이동 경보, 순간이동 도착 W의 같은 턴 재이동 금지를 확인했다.
- `official_check.py`는 수정하지 않은 공식 Python 엔진으로 4개 리플레이의 첫 8턴을 재실행했다. 32개 전이의 전체 상태가 기록과 정확히 일치했다. 후보가 보존하는 원래 8턴 명령은 K ENG W6/Y ENG W4, guard3는 W7/W5를 남긴다.
- 전체 후보 소스와 probe를 로컬 GCC16/C++20/O2로 컴파일했다. GCC12/서버 제한 내 실행 검증은 아직 하지 않았다.
- 전체 경기 반사실 재현, 새 맵 리그, 후보 승률 개선은 검증하지 않았다. 두 패배의 원인 전체가 추가 W1이었다고 주장하지 않는다.

재현:

```bash
python3 -B /tmp/yk-strategy-20260930/make_probe.py
g++ -std=c++20 -O2 /tmp/yk-strategy-20260930/probe.cpp -o /tmp/yk-strategy-20260930/probe
/tmp/yk-strategy-20260930/probe
python3 -B /tmp/yk-strategy-20260930/official_check.py
```

원래 저장소나 Git 상태는 변경하지 않았다. 실험 입력으로 두 선택 맵을 읽었으므로 다음 승격 판정은 새 맵에서 수행해야 한다.
