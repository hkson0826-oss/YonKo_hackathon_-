# 로컬 리그의 탐색 후보

확인일: 2026-09-27. [생성 코드](../../../experiments/local_league/search_families.py)는 제출 v2의 전이·관측·평가 함수를 보존하고 행동 선택만 바꾼 10개 후보를 만든다. 각 후보의 가설과 약점은 `variants()` 반환값에도 남긴다. 이 문서는 설계 기록이며 대전 성능 결과가 아니다.

| 후보 | 변화 | 비교할 약점 |
|---|---|---|
| `s_maximin_d4` | 상대 정책 4개 중 최악 평가 최대화 | 보수성 때문에 유리한 공격을 놓칠 수 있음 |
| `s_mean_d4` | 상대 정책 4개 평균 최대화 | 특정 공략에 취약할 수 있음 |
| `s_mean_min_d4` | 평균·최악 평가를 1:1로 합침 | 혼합 비율은 검증 전 가설 |
| `s_tail2_d4` | 낮은 평가 2개의 평균 최대화 | 4개 가상 상대가 실제 상대 분포는 아님 |
| `s_regret_d2` | 기존 regret 선택, 깊이 2 | 재점령·투자 효과를 놓칠 수 있음 |
| `s_regret_d6` | 기존 regret 선택, 깊이 6 | 모델 오차·시간 초과 증가 가능 |
| `s_switch_guard_d4` | 처음 2턴은 각 정책, 이후 정책0 | 영속 역할 예약·계획 유전자는 없음 |
| `s_assignment_only` | 기존 할당 정책만 실행 | 탐색으로 얻던 전술 대응을 잃을 수 있음 |
| `s_maximin_d1` | 다음 한 턴의 최악 평가 최대화 | 2턴 점령을 과소평가할 수 있음 |
| `s_local_hold_d3` | 할당 슬롯 대신 경합 건물 W 출발 취소 후보, 깊이3 maximin | 과잉 주둔 및 할당 후보 제거의 영향이 섞임 |

`s_local_hold_d3`는 적 F가 1칸 안에 있는 아군 건물을 찾고, 정책0이 만든 명령 중 그 건물을 떠나는 W 이동만 삭제한다. 생산·F 이동·우선순위는 보존한다. 원래 정책0·1·2와 이 후보를 비교하므로 모든 병력을 무조건 주둔시키는 봇은 아니다. 새 상대 후보를 만들지는 않는다.

탐색 후보는 기존 160ms 중단 조건과 미완료 시 정책0 복귀를 유지한다. 실제 300ms 제한 내 응답 여부는 리그의 턴 시간 기록으로 따로 판정해야 한다. `s_regret_d6`는 전이가 최대 96회로 v2의 64회보다 많다. 깊이 1/2/3 후보는 최대 16/32/48회다. 할당 단독에는 전이 탐색이 없다.

## 연구를 적용한 범위

[Portfolio Search and Optimization](https://arxiv.org/abs/2104.10429)의 S-PRHEA 본문은 역할을 자주 바꾸는 장기 계획의 실패와 역할 변경 시점 표현을 설명한다. 여기서는 전환 시점 하나를 고정한 작은 대조 실험으로 좁혔다. 집단·돌연변이·교차·이전 계획 재사용이 없으므로 RHEA 구현으로 부르지 않는다.

[Opponent Modelling in an RTS game](https://arxiv.org/abs/2006.08659)의 깊이 실험은 부정확한 상대 모델에서 깊이를 줄이는 것만으로 모든 문제가 해결되지 않았음을 보인다. 따라서 깊이 1·2·4·6을 비교하고 평균·최악·혼합 선택을 별도로 둔다. 이 게임에서 어떤 깊이가 좋은지는 실제 대전 전에는 알 수 없다.

[Asymmetric Action Abstractions](https://arxiv.org/abs/1711.08101)는 기존 [본문 검증 기록](../round2/README.md)의 근거를 재사용했다. 국소 전술 후보라는 아이디어만 적용했으며 전체 유닛의 스크립트 배정을 hill climbing하는 PGS는 구현하지 않았다.

Firecrawl 연구 index에서 검색·인접 논문 확장 후 위 두 핵심 논문의 관련 본문을 다시 확인했다. [조회·적용 기록](sources.json)에 검색 질문, 짧은 근거와 적용 한계를 남겼다. NTBEA와 2L은 인접 방법으로 보존하되 이번 생성기에 구현하지 않았다. 금융 포트폴리오 논문은 게임 행동 추상화와 다른 문제라 제외했다.

## 검사

```sh
python3 -m unittest discover -s tests -p test_league_search.py -v
```

검사는 후보 10개의 컴파일, 전이·관측 블록 보존, 서로 다른 행렬 선택 기준, regret의 지배 행동 선택, 동률 처리, W 이동 취소의 범위를 확인한다. 승률·시간·최종 채택은 리그 결과에서 판정한다.
