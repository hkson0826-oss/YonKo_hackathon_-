# 분석기 독립 검토

검토 대상: `/tmp/yk-benchmark-analysis-20261001/analyze_team_comparison.py`와 `direct-analysis.json`의 완료된 64경기(32맵). 분석기 코드는 수정하지 않았다.

현재 결과를 정정해야 할 승패·중복 집계·병력 수지 오류는 발견하지 못했다. 원자료를 별도로 읽어 다음을 확인했다.

- 64개 고유 job마다 Y/K 2개 관점만 존재하며, 각 관점의 승점 합은 1이다. 128관점을 128경기로 부풀리지 않았고 전체 games=64, bot별 games=64가 맞는다.
- `(bot, team, seed, opponent)` 키 중복이 없다. v8 60승(Y 31/K 29), 팀원 4승(Y 3/K 1)이 집계와 일치한다.
- 각 봇·맵에 양 진영 2경기가 있어 현재 `outcome_summary`의 경기 평균과 동등 맵 가중 bootstrap 중심이 같은 대상이다. Y−K 비교도 맵별 쌍 차이로 계산한다. 공통 상대 차이는 같은 상대·맵·진영끼리만 비교하며 direct 결과에서는 매칭 공통 상대가 없어 0쌍/null로 표시한다.
- 전 128관점의 F/W/S에서 생산−손실=종료 병력이 성립한다. 각 경기의 양측 W 손실 수도 같다. 공식 spawn 처리를 재사용해 자원 부족에 따른 실제 생산 인원을 복원하므로 SPAWN 요청 수를 곧 생산 수로 취급하지 않는다.
- 10/20/40턴은 64경기, 80턴은 61경기, 120턴은 46경기다. 종료 전 checkpoint가 없는 경기를 종료 상태로 채우지 않는다. 실제 terminal state는 별도 final이다.

## 보고서 해석에 영향을 주는 확인 사항

1. **장애물 우회 거리 층화는 이번 자료에서 비교할 수 없다.** `exploratory_strata` 348~352행은 중앙값보다 작은 구간과 이상 구간을 만든다. `base_to_plaza_obstacle_detour` 중앙값이 0이라 `<0` 구간은 0경기, `>=0` 구간은 64경기다. 값 종류가 2개 이상이라는 검사만으로 양쪽 구간이 채워지지는 않는다. 해당 지표로 양 구간 승률·유불리 차이를 서술하면 안 된다. 다른 5개 층화의 양쪽 구간은 비어 있지 않다.
2. **구간별 생산·손실은 턴당 비율이 아니다.** 266~272행은 해당 구간에 도달한 경기마다 구간 합계를 평균한다. 81~120 구간은 61경기, 121~종료 구간은 45경기이며 조기 종료 경기는 노출 턴 수가 짧다. ‘후반 생산 속도’, ‘턴당 손실’처럼 표현하면 잘못이다. ‘해당 구간에 도달한 경기의 평균 생산/손실 수’로 표현해야 한다.
3. **후반 checkpoint 평균은 생존 조건부 수치다.** 120턴 46경기와 final 64경기를 동일 표본의 시간 변화처럼 연결하면 안 된다. 현재 JSON method 설명은 이 한계를 이미 밝힌다.

## 재사용 시 경계조건

현재 실행에는 영향을 주지 않지만, 추후 같은 맵·상대·진영에 정책 시드를 달리한 반복을 합치면 `side_pairing` 283행과 `paired_common` 323행의 dict 키가 반복 관측을 덮어쓴다. main의 job ID 중복 차단만으로는 서로 다른 ID의 동일 matchup 반복을 차단하지 않는다. 반복실험을 이 분석기에 추가할 때에는 평균화/추가 키를 먼저 정해야 한다.

마찬가지로 맵별 경기 수가 달라지면 outcome의 point_rate는 경기 가중 평균인 반면 CI는 맵 평균들을 동등 가중하여 다른 추정량이 된다(현재 32맵×2경기는 균형이므로 해당 없음). 완료되지 않은 배치의 중간 CI를 최종 균형 실험의 CI처럼 쓰면 안 된다.

좁은 신뢰구간을 강도 보장으로 해석하거나 사후 지형층화를 인과효과로 해석해서는 안 된다. 현재 방법 설명의 bootstrap 퇴화·사후 층화 제한 표시는 적절하다.
