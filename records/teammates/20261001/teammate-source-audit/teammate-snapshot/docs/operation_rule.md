## 2. 제출과 리더보드

- 파일 제출은 9월 27일 15:00부터 10월 1일 23:00까지 가능하다. 20:00은 저녁 회차 반영 마감이며, 그 뒤에도 다음 회차를 위한 제출은 가능하다.
- 각 회차 마감 전에 업로드를 완료하고 대회에 사용할 코드를 직접 선택한다. 선택하지 않은 코드는 평가에 사용하지 않는다.
- 파일 확인 중인 코드도 경고를 확인한 뒤 선택할 수 있다. 마감 후 확인이 완료되어도 해당 회차에 사용하지만, 검사 실패 시 그 코드로는 참가할 수 없다. 이전 코드로 자동 변경되지 않는다.
- 서버 문제로 확인이 지연되거나 실패하면 참가자 오류로 처리하지 않는다. 운영팀이 복구 후 다시 진행한다.
- 마감 시각 이후의 업로드나 선택 변경은 해당 회차에 반영되지 않는다.
- 하루에 반영 회차가 두 번(오전·저녁) 있으므로, 개선 작업은 다음 마감 시각을 기준으로 계획한다.
- 제출 형식과 실행 제한(파일 구성, 사용 가능한 언어와 라이브러리, 시간·메모리·출력 한도)은 대회 서버의 안내 페이지를 따른다.
- 10월 1일 23:59까지 최종 평가에 사용할 코드 하나를 직접 선택해야 한다. 이전에 선택한 코드는 선택을 바꾸기 전까지 유지된다. 선택한 코드가 없거나 사용할 수 없으면 최종 경기에서 몰수패 처리한다.

## 3. 평가 방식

평가는 대회 기간 중의 리더보드와 마감 후의 최종 평가로 나뉜다. **리더보드 순위는 최종 순위가 아니다.**

### 가. 리더보드 (참고용)

- 하루 두 차례, 각 회차의 반영 마감 시점에 확정된 제출본끼리 대전해 순위를 갱신한다.
- 모든 팀이 서로 동일한 횟수로 맞붙지는 않으므로, 리더보드 순위는 현재 실력을 가늠하는 진단 지표이며 정확한 전체 순위가 아니다.
- 리더보드 결과는 최종 순위 산정에 직접 반영되지 않는다. 개선 방향을 잡는 용도로 활용한다.
- 결과는 예정 시각에 자동 공개한다. 계산이 끝나지 않은 부분 순위는 공개하지 않으며, 지연 시 운영팀이 별도로 안내한다.

### 나. 최종 평가

- 마감 후, 각 팀이 선택한 최종 에이전트로 최종 대전을 진행한다.
- 각 팀은 등록된 연세(Y)·고려(K) 진영을 유지하며, **반대 진영의 모든 팀과 1경기씩** 치른다. 경기 수는 최종 등록 팀 수에 따라 정해진다. 예: Y 51팀·K 53팀이면 총 2,703경기.
- 승점: 승리 1점, 무승부 0.5점, 패배 0점. 한 팀만 시간 초과·비정상 종료 등의 오류를 내면 그 팀의 몰수패. 두 팀이 동시에 오류를 내면 무승부로 각 0.5점.
- 진영별 팀 수가 달라 경기 수가 다르므로, 개인 순위는 총점이 아니라 **승점률(획득 승점 ÷ 전체 경기 수)** 로 비교한다.
- 동률이면 다음 순서로 비교한다.
  1. 승률
  2. (이긴 상대의 승점률 + 비긴 상대 승점률의 절반) ÷ 경기 수
- 위 기준까지 같으면 공동 순위다. 상위 7팀 경계에 걸친 동률은 별도 동률 결정전으로 정한다. 결정전은 마감 때 선택한 동일 코드와 등록 진영을 유지하고 새로운 맵에서 진행한다. 경기 수가 다르면 승점률로 비교하며, 운영팀이 대진과 세부 진행을 안내한다.
- 동률 결정전이나 서버 장애로 결과 확정이 늦어지면 최종 리더보드를 임의로 공개하지 않고 운영팀이 지연을 공지한다.
- **최종 상위 7팀 중 더 많은 팀이 포함된 진영이 학교 대항전에서 승리한다.** 개인 순위별 시상은 별도로 진행한다.
- 최종 리더보드는 10월 2일 08:00에 공개한다.

### 다. 모의 전투와 수료 전투 기준

- 게임팀이 제공한 하·중·상 봇을 선택해 모의 전투를 할 수 있다. 한 번 요청하면 등록된 진영에서 서로 다른 맵 10개로 대결한다.
- **중 봇과의 한 번의 모의 전투에서 10경기 중 6승 이상**을 거두면 수료 전투 기준을 통과한다. 무승부는 승리 횟수에 포함하지 않는다.
- 모의 전투 결과는 리더보드와 최종 순위에 반영되지 않는다.

### 라. 보고서 평가

에이전트 성적과 별도로, 개발 과정을 정리한 보고서를 제출한다. 제출 마감은 10월 1일 23:59이며, 100점 만점으로 평가한다.

| 평가 항목 | 배점 | 핵심 평가 요소 |
| --- | ---: | --- |
| 1. 핵심 전략 요약 | 15 | 핵심 전략의 명확성, 전략의 논리성 |
| 2. 유닛 운용 전략 | 20 | 병종별 역할 정의, 생산 우선순위·비율·투입 시점의 구체성, 규칙 이해 |
| 3. 구역별 운영 전략 | 20 | 구역별 점령·방어·공격 방침, 건물 기능 활용, 판단 조건의 명시 |
| 4. 개발 과정 | 30 | 문제 인식과 변경 근거, 정량적 검증, 제출 간 발전 흐름 |
| 5. 소감 | 5 | 경험과 배운 점의 구체성 |
| 6. 보고서 완성도 | 10 | 완결성, 용어 정확성, 가독성, 양식 준수 |
| **합계** | **100** | |

- 배점이 가장 큰 항목은 개발 과정(30점)이다. 결과의 좋고 나쁨보다, 무엇을 문제로 보았고 어떤 근거로 바꾸었으며 그 변화를 어떻게 확인했는지가 평가 대상이다.
- 대회 기간 중 시도와 측정 기록을 남겨 두면 작성에 도움이 된다.
- 보고서 양식과 제출 방법은 대회 페이지 공지를 따른다.

### 마. 최종 발표

- 최종 평가 결과에 따라 12팀이 최종 발표를 진행한다.
- 발표 일시와 장소, 발표 시간은 인스타그램 카드뉴스 공지 등을 통해 별도로 안내한다.

## 4. 코드와 LLM 사용 기준

- **팀 간 공유는 금지한다.** 다른 팀과 코드, 전략 문서, 제출물을 주고받을 수 없다.
- 외부 코드는 사용할 수 있다. 공개된 라이브러리나 예제 코드를 참고하거나 활용해도 된다.
- LLM(생성형 AI) 사용도 허용한다. 다만 사용한 경우 아래 내용을 보고서에 반드시 기재한다.
  - 사용한 LLM의 모델 정보
  - 입력한 프롬프트
  - 사용 목적과 범위 (어느 부분에 어떻게 활용했는지)
- 표절이 의심되는 코드에 한해 유사도 비교를 진행한다. 전수 검사는 하지 않는다.
- 기재 누락이나 표절이 확인된 경우 감점 또는 실격 대상이 될 수 있다.
- LLM 사용 자체는 감점 요소가 아니다. 보고서의 개발 과정 항목은 무엇을 왜 바꾸었고 그 변화를 어떻게 확인했는지를 본다. LLM을 활용한 과정도 그 흐름의 일부로 설명하면 된다.

## 5. 유의 사항

- 모든 시각은 한국 표준시(KST) 기준이며, 서버 시각을 기준으로 마감을 판정한다. 마감 직전 제출은 업로드 지연으로 마감을 넘길 수 있으므로 여유를 두고 제출한다.
- 대회 기간 중 게임 규칙과 밸런스 수치는 변경하지 않는다.
- 규칙 해석과 시스템 오류에 관한 문의는 채널톡으로 접수한다. 전략이나 코드 작성 방법에 관한 문의에는 답변하지 않는다.
- 규칙 해석이 갈릴 수 있는 답변은 전체 공지로 함께 게시한다.
- **실행 환경의 제한을 우회하려는 시도는 실격 사유다.**
