# 개발 기록 — Campus Conquest

이 문서는 보고서 작성을 위한 근거 기록이다. 완료된 작업, 설계 가설, 미검증 사항을 구분한다. 이전 대화와 저장된 파일을 바탕으로 2026-09-27 KST에 소급 작성했다. 개별 작업의 정확한 시작·종료 시각은 보존되어 있지 않아 기재하지 않았다. 실험을 새로 실행한 기록이 아니다.

## 운영 규칙과 기록 원칙

근거: [운영 규칙](operation_rule.md) 3절 라항 및 4절.

- 개발 과정 30점: 문제 인식 → 변경 근거 → 구현 → 정량적 검증 → 다음 개선으로 기록한다.
- 핵심 전략 15점, 유닛 운용 20점, 구역별 운영 20점에 사용할 설계 근거도 함께 보존한다.
- LLM 모델 정보·프롬프트·활용 범위는 [LLM 사용 기록](llm_usage_log.md)에 별도 기록한다.
- 로컬 예제 봇과 서버 하·중·상 봇은 동일하다고 확인되지 않았다. 로컬 결과로 서버 수료 기준 통과를 주장하지 않는다.
- 다른 참가 팀 간 코드·전략 문서·제출물 공유는 금지다. 사용자는 친구가 같은 팀원이라고 명확히 설명했다. 따라서 요청한 팀 내부 코드 공유와 로컬 비교 테스트에는 이 금지 조항이 적용되지 않는다. LLM이 친구를 다른 팀으로 오해해 주의 안내를 했으며 이후 정정했다. 실제 팀원 코드 수령이나 대전은 아직 수행하지 않았다.

## DEV-001 — 규칙 및 기본 예제 분석

날짜: 2026-09-27. 상태: 완료.

읽은 자료: [규칙](rule.md), [기초 안내](instructure.md), Python example_lv1/example_lv2와 search/main/protocol, C++ main/search/protocol 및 starter의 example_lv2, 엔진 pipeline의 생산·동시 이동 처리.

확인한 문제와 판단:

| 관찰 | 설계에 주는 의미 |
|---|---|
| 예제는 각 깃발병 집단이 독립적으로 가까운 목표를 고른다 | 같은 목표로 몰리는 중복 배정을 제어할 필요가 있다 |
| 깃발병 수가 늘어도 건물당 점령 단계는 한 턴에 하나다 | 점령 병력은 분산할 동기가 있다 |
| 전투병 수를 상쇄하고 남은 쪽이 비전투병을 제거한다 | 전투병에는 깃발병과 다른 집결 기준이 필요하다 |
| 생산 → 이동 → 전투 → 수입 → 점령 순서다 | 신규 생산 병력의 즉시 이동, 도착 예정 호위, 점령 예산을 함께 고려한다 |
| 지형과 모든 유닛은 공개되고 건물 점수만 일부 비공개다 | 첫 버전에서 정찰병은 생략하고 대칭 점수 추론을 사용한다 |
| 예제 Lv2는 전투병을 최대 3명까지만 보충한다 | 전투병 지속 생산을 포함한 초안과 비교할 수 있다 |

위 관찰은 코드·규칙 분석이며, 패배 리플레이에서 확인한 원인이라고 주장하지 않는다.

## DEV-002 — 외부 레퍼런스 선택

날짜: 2026-09-27. 상태: 조사 완료.

선택 자료: [delineate, CodinGame Fall Challenge 2022](https://github.com/delineate/cg-2022-fall-challenge-strategy#movement). 저자가 최종 1위임을 명시한 전략 설명이다. 저장소에는 실행 가능한 우승 봇 코드가 없으며 설명을 참고했다.

차용 개념은 목표 배정 후 해당 목표의 비용을 높여 다음 병력의 중복 배정을 줄이는 방법이다. Campus Conquest에서는 일반 영역 대신 건물을 목표로 사용한다. 자체 생산·전투·회피 휴리스틱과 가중치는 원문의 검증 결과를 물려받는 것이 아니다.

비채택 후보:

- [mzotkiew HaliteBot](https://github.com/mzotkiew/HaliteBot): 공개 소스의 생산력·병력 상한 255·인접 피해 모델을 그대로 적용할 수 없어 전체 이식 제외.
- [reCurse A Code of Ice & Fire 1위 전략](https://forum.codingame.com/t/a-code-of-ice-fire-feedbacks-and-strategies/105722/30): 연쇄 생산·점령 중심 접근이 본 게임의 한 턴 재이동 금지 구조와 달라 제외.

## DEV-003 — delineate_v1 구현

날짜: 2026-09-27. 상태: 로컬 구현 및 ZIP 생성 완료, 서버 제출 여부 미확인.

가설: 깃발병의 중복 목표를 줄이고 전투병을 지속 보충하면 기본 예제보다 유리할 것이다. 이번 버전은 여러 변경을 한꺼번에 적용한 최초 기준 버전이며, 개별 변경의 효과를 분리 검증하지 않았다.

구현 파일: [main.py](../bots/delineate_v1/main.py). 상세 설계: [STRATEGY.md](../bots/delineate_v1/STRATEGY.md).

| 변경 | 이유 | 실제 구현 범위 |
|---|---|---|
| BFS 거리 사전 계산 | 고정 지형의 반복 경로 계산 감소 | 첫 판단에서 통과 가능한 셀 간 거리 계산 |
| 순차 목표 배정 | 깃발병 중복 투입 완화 | 거리 - 건물 가치 + 중복 수 × 18 + 적 주둔 W 패널티 |
| 깃발병 생산 제한 | 불필요한 F 생산을 줄이고 W 투자 | 최대 6명, 부족 시 보충. 강제 인원 감축은 하지 않음 |
| 전투병 임무 배정 | 방어·공격에 병력 집중 | 근처 적 W 수 + 1을 수요로 추정, 초과 배정에 패널티 |
| 깃발병 위험 회피 | 이동 후 전투에서의 손실 완화 | 적 도달 가능 W와 아군 도착 예정 W 비교 |
| 건물 기능 평가 | 점수 외 경제·생산 효과 활용 | HALL/ENG/HOSPITAL 등 기능 보너스; 후반 감쇠 |
| 신규 병력 즉시 이동 | 규칙상 가능한 이동 시간 절약 | 생산 병력을 현재 이동 계획에 포함 |
| 병원 생산·PRIORITY | 목표 접근과 점령 자원 배정 | 본진/보유 병원 선택, 건물 가치순 점령 우선순위 |

핵심 초기값: 점수 계수 1.4, F 중복 패널티 18, F 위험 패널티 1000, W 주변 적 탐색 거리 3. 실험으로 최적화한 수치가 아니다.

구역별 운영은 별도 지역 모드가 아니라 거리·건물 가치·위협으로 결정한다. 본진 쪽에서는 경제 건물 확보와 근거리 방어, 중앙에서는 가치와 거리의 균형, 적 지역에서는 호위 가능한 목표 접근을 의도했다. 이 의도대로 항상 움직이는지 리플레이 정밀 분석은 아직 하지 않았다.

## EXP-001 — 기본 예제 상대 초기 확인

날짜: 2026-09-27. 상태: 완료.

- 후보: delineate_v1, 상대: 제공 Python example_lv1 및 example_lv2.
- 맵 seed 0, 1 × 후보 Y/K × 상대 2종 = 8경기.
- Windows, 테스트 실행 Python 3.12.10, 공식 엔진 기본 설정 사용.
- 공식 InProcessBot 대전 후, 각 경기 입력 전체를 독립 Python 봇 프로세스에 전달해 명령과 END 출력이 일치하는지 확인.

해석: 테스트한 두 맵과 기본 예제에 대해서는 초안의 정상 동작과 우위를 확인했다. 전체 대회 승률 100%, 강한 상대에 대한 우위, 목표 분산 단독 효과는 확인하지 않았다. 별도의 분산 미적용 대조군 실험도 아직 없다.

## ENV-001 — Windows 별도 프로세스 러너 오류

공식 CLI로 seed 0의 후보 Y / Lv2 K 대전을 시도했으나 `RunnerIOError: input transport failed: [WinError 10093]`로 종료됐다. 이 실패는 정상 대전 8경기에 포함하지 않는다. 상세 원인은 아직 수정·검증하지 않았다.

대안으로 공식 엔진 + InProcessBot을 사용했다. 독립 프로세스의 전체 입력/출력 일치는 추가 확인했지만, 턴마다 시간 제한을 강제하는 대전과 동등하지 않다. 따라서 서버 300ms 제한, 메모리 제한 통과는 미확인이다.

## 증거 보존 및 재현

초기 버전의 소스·ZIP·결과·리플레이·테스트 코드를 [EXP-001 스냅샷](../development-logs/2026-09-27-v1/)에 복사 보존했다. `manifest.json`에는 보존 시각과 각 파일의 SHA-256을 기록한다. 해시는 파일 식별용이며 실제 실험 시각을 증명하지 않는다. 현재 소스와 최초 ZIP 내용의 일치도 보존 시 확인한다.

저장소 루트에서 재실행:

```powershell
yk-development-tools/.venv/Scripts/python.exe bots/test_delineate_v1.py
```

이 명령은 작업용 test-results/delineate-v1 결과를 갱신한다. 초기 결과는 위 스냅샷에서 확인한다.
